## Root Cause
The bug is in the get_permissions function using the ROLE_PERMISSIONS mapping: ROLE_PERMISSIONS does not include a "moderator" key, so get_permissions(role) falls through to the default empty set. Concretely, get_permissions relies on ROLE_PERMISSIONS.get(role, set()), and because ROLE_PERMISSIONS is missing 'moderator', get_permissions('moderator') returns an empty set instead of the intended moderator permission set.

## Failure Mechanism
When code checks permissions for a moderator, e.g. has_permission('moderator', 'delete'), has_permission calls get_permissions('moderator'). Because ROLE_PERMISSIONS lacked the 'moderator' entry, get_permissions returned the default empty set and has_permission evaluated 'delete' in set() to False. The effect is that moderators are incorrectly denied actions they should be allowed to perform.

## Broken Invariant
The module-level contract that get_permissions('moderator') returns a permission set that includes moderator privileges (e.g. contains 'read' and 'delete') is violated. Specifically, get_permissions('moderator') must contain 'delete' for moderator accounts, but previously it returned an empty set.

## Fix Strategy
I added an explicit 'moderator' entry to ROLE_PERMISSIONS so get_permissions('moderator') returns the correct permission set. I also made permission sets immutable (frozenset), introduced DEFAULT_PERMISSIONS to make the fallback explicit, and exposed KNOWN_ROLES/is_valid_role to clarify which roles are recognized. These changes ensure has_permission('moderator', 'delete') now returns True because ROLE_PERMISSIONS['moderator'] contains 'delete', and the behavior for unknown roles is explicit and immutable.

```python
"""Access control: map roles to permission sets.

This module defines the canonical ROLE_PERMISSIONS mapping and helper
functions for querying role permissions. Permission sets are exposed as
immutable frozenset objects for clarity and to avoid accidental mutation.
"""

ROLE_PERMISSIONS = {
    "admin": frozenset({"read", "write", "delete", "manage_users"}),
    "moderator": frozenset({"read", "delete", "moderate_comments"}),
    "user": frozenset({"read", "write"}),
}

# Explicit empty default for unknown roles
DEFAULT_PERMISSIONS = frozenset()

# Known roles (derived from ROLE_PERMISSIONS for clarity elsewhere)
KNOWN_ROLES = frozenset(ROLE_PERMISSIONS.keys())


def is_valid_role(role):
    """Return True if the role is recognized by the system."""
    return role in KNOWN_ROLES


def get_permissions(role):
    """Return the immutable set of permissions for the given role.

    Unknown roles return an empty frozenset (DEFAULT_PERMISSIONS).
    """
    return ROLE_PERMISSIONS.get(role, DEFAULT_PERMISSIONS)


def has_permission(role, action):
    """Check whether a role has a specific permission.

    This returns True only if the action appears in the role's
    permission set. Unknown roles are treated as having no permissions.
    """
    return action in get_permissions(role)

```
