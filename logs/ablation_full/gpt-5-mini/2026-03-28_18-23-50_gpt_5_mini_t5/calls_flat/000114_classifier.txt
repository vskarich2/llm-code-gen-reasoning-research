## Root Cause
In code_snippets_v2/temporal_drift_b/pipeline.py the variable raw_stats is assigned by calling compute_raw_stats(cleaned). The compute_raw_stats function is intended to operate on the original (untransformed) data, but the pipeline passes the normalized list 'cleaned' instead of the original 'data', causing raw_stats to reflect transformed values.

## Failure Mechanism
For a concrete input, e.g. data = [10, 20, 30], normalize(data) produces cleaned = [0.0, 0.5, 1.0]. Because pipeline calls compute_raw_stats(cleaned), raw_stats becomes {'raw_max': 1.0, 'raw_min': 0.0, 'raw_sum': 1.5} instead of the expected {'raw_max': 30, 'raw_min': 10, 'raw_sum': 60}. Thus any consumer relying on raw_stats to reflect original magnitudes will get incorrect, normalized values.

## Broken Invariant
For any non-empty input list 'data', pipeline(data)['raw_max'] must equal max(data), pipeline(data)['raw_min'] must equal min(data), and pipeline(data)['raw_sum'] must equal sum(data). The current implementation violates this invariant by computing these values from the normalized list.

## Fix Strategy
Call compute_raw_stats with the original 'data' rather than the normalized 'cleaned'. The change is limited to replacing compute_raw_stats(cleaned) with compute_raw_stats(data) in pipeline.py so that compute_raw_stats operates on untransformed input as its contract requires. No changes are necessary in transforms.py.
