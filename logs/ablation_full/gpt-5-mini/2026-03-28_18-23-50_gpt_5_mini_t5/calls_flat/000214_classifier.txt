# Developer's Reasoning

## Root Cause
writer_b.write_cached (file writer_b.py) writes product values by calling write(key, _cache[key]) without passing a version. In store.write (file store.py) the version map _versions is only updated when a non-None version is passed. Because write_cached never supplies a version, a subsequent call to write_cached can overwrite _data[key] with a cached (stale) value while leaving _versions[key] unchanged (or set by a prior writer).

## Failure Mechanism
In api.update_product (file api.py) the code calls write_fresh(product_id, compute_fn) and then write_cached(product_id, compute_fn). Example sequence: 1) First update: write_fresh computes V1 and calls write(key, V1, version=1) -> _data[key]=V1, _versions[key]=1; writer_b caches V1. 2) Second update: compute_fn now returns V2; write_fresh computes V2 and calls write(key, V2, version=2) -> _data[key]=V2, _versions[key]=2. Immediately after, write_cached finds the old cached value V1 and calls write(key, V1) (no version) -> _data[key]=V1 but _versions[key] remains 2. The stored value becomes stale (V1) while the version claims the latest update (2). serve_request then returns a mismatched/stale product value despite a higher version, because write_cached silently overwrote the fresh value without updating version.

## Broken Invariant
After update_product(product_id, compute_fn) finishes, read(product_id) must equal the latest value returned by the compute_fn invocation used during that update (i.e., the most-recent compute_fn result that produced the stored value). Concretely: calling update_product must leave _data[product_id] equal to the last compute_fn() result computed during that call. Currently this invariant can be violated because writer_b.write_cached can overwrite the fresh result with an older cached value.

## Fix Strategy
I removed the redundant, dangerous writer from the update path by making api.update_product call only writer_a.write_fresh. This prevents the sequence where write_fresh writes a new value+version, then write_cached overwrites the data without a version. To avoid accidental reuse of the removed writer, writer_b.write_cached has been replaced with a stub that raises an explicit error and reset() becomes a safe no-op. This ensures versioned writes (via write_fresh) are the single source of truth and prevents stale overwrites because write_cached is no longer invoked by the API.
