The missing assignments (user['verified'] = False and user['cached_greeting'] = None) after setting the new email are the direct cause of the stale greeting and retained verified status.

## Failure Mechanism
Concrete scenario: create_user('Alice', 'a@example.com') produces a user with cached_greeting 'Hello, Alice!' and verified False. After calling verify_user(user) the user becomes verified True. Calling update_profile(user, {'email': 'alice@EXAMPLE.com'}) runs the branch that validates and sets user['email'] but, due to the bug, leaves user['verified'] as True and user['cached_greeting'] unchanged. The result is a user whose email changed but still shows the old/cached greeting and remains marked verified, violating expected behavior.

## Broken Invariant

Currently, when the new email is assigned, user['verified'] remains True and user['cached_greeting'] remains the previous greeting.

## Fix Strategy
update_profile now explicitly handles 'email' updates before 'name' updates. When a valid new email is provided and differs from the stored email, the code sets user['email'] = value, sets user['verified'] = False, and clears the cached greeting by setting user['cached_greeting'] = None. After that, if a name change is provided it updates user['name'] and rebuilds cached_greeting. This guarantees the invariant (email change clears greeting and un-verifies) while allowing a simultaneous name change to rebuild the greeting to reflect the new name.

```python
"""User profile with email verification and cached greeting."""

from validation import validate_email, validate_name
from notifications import build_greeting, should_reverify


def create_user(name, email):
    """Create a user with verified status and cached greeting."""
    return {
        "name": name,
        "email": email,
        "verified": False,
        "cached_greeting": build_greeting({"name": name}),
    }


def verify_user(user):
    """Mark user as verified."""
    user["verified"] = True
    return user


def update_profile(user, changes):
    """Update profile fields.

    Invariant: changing email must set verified=False and clear cached_greeting.
    Invariant: changing name must update cached_greeting.
    """
    # Apply email change first so a simultaneous name change can rebuild the greeting.
    if "email" in changes:
        value = changes["email"]
        if validate_email(value):
            old_email = user.get("email")
            # Only apply change if value is actually different from current stored email
            if value != old_email:
                user["email"] = value
                # Ensure email changes invalidate verification and clear cached greeting
                user["verified"] = False
                user["cached_greeting"] = None
    # Then apply name change (will rebuild cached_greeting if name changed)
    if "name" in changes:
        value = changes["name"]
        if validate_name(value):
            user["name"] = value
            user["cached_greeting"] = build_greeting(user)
    return user

```
