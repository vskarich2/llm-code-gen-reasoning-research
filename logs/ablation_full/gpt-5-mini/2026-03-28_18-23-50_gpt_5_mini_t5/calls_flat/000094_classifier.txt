# Developer's Reasoning

## Root Cause
In pipeline.ingest (code_snippets_v2/retry_dup_c/pipeline.py) the for-loop over max_pipeline_retries calls send_with_retry(...) but lacks a break after a successful call. Because send_with_retry itself performs the send (which calls sender.send that appends messages via store.append and records notifications via store.notify), the pipeline loop will invoke send_with_retry again and cause additional calls to sender.send for the same message.

## Failure Mechanism
Example: call ingest(msg, max_pipeline_retries=2, fail_first=True). On the first pipeline attempt, send_with_retry will internally retry via sender.send: sender.send fails on its first try (raising ConnectionError) and succeeds on its second try, which appends msg once. Back in pipeline.ingest, there is no break, so the pipeline loop proceeds to its second attempt and calls send_with_retry again — sender.send will append msg again. The result is msg appearing multiple times in store._messages and multiple notifications, typically doubling the expected single append (so messages appear 2x, and depending on nested retry counts could be 3-4 times).

## Broken Invariant
Calling ingest(msg, ...) must result in exactly one append of msg to store._messages and exactly one notification for that msg; formally, after reset() and a single ingest(msg) call, store.message_count() == 1 and len([n for n in get_notifications() if n['msg'] == msg]) == 1.

## Fix Strategy
Stop the pipeline-level retry loop once send_with_retry succeeds. I added an explicit break after the successful send_with_retry(...) call in pipeline.ingest so the pipeline does not make an additional successful call to sender.send. I also replaced the previous attempt to directly reset other module-level variables in pipeline.reset with calls to the appropriate reset functions (store.reset and sender.reset_sender) so reset properly reinitializes shared state rather than creating local globals that don't affect the other modules. Together these changes prevent duplicate invocations of sender.send for the same ingest and ensure a clean reset.
