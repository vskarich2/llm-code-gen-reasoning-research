# Developer's Reasoning

## Root Cause
In enqueue(task, queue=[]), the parameter queue has a mutable default value (an empty list) that is allocated once at function definition time. The function's queue.append(task) mutates that single shared list, so subsequent calls that omit the queue parameter reuse and further mutate the same list.

## Failure Mechanism
If a caller does enqueue(make_task('a')) the default list is mutated to ['a'] and returned. A later caller doing enqueue(make_task('b')) (without passing an explicit queue) appends to the same default list and returns ['a', 'b']. The intended behavior (one task per call when no explicit queue is supplied) is violated because the shared default list preserves prior tasks across independent calls.

## Broken Invariant
The function enqueue must satisfy: for any task t, calling enqueue(t) with no explicit queue argument returns a new list equal to [t] and does not include tasks from previous calls. Formally: enqueue(t1) == [t1] and enqueue(t2) == [t2] when called in separate, independent calls with no queue argument.

## Fix Strategy
Changed the enqueue signature to use queue=None and allocate a fresh list inside the function when queue is None. This removes the shared mutable default and guarantees a new list for callers who omit the queue argument. The fix is implemented by replacing the default queue=[] with queue=None and initializing queue = [] when needed, preserving the existing append-and-return logic.
