## Root Cause
In auth.py, the module-level dictionary _ROLE_DISPATCH omits the "guest" key, so the guest_access function (imported at the top) is never associated with the 'guest' role. The missing mapping causes lookups for the 'guest' role to fall back to _default_access instead of calling guest_access.

## Failure Mechanism
When get_access('guest') is called, auth._ROLE_DISPATCH.get('guest', _default_access) returns the default handler because 'guest' is not present in _ROLE_DISPATCH. The returned handler is _default_access, which returns {'read': False, 'write': False, 'delete': False}. As a result, can_read('guest') evaluates to False even though roles.guest_access() would return {'read': True, 'write': False, 'delete': False}. Example: calling can_read('guest') returns False due to the missing dispatch entry.

## Broken Invariant

Concretely, get_access('guest') must equal guest_access() and get_access('guest')['read'] must be True.

## Fix Strategy

This ensures get_access('guest') calls guest_access() and returns the intended read-only permissions. The change is limited to adding the mapping and does not alter other logic.

from roles import admin_access, user_access, moderator_access, guest_access


# Dispatch table mapping roles to access handlers
_ROLE_DISPATCH = {
    "admin": admin_access,
    "user": user_access,
    "moderator": moderator_access,
    "guest": guest_access,
}


def _default_access():
    """Default: no access for unknown roles."""
    return {"read": False, "write": False, "delete": False}


def get_access(role):
    """Return the access dict for a given role."""
    handler = _ROLE_DISPATCH.get(role, _default_access)
    return handler()


def can_read(role):
    """Check if role has read access."""
    return get_access(role).get("read", False)
