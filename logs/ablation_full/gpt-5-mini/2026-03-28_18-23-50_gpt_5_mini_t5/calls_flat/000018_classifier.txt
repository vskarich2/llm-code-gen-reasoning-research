# Developer's Reasoning

## Root Cause
In code_snippets_v2/partial_update_b/profile.py, the function update_profile fails to recompute the derived field user['full_name'] when the 'first_name' key is processed. Specifically, the branch for key == 'first_name' sets user['first_name'] = value but does not update user['full_name'], while the 'last_name' branch sets full_name only when last_name is changed. This asymmetry causes full_name to be stale whenever first_name is changed after last_name has been updated or when first_name is the only changed field.

## Failure Mechanism
For example, given a user {'first_name': 'Bob', 'last_name': 'Jones', 'full_name': 'Bob Jones'} and changes = {'last_name': 'Smith', 'first_name': 'Alice'}: if the update loop processes last_name first it sets user['last_name'] = 'Smith' and user['full_name'] = user['first_name'] + ' ' + 'Smith' -> 'Bob Smith'. Then when the loop later processes first_name it sets user['first_name'] = 'Alice' but (due to the missing recompute) leaves user['full_name'] as 'Bob Smith'. The observable failure is that user['full_name'] no longer equals user['first_name'] + ' ' + user['last_name'] (it remains 'Bob Smith' instead of 'Alice Smith').

## Broken Invariant
After update_profile(user, changes) returns, user['full_name'] must equal user['first_name'] + ' ' + user['last_name']. The current implementation can return a user where user['full_name'] != user['first_name'] + ' ' + user['last_name'].

## Fix Strategy
Always recompute the derived full_name from the canonical fields after applying allowed changes. I removed the ad-hoc full_name assignment from the 'last_name' branch and added a final step that sets user['full_name'] = user['first_name'] + ' ' + user['last_name'] after the loop. This guarantees the invariant regardless of the iteration order of changes or which name fields were modified.

def update_profile(user, changes):
    """Update profile fields. full_name must stay in sync.

    Invariant: full_name == first_name + ' ' + last_name
    """
    for key, value in changes.items():
        value = sanitize_string(value)

    # Recompute derived field from canonical pieces to maintain invariant
    user["full_name"] = user["first_name"] + " " + user["last_name"]
