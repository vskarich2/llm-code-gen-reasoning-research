# Developer's Reasoning

## Root Cause
enqueue + queue default argument (queue=[]) + queue.append() — the function uses a mutable default list defined at function definition time and mutates it with append, causing state to persist across calls.

## Failure Mechanism
Call enqueue(task) with no explicit queue → Python binds the same default list object to parameter 'queue' for every call → enqueue calls queue.append(task) which mutates that shared list → subsequent calls observe previously appended tasks (state propagation) → observable failure: a call that is intended to return a list containing only the new task instead returns a list with tasks from previous calls.

## Broken Invariant
Invariant: 'each call with a single task (no explicit queue) must return a list containing only that task.' This is testable: enqueue('a') should return ['a'], and a subsequent enqueue('b') (also with no explicit queue) must return ['b']. With the bug, enqueue('a') -> ['a'], enqueue('b') -> ['a','b'], violating the invariant.

## Fix Strategy
Change enqueue's signature to use an immutable default (None) and create a new list inside the function when queue is None. Specifically: def enqueue(task, queue=None): if queue is None: queue = [] ; queue.append(task) ; return queue. This breaks the causal chain because no shared mutable object is created at function definition time; each call without an explicit queue gets a fresh list, so appends cannot leak between calls. Also add a runtime check to ensure that if a caller passes an explicit queue it is a list (to fail fast on incorrect types).
