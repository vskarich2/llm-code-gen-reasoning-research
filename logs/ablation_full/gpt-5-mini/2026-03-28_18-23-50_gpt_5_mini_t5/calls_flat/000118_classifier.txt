# Developer's Reasoning

## Root Cause
In code_snippets_v2/temporal_drift_c/pipeline.py, the pipeline() function calls compute_raw_stats(normalized) instead of compute_raw_stats(data). The variable 'normalized' (result of normalize(data)) is passed to compute_raw_stats even though compute_raw_stats is specified (in its docstring and in the pipeline comment) to receive the original untransformed data. This causes raw metric computations to operate on transformed values rather than the originals.

## Failure Mechanism
Given an input like data = [10, 20, 30], normalize(data) produces normalized = [0.0, 0.5, 1.0]. The buggy line raw_stats = compute_raw_stats(normalized) causes compute_raw_stats to return {'raw_max': 1.0, 'raw_min': 0.0, 'raw_sum': 1.5, 'raw_count': 3}. compute_derived then returns {'raw_mean': 0.5}. The observed effect is raw_sum and raw_mean reflect the normalized values instead of the original sum (60) and original mean (20). Thus reports show incorrect raw metrics whenever data is transformed before compute_raw_stats is called.

## Broken Invariant
The pipeline() contract in pipeline.py states and relies on: raw_stats MUST reflect the original data before any transforms. Concretely, for any non-empty input list 'data', pipeline()['raw_stats']['raw_sum'] must equal sum(data) and pipeline()['raw_stats']['raw_count'] must equal len(data). The current implementation violates this invariant by computing raw_sum on 'normalized' instead of 'data'.

## Fix Strategy
Replace the incorrect call compute_raw_stats(normalized) with compute_raw_stats(data) so compute_raw_stats operates on the original, untransformed input. This directly restores the intended data flow: raw stats are computed from the original data (which compute_raw_stats expects and is implemented for), derived metrics (like raw_mean) are then correct, and later stages (normalize -> clip -> summarize_for_display) remain unchanged and continue to produce cleaned/display outputs. The only change is the single corrected argument to compute_raw_stats, preserving empty-data handling and all other behavior.
