# Developer's Reasoning

## Root Cause
In make_withdraw_steps the inner function step_act trusts the previously stored result['approved'] value (set by step_check) and calls do_withdraw without re-checking the account balance. The causal variable is result['approved'] inside step_act: it can remain True even after intervening operations have reduced the balance, so step_act performs a withdrawal based on stale approval rather than current state.

## Failure Mechanism
Sequence: create_account('alice', 100). make_withdraw_steps returns (check_a, act_a) and (check_b, act_b). run_steps executes check_a -> result_a['approved']=True (100 >= 80). Then check_b -> result_b['approved']=True (still 100 >= 80). Now act_a sees result_a['approved'] True and does do_withdraw('alice', 80), leaving balance 20. act_b also sees its stored result_b['approved'] True and does do_withdraw('alice', 80) again, decrementing balance to -60. The bug manifests because act functions act on stale approvals without observing current balance.

## Broken Invariant
After any sequence of operations, get_balance(name) >= 0 (specifically, a withdrawal of amount must only succeed if the account's balance at the time of the ACT is >= amount). This code can violate that invariant: get_balance('alice') can become negative after the interleaved sequence.

## Fix Strategy
Modify step_act to re-check the account balance at ACT time (call check_balance(name, amount)) before performing do_withdraw. This prevents using a previously stored approval that may be stale because of intervening operations. The change makes the withdrawal conditional on the current state rather than only on the earlier check, ensuring the ACT enforces the invariant even under interleaving.

def do_withdraw(name, amount):

def run_steps(steps):
    results = []
    for fn, args in steps:
        results.append(fn(*args))

    """Split withdrawal into separate check and act steps.

    BUG: under interleaving, both checks pass before either debits.

        result["approved"] = check_balance(name, amount)

        if result["approved"] and check_balance(name, amount):

            result["approved"] = True
        else:
            # If the balance is no longer sufficient, mark as not approved and do nothing.
            result["approved"] = False
