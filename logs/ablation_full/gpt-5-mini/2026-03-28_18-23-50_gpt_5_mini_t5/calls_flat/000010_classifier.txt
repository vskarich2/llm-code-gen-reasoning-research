# Developer's Reasoning

## Root Cause
In config.create_config the line `config = DEFAULTS` returns a reference to the global DEFAULTS dict instead of a copy. That shared reference is stored by ConfigMiddleware.__init__ in self._base (because it calls create_config()), and ConfigMiddleware.apply_config then does `cfg.update(request_overrides)` on that reference (cfg = self._base), mutating the cached base and the global DEFAULTS.

## Failure Mechanism
Example sequence: 1) A ConfigMiddleware is constructed, storing self._base as the dict returned from create_config (currently the same object as DEFAULTS). 2) handle_debug_request calls apply_config with {'debug': True}; apply_config sets cfg = self._base and then cfg.update({'debug': True}), which mutates the cached base and the global DEFAULTS. 3) A later call to handle_request() without overrides observes debug == True even though no current request asked for debug, because the cached base/DEFAULTS were mutated by the earlier request.

## Broken Invariant
Calling handle_request() with no overrides must always return a config equal to the factory defaults (timeout=30, retries=3, debug=False), independent of previous requests. Currently a prior request's overrides can change subsequent responses, violating this invariant.

## Fix Strategy
create_config now returns a shallow copy of DEFAULTS (dict(DEFAULTS)) so callers receive an independent dict. apply_config now works on a copy of the cached base (cfg = dict(self._base)) and applies request_overrides to that copy, so per-request updates do not mutate the middleware's cached base or the global DEFAULTS. This preserves the intended 'load once' caching of the base but prevents request-scoped mutations from leaking into later requests.
