# Developer's Reasoning

## Root Cause
The bug is in process(): it checks the module-level flag _initialized and, when False, appends an error to _log and returns False, effectively dropping the item. The causal relationship is that process() uses the _initialized flag to decide whether to handle an item, and when called before init() it records error and does not retain the item in any buffer, so subsequent init() has no way to see or process that item.

## Failure Mechanism
In broken_order(), run_steps calls process('a') before init(). Because _initialized is False, process('a') executes the branch that does _log.append(f"error:not_init:{item}") and returns False; _buffer is never used and 'a' is never kept. Later init() sets _initialized True and appends 'init' to _log, but since 'a' was not stored, no 'processed:a' entry is ever produced. The effect is that items passed to process() before init() are lost from the system and only an error entry remains.

## Broken Invariant
For any item x passed to process() at any time before shutdown(), the final log returned by shutdown() must contain an entry 'processed:x'. Currently items passed before init() are not processed and violate this invariant.

## Fix Strategy
Modify process() to buffer items if _initialized is False instead of logging an error or dropping them, and modify init() to flush that buffer after setting _initialized. This ensures items arriving before init() are retained in _buffer and then handled (logged as processed) immediately when init() runs. Concretely, the error branch in process() is replaced with _buffer.append(item) and a successful return, and init() is extended to copy and clear _buffer and emit 'processed:{item}' entries for each buffered item after appending 'init'.
