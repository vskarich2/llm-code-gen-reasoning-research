# Developer's Reasoning

## Root Cause
In limiter.should_allow the final boolean expression uses operator precedence incorrectly. The function computes local booleans expired, under_limit, and exempt and then returns the expression 'not expired and under_limit or exempt'. Because Python evaluates 'and' before 'or', that expression is parsed as '((not expired) and under_limit) or exempt', which makes the value of 'exempt' able to make the whole expression True even when 'expired' is True. The causal relationship is: the returned value depends on the top-level 'or exempt' term independently of 'expired', so an exempt client can be allowed despite an expired timestamp.

## Failure Mechanism
Concrete scenario: a client in EXEMPT_CLIENTS (so is_exempt returns True) has a stored timestamp outside the current window (is_expired returns True). For example, timestamp such that (now - timestamp) > window_seconds. With the current return expression 'not expired and under_limit or exempt', Python evaluates that as '((not expired) and under_limit) or exempt' -> (False and under_limit) or True -> False or True -> True. As a result should_allow returns True and middleware.process_request treats the request as allowed, so an expired token is accepted for an exempt client. The code path that causes this is the single-line return in limiter.py, which places 'exempt' outside the 'not expired' conjunction.

## Broken Invariant
For any input to should_allow, if is_expired(timestamp, now, window_seconds) returns True then should_allow(...) must return False. (I.e., expired tokens must be rejected regardless of exempt status.) The current implementation violates this: there exist inputs with expired == True and exempt == True for which should_allow returns True.

## Fix Strategy
Change the boolean expression to explicitly require the token be not expired before considering exemption. I replaced the single-line return 'not expired and under_limit or exempt' with a parenthesized expression '(not expired) and (under_limit or exempt)'. This enforces that expired must be False for the whole result to be True, while still allowing exempt clients to bypass the under_limit check when not expired. The parentheses remove reliance on Python operator precedence and match the intended contract described in the function docstring.

def should_allow(client_id, count, limit, timestamp, now,
                 window_seconds, exempt_list):
    """Decide whether to allow a request.

    Allow if:
      - token is not expired AND (under limit OR exempt)

    Exempt clients bypass the rate limit even if over it,
    but expired tokens are always rejected.
    """
