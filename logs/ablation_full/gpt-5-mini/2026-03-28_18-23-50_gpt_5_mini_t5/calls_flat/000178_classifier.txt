## Root Cause
In code_snippets_v2/silent_default_c/flags.py the environment mapping _ENV_KEY_MAP maps the 'dark_mode' flag to the wrong env var name ('FEATURE_DARKMODE' instead of 'FEATURE_DARK_MODE'), and is_enabled() uses get_env_bool(env_key) and then only returns True when that result is truthy rather than treating a present env var (True or False) as authoritative. Together these cause environment overrides for dark_mode to be ignored.

## Failure Mechanism
Example: _ENV contains 'FEATURE_DARK_MODE': 'false'. Because _ENV_KEY_MAP maps 'dark_mode' -> 'FEATURE_DARKMODE', flags.is_enabled('dark_mode') finds no env_key and skips the env layer. It then calls get_config_bool('dark_mode'), which returns True (from _FILE_CONFIG), so is_enabled returns True despite the environment explicitly setting the feature to 'false'. In the current code, even if the mapping were correct, is_enabled used get_env_bool(env_key) and only returned when that value was truthy; thus an env value of 'false' would be ignored and the call would fall through to config/hardcoded values.

## Broken Invariant
If an environment variable for a flag is present (e.g. _ENV contains 'FEATURE_<FLAG>'), then is_enabled('<flag>') MUST return that environment variable's boolean value (and get_flag_source('<flag>') MUST report 'env'). This invariant is violated for 'dark_mode' because the env key name is wrong and for any env 'false' because presence was not honored for False.

## Fix Strategy
Fixes: (1) Correct the env var mapping for the dark_mode flag to 'FEATURE_DARK_MODE' in _ENV_KEY_MAP. (2) Make is_enabled() treat the environment layer as authoritative when the env var is present by checking presence with get_env(env_key) is not None and returning get_env_bool(env_key) (so both True and False override lower layers). (3) Make the config layer check presence with get_config(flag_name) is not None before returning get_config_bool(flag_name). These changes ensure the env layer always overrides config/hardcoded when present and that config overrides hardcoded only when a config entry exists.

```python
"""Feature flag system with env -> config -> hardcoded fallback chain.

Lookup order:
  1. Environment variable (via env.get_env_bool)
  2. Config file (via config.get_config_bool)
  3. Hardcoded defaults
"""

from env import get_env, get_env_bool
from config import get_config, get_config_bool


HARDCODED_DEFAULTS = {
    "dark_mode": False,
    "beta": False,
    "analytics": False,
}

# Maps flag names to their env var keys
_ENV_KEY_MAP = {
    "dark_mode": "FEATURE_DARK_MODE",
    "beta": "FEATURE_BETA",
    "analytics": "FEATURE_ANALYTICS",
}


def is_enabled(flag_name):
    """Check if a feature flag is enabled.

    Checks env first, then config, then hardcoded defaults.
    """
    env_key = _ENV_KEY_MAP.get(flag_name)
    if env_key:
        # If the env var is present, its boolean value should be authoritative
        if get_env(env_key) is not None:
            return get_env_bool(env_key)

    # Only use config if a config entry exists
    if get_config(flag_name) is not None:
        return get_config_bool(flag_name)

    return HARDCODED_DEFAULTS.get(flag_name, False)


def get_flag_source(flag_name):
    """Return which layer provides the flag value (for debugging)."""
    env_key = _ENV_KEY_MAP.get(flag_name)
    if env_key:
        if get_env(env_key) is not None:
            return "env"

    if get_config(flag_name) is not None:
        return "config"

    return "hardcoded"

```
