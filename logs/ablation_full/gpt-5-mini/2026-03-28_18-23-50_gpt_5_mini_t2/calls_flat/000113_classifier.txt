## Root Cause
In code_snippets_v2/temporal_drift_b/pipeline.py, the pipeline() function calls compute_raw_stats(cleaned) using the variable cleaned (the result of normalize(data)) instead of calling compute_raw_stats(data). This passes the normalized values into compute_raw_stats instead of the original untransformed data, causing raw_stats to be computed from the wrong variable.

## Failure Mechanism
When pipeline() is given a numeric list like data = [10, 20, 30], the code does cleaned = normalize(data) -> [0.0, 0.5, 1.0], then calls compute_raw_stats(cleaned). compute_raw_stats computes raw_max = max(cleaned) which becomes 1.0 rather than max(data) == 30. As a result, the returned dictionary contains raw_stats that reflect the normalized range (0.0..1.0) instead of the original values, e.g. {'raw_max': 1.0, 'raw_min': 0.0, 'raw_sum': 1.5} instead of {'raw_max': 30, 'raw_min': 10, 'raw_sum': 60}. The incorrect argument flow (passing cleaned instead of data) is the causal chain producing the wrong numbers.

## Broken Invariant
The function compute_raw_stats must be called on the original input data before any transforms, so for any non-empty input list data the pipeline must satisfy: pipeline(data)['raw_stats']['raw_max'] == max(data), pipeline(data)['raw_stats']['raw_min'] == min(data), and pipeline(data)['raw_stats']['raw_sum'] == sum(data). Currently this invariant is violated because compute_raw_stats receives the normalized list.

## Fix Strategy
Call compute_raw_stats with the original data variable instead of the normalized 'cleaned' variable. Changing the line compute_raw_stats(cleaned) to compute_raw_stats(data) ensures compute_raw_stats operates on the untransformed input, restoring the invariant that raw_stats reflect the original values. No other functions need modification because normalize and summarize_for_display already operate on cleaned as intended.
