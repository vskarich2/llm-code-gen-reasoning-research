# Developer's Reasoning

## Root Cause
The bug is in process_batch: it updates the module-level counter (_counter) inside the loop but calls snapshot() only once after the loop, so the module-level list _snapshots (the variable recording per-item snapshots) is appended a single time instead of once per processed item. The causal relationship is that process_batch controls when snapshots are recorded but it invokes snapshot() at the wrong time (after the loop) causing under-recording in _snapshots.

## Failure Mechanism
For example, call reset(); then process_batch([1, 2, 3]). process_batch increases _counter three times (0 -> 1 -> 3 -> 6) but snapshot() is called only once at the end, so _snapshots becomes length 1 instead of length 3. Any code that expects one snapshot per item (for instance, checking snapshot counts or replaying state per item) will observe too few snapshots and will treat the batch as if it produced fewer effects.

## Broken Invariant
After processing N items, the number of recorded snapshots must equal the number of processed items. Formally: reset(); process_batch(items); verify_consistency() should return True and len(get_snapshots()) == len(items). The original code violates this because len(get_snapshots()) becomes 1 regardless of len(items) > 0.

## Fix Strategy
I changed process_batch to record a snapshot immediately after each per-item counter update and introduced an explicit _processed_count to track how many items have been processed. I renamed the low-level snapshot function to record_snapshot for clarity and kept snapshot as a backward-compatible wrapper. verify_consistency now returns a boolean comparing _processed_count to len(_snapshots). This directly fixes the mechanism: snapshots are appended inside the loop once per item, and consistency is testably enforced by comparing the two counters.

```python
 """Batch processor with per-item snapshots.

This module maintains a running counter and records a snapshot of the counter after
each processed item. It exposes functions to reset state, process a batch of items,
retrieve snapshots, and verify that each processed item produced exactly one snapshot.
"""

# Module-level state
_counter = 0
_snapshots = []
_processed_count = 0


def reset():
    """Reset the counter, snapshot list, and processed-item count."""
    global _counter, _snapshots, _processed_count
    _counter = 0
    _snapshots = []
    _processed_count = 0


def record_snapshot():
    """Record the current counter value into the snapshots list.

    This is the clearer, explicit name for the operation. The old name
    snapshot() is preserved as a thin wrapper for backward compatibility.
    """
    _snapshots.append(_counter)


def snapshot():
    """Backward-compatible wrapper for record_snapshot()."""
    record_snapshot()


def get_snapshots():
    """Return a shallow copy of the snapshots recorded so far."""
    return list(_snapshots)


def process_batch(items):
    """Process each item by adding it to the counter and recording a snapshot.

    For each item in items:
    - increment the running counter by the item's value
    - record a snapshot immediately after that increment

    Returns the updated counter value.
    """
    global _counter, _processed_count
    for item in items:
        _counter += item
        # Record a snapshot for this item (one snapshot per processed item)
        record_snapshot()
        _processed_count += 1
    return _counter


def verify_consistency():
    """Verify that exactly one snapshot was recorded per processed item.

    Returns True when the number of snapshots equals the number of processed items,
    otherwise False.
    """
    return _processed_count == len(_snapshots)

```
