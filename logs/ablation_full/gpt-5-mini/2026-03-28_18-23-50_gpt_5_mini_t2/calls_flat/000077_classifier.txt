# Developer's Reasoning

## Root Cause
In loader.load the module-level variable _status (and implicitly _data) is not updated when source is empty or None. The load function only sets _status = 'loaded' and _data when the if branch (source and len(source) > 0) is taken; on the else path it leaves _status and _data unchanged, so the previous call's _status persists.

## Failure Mechanism
Concretely: call sequence: load([1,2]) sets _status='loaded' and _data=[1,2]. A subsequent call load([]) or load(None) returns (previous) _data or an empty value but does not modify _status, so get_status() still returns 'loaded'. When run_pipeline([]) executes, it calls load([]), then status = get_status() yields 'loaded' while data is empty (count 0). The pipeline therefore reports status 'loaded' for an empty source, violating the intended behavior and misleading downstream consumers.

## Broken Invariant
After run_pipeline(source) completes, its returned 'status' must reflect the outcome of THIS call. In particular, for an empty or None source the invariant is: run_pipeline([]) (or run_pipeline(None)) must return {'status': 'empty', 'count': 0, 'data': []}.

## Fix Strategy
I changed loader.load to explicitly handle the empty/None case: the else branch now sets _data = [] and _status = 'empty'. This makes _status deterministic for every call to load and ensures get_status()/get_data() reflect the current call's outcome. Returning an empty list for _data also makes counts stable (len(data) == 0) instead of relying on None checks.
