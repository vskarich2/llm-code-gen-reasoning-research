# Developer's Reasoning

## Root Cause
pipeline.ingest is missing a break after a successful call to send_with_retry, causing the pipeline loop to perform additional send attempts. Because sender._attempt_count is global and incremented inside sender.send(), subsequent iterations call send() again and append the same message multiple times. Additionally, sender.send_with_retry always returned True even when all attempts failed, masking failures and allowing pipeline.ingest to proceed as if a send had succeeded.

## Failure Mechanism
Example: ingest(msg, max_pipeline_retries=2, fail_first=True) calls send_with_retry which itself attempts to send up to 2 times. On the first call, send() raises ConnectionError (fail_first), send_with_retry retries and succeeds on its second attempt and appends the message once. Because pipeline.ingest lacked a break, the outer pipeline loop continues to the next iteration and calls send_with_retry again. That causes sender.send() to append the message again (incrementing sender._attempt_count and calling append/notify again). Result: the same message is appended multiple times (2 outer retries × up to 2 inner attempts), producing 2–4 duplicates. Furthermore, if send_with_retry exhausted its inner attempts, it previously returned True anyway, so pipeline.ingest would treat a failed send as success and continue, hiding the failure.

## Broken Invariant
A single successful pipeline.ingest(msg, ...) call must result in exactly one call to store.append(msg).

## Fix Strategy
Stop the pipeline from retrying after a successful inner send and make send_with_retry surface failures when all retries fail. I added a break (via a success flag and explicit break) in pipeline.ingest so the pipeline loop stops once send_with_retry succeeds, preventing extra calls to sender.send and duplicate appends. I also changed sender.send_with_retry to raise the last ConnectionError if all attempts fail (instead of returning True), so pipeline-level retry logic receives failures correctly. Finally, I fixed pipeline.reset to call the store and sender reset functions so state is properly cleared between runs.
