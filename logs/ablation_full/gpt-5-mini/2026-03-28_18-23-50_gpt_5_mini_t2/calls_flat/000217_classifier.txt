# Developer's Reasoning

## Root Cause
In make_withdraw_steps(), the nested function step_act() relies on the previously-set mutable variable result['approved'] (written by step_check()) instead of consulting the live account state. The causal relationship: step_check() sets result['approved'] based on check_balance(name, amount) at the time of the check, and step_act() uses that stale result['approved'] to decide whether to call do_withdraw(), so an earlier check result can be used to withdraw later even if the balance changed in between.

## Failure Mechanism
Concrete scenario: reset(); create_account('alice', 100); create two withdraw step pairs for amount=80. run_steps executes (check_a), (check_b), (act_a), (act_b). check_a sets result_a['approved']=True because check_balance('alice',80) sees 100 >= 80. check_b also sets result_b['approved']=True because it also sees 100 >= 80. act_a then calls do_withdraw('alice',80) because result_a['approved'] is True, reducing the balance to 20. act_b still sees result_b['approved'] True (stale) and calls do_withdraw('alice',80) again, reducing the balance to -60. The bug arises because step_act() used the stale result['approved'] variable instead of re-checking the current balance before debiting.

## Broken Invariant
For every account name, after any sequence of withdrawal steps produced by make_withdraw_steps and run_steps, get_balance(name) >= 0. (Example test: after attempting two withdrawals of 80 from an initial balance of 100, the final balance must be >= 0 and the second withdrawal must not be applied if insufficient funds remain.)

## Fix Strategy
Change step_act() to re-check the live balance with check_balance(name, amount) at act time and update result['approved'] based on that fresh check before calling do_withdraw(). This removes reliance on the stale flag set during the earlier check step so an intervening withdrawal will prevent a later act from overdrawing. Concretely, step_act() now does: if check_balance(...): do_withdraw(...); result['approved']=True else result['approved']=False; return ('act', result['approved']).

def do_withdraw(name, amount):

    _accounts[name] = _accounts.get(name, 0) - amount


def run_steps(steps):
    results = []
    for fn, args in steps:

    """Split withdrawal into separate check and act steps.

    BUG: under interleaving, both checks pass before either debits.
    """

        result["approved"] = check_balance(name, amount)

        else:
