# Developer's Reasoning

## Root Cause
The function execute_transfer in transfer_service.py interleaves domain state changes (sender.balance -= amount) with observability side-effects (record_debit, record_credit, emit_failure_alert) and performs a transient failure check (random.random) before the receiver.balance is updated. Specifically, sender.balance is decremented and record_debit is called, then the random failure check can raise before receiver.balance is incremented, so the code can leave the domain state (sender.balance, receiver.balance) partially updated.

## Failure Mechanism
Example: sender.balance == 100, receiver.balance == 0, amount == 30. execute_transfer calls validate_transfer then record_transfer_attempt, then does sender.balance -= 30 (sender.balance becomes 70) and record_debit(sender, 30). Next the code executes if random.random() < 0.3 and that branch triggers: emit_failure_alert(...) is called and RuntimeError('transient failure during credit') is raised. Since receiver.balance += amount and record_credit were not executed, sender lost 30 but receiver did not gain 30; ledger entries contain the debit but no credit. The result is a concrete partial-application: domain balances and ledger entries are inconsistent.

## Broken Invariant
The transfer operation is expected to be atomic at the domain level: for any call execute_transfer(sender, receiver, amount), either both balances change (sender.balance decreases by amount and receiver.balance increases by amount) or neither does. Concretely: after execute_transfer returns (even if it raises a RuntimeError due to transient failures), (sender.balance + receiver.balance) must equal its pre-call value. The original code can violate this (sender decreased but receiver unchanged).

## Fix Strategy
I extracted the pure business logic that validates and performs the balance updates into a new helper _core_transfer(sender, receiver, amount) which performs validate_transfer and then updates both balances with no ledger/audit calls. execute_transfer is turned into an observability wrapper: it records the transfer attempt, invokes the core transfer, and only after the core completes emits ledger entries and audit events. If business logic raises, the wrapper emits a failure alert and re-raises; if observability fails (the simulated transient failure) it only affects logs/alerts, not the domain balances because the atomic balance updates were already done in _core_transfer. This prevents the previous partial-debit bug where a transient failure during the credit phase could leave domain balances inconsistent.

```python
import random
from models import Account
from ledger import record_debit, record_credit, record_transfer_attempt
from audit import emit_transfer_event, emit_failure_alert


def validate_transfer(sender, amount):
    if amount <= 0:
        raise ValueError("amount must be positive")
    if sender.balance < amount:
        raise ValueError("insufficient funds")


def _core_transfer(sender, receiver, amount):
    """Pure business logic: validate and perform the balance updates atomically.

    This helper makes no observability/logging calls so it can't leave the
    domain object state partially-applied due to failures in logging.
    """
    validate_transfer(sender, amount)
    sender.balance -= amount
    receiver.balance += amount


def execute_transfer(sender, receiver, amount):
    """Observability wrapper around the core transfer.

    This wrapper records the attempt, calls the pure business helper, then
    emits ledger and audit events. Any failures in observability will not
    leave the domain balances partially applied because the core helper
    completed the balance changes before observability side-effects.
    """
    record_transfer_attempt(sender.account_id, receiver.account_id, amount)

    try:
        _core_transfer(sender, receiver, amount)
    except Exception as e:
        # Emit a failure alert for errors in business logic and re-raise.
        emit_failure_alert(sender.account_id, receiver.account_id, amount, str(e))
        raise

    # Record ledger entries and emit events after domain state is updated.
    record_debit(sender.account_id, amount)

    # Simulate a transient observability failure during the credit phase.
    if random.random() < 0.3:
        emit_failure_alert(
            sender.account_id, receiver.account_id, amount,
            "connection reset during credit phase",
        )
        raise RuntimeError("transient failure during credit")

    record_credit(receiver.account_id, amount)
    emit_transfer_event(sender.account_id, receiver.account_id, amount)

```
