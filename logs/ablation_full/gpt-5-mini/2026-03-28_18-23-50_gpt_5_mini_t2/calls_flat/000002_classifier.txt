## Root Cause
In create_config, the line 'config = DEFAULTS' binds the local name 'config' to the module-level dictionary DEFAULTS rather than making a copy. As a result, the subsequent 'config.update(overrides)' call mutates the module-level DEFAULTS. The causal relationship is: create_config -> assignment from DEFAULTS -> update(overrides) -> DEFAULTS mutated.

## Failure Mechanism
If a caller does config = create_config({'debug': True}), the function currently assigns config to the same dict object as DEFAULTS and then calls config.update({'debug': True}). That update changes DEFAULTS['debug'] to True. A later call to create_config() (with no overrides) will return a dictionary with 'debug': True even though the caller expected the module defaults to remain unchanged. This manifests as surprising, persistent changes to DEFAULTS after any call to create_config with overrides.

_BASE_DEFAULTS = {'timeout': 30, 'retries': 3, 'debug': False}

    '''Return a new config dict based on DEFAULTS, applying optional overrides.

    DEFAULTS.
