# Developer's Reasoning

## Root Cause
The bug is in process() which directly checks the module-level flag _initialized and, when False, appends an "error:not_init:{item}" entry and returns False. The code defines a _buffer list at module scope but process() never uses it; as a result items handed to process() before init() are discarded (logged as an error) instead of being retained for later processing.

## Failure Mechanism
Concretely, when run_steps executes (process, ("a",)) before (init, ()), process() sees _initialized == False, executes _log.append(f"error:not_init:{item}") and returns False. That call never stores "a" in _buffer, so when init() later sets _initialized = True there is nothing to replay. The sequence in broken_order() therefore produces a log like ["error:not_init:a","init","processed:b","shutdown"] and the item "a" is effectively lost.

## Broken Invariant
For any sequence of steps containing init() and process(item) calls, every call process(item) must produce a corresponding "processed:{item}" entry in the log by shutdown(), regardless of whether process(item) was invoked before or after init(). (Testable by calling run_steps with any interleaving that includes an init() and asserting every item seen by process() appears as "processed:{item}" in get_log()/shutdown().)

## Fix Strategy
I changed process() so that if _initialized is False it appends the item to the module-level _buffer instead of logging an error or dropping it. I also changed init() to, after setting _initialized = True and logging "init", flush _buffer by emitting "processed:{item}" entries for each buffered item and clearing the buffer. This ensures items that arrive before init() are retained and processed once initialization occurs, restoring the invariant that every process(item) call results in a "processed:{item}" log entry after init(). The changes specifically use the existing _buffer variable and add buffering + flushing logic while preserving other behavior.
