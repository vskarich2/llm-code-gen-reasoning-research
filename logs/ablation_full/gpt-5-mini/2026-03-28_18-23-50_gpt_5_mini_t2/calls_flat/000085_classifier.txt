# Developer's Reasoning

## Root Cause
The bug is in retry_send: the local variable 'result' is checked with 'if not result: continue', but there is no break or return on success. This inverted/insufficient logic causes retry_send to ignore a successful send() and keep looping.

## Failure Mechanism
For example, with max_retries=3 and send always returning True, calling retry_send('msg', max_retries=3) will call send three times and append 'msg' to _sent three times. Because retry_send never returns or breaks when result is True, the loop continues for all iterations and produces duplicate entries in _sent.

## Broken Invariant
If send(msg) returns True on the first attempt, then retry_send(msg, max_retries=N) must call send exactly once and return True. (This is testable by checking len(get_sent()) after a single retry_send call.)

## Fix Strategy
I changed retry_send to stop immediately when send(msg) returns True (returning True). If all attempts fail, retry_send returns False. I also implemented clear_log() to actually clear the _sent list (delegating to reset) so the log-clearing utility works. These changes ensure the function exits on success and no duplicate sends occur.

def retry_send(msg, max_retries=2):
    """Send with retry.

    Try up to max_retries times. Stop and return True as soon as a send succeeds.
    Return False if all attempts fail.
    """
    for _attempt in range(max_retries):
        result = send(msg)
        if result:
            # Stop retrying on success.
            return True
        # otherwise continue to next attempt
    return False
