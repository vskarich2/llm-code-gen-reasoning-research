# Developer's Reasoning

## Root Cause
The bug is in is_enabled(flag_name): it calls FLAGS.get(flag_name, False) using the raw flag_name string passed by callers. Callers often pass camelCase names (e.g. "darkMode") while FLAGS keys are snake_case (e.g. "dark_mode"). Because is_enabled does not normalize the caller-provided name, the lookup misses the existing snake_case key and falls back to the silent default False.

## Failure Mechanism
Concrete scenario: FLAGS contains "dark_mode": True. A caller calls is_enabled("darkMode"). is_enabled performs FLAGS.get("darkMode", False). Since "darkMode" is not a key in FLAGS, .get returns the default False, so the caller observes dark mode as disabled even though FLAGS["dark_mode"] is True. The mismatch between caller key format and stored key format causes the incorrect False result.

## Broken Invariant
For any feature whose canonical snake_case key K exists in FLAGS, calling is_enabled with either K or its camelCase equivalent must return the same boolean value. Formally: for a snake_case key K in FLAGS, let C be the camelCase form of K; then is_enabled(K) == is_enabled(C) == FLAGS[K]. The original implementation violated this invariant (e.g. is_enabled('darkMode') != FLAGS['dark_mode']).

## Fix Strategy
I normalize incoming flag names to snake_case before performing the lookup. I added a helper _to_snake_case and changed is_enabled to convert the provided flag_name to snake_case, then perform FLAGS.get(snake_name, False). This ensures lookups succeed whether callers pass snake_case or camelCase, eliminating the silent mismatch that caused missing-key False results. I also made list_flags return a sorted list for deterministic output and added basic type checking and clearer docstrings for clarity.

# Code Produced
```python
 """Feature flag system with snake_case keys.

This module stores flags with snake_case keys but accepts either snake_case or
camelCase names when checking whether a feature is enabled. The public API:

- is_enabled(flag_name): returns True/False for the named feature. Accepts
  either snake_case or camelCase and normalizes the name before lookup.
- list_flags(): returns a deterministic (sorted) list of available flag names.
"""

import re

FLAGS = {
    "dark_mode": True,
    "beta_features": False,
    "new_dashboard": True,
    "analytics_v2": False,
}


def _to_snake_case(name):
    """Convert a camelCase or mixed-name string to snake_case.

    Examples:
        "darkMode" -> "dark_mode"
        "AnalyticsV2" -> "analytics_v2"
        "new-dashboard" -> "new_dashboard"
    """
    if not isinstance(name, str):
        raise TypeError("flag name must be a string")

    # Normalize separators to underscore first
    s = re.sub(r"[\-\s]+", "_", name)
    # Turn camelCase / PascalCase into snake_case
    s = re.sub(r"(.)([A-Z][a-z]+)", r"\1_\2", s)
    s = re.sub(r"([a-z0-9])([A-Z])", r"\1_\2", s)
    return s.lower()


def is_enabled(flag_name):
    """Check if a feature flag is enabled.

    flag_name may be provided in snake_case or camelCase; it will be
    normalized to snake_case before lookup. Unknown flags return False.

    Args:
        flag_name: the flag key to look up (snake_case or camelCase)

    Returns:
        True if the flag is enabled, False otherwise.
    """
    snake = _to_snake_case(flag_name)
    return FLAGS.get(snake, False)


def list_flags():
    """Return all flag names (sorted for deterministic order)."""
    return sorted(FLAGS.keys())

```
