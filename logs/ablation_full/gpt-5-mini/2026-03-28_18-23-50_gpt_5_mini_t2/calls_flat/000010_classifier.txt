# Developer's Reasoning

## Root Cause
In config.create_config the local variable `config` is set to the module-level `DEFAULTS` dict (config = DEFAULTS), so create_config returns a reference to the shared DEFAULTS object instead of a new dict. In middleware.ConfigMiddleware.apply_config the code does `cfg = self._base` and then `cfg.update(request_overrides)`, which mutates that shared dict (self._base is the same object returned by create_config). The combination of create_config returning DEFAULTS and middleware applying updates in-place causes global/shared state to be mutated.

## Failure Mechanism
Concrete scenario: when a ConfigMiddleware instance is constructed, __init__ calls create_config(), which returned the DEFAULTS object (not a copy). Later, handle_debug_request() calls handle_request({'debug': True}), which calls mw.apply_config and runs cfg = self._base followed by cfg.update({'debug': True}). Because cfg is the same object as DEFAULTS and self._base, the update mutates the shared dict and sets DEFAULTS['debug'] = True. Subsequent requests that call handle_request() without overrides read debug from the mutated cached config and incorrectly see debug=True. In short: per-request overrides (cfg.update) leak into the cached base and into DEFAULTS because the same dict object is reused and mutated.

## Broken Invariant
create_config(overrides=None) must return a new dict object equal to DEFAULTS but not the same object (i.e., create_config() is not DEFAULTS). Additionally, apply_config(request_overrides) must not mutate the middleware's cached base config or the module DEFAULTS: after apply_config({'debug': True}), a later call apply_config(None) must still return a config where 'debug' equals DEFAULTS['debug'] as it was before the per-request override (i.e., per-request overrides must not persist between requests). Both are testable: (1) assert create_config() is not DEFAULTS; (2) assert ConfigMiddleware().apply_config({'debug': True}); then ConfigMiddleware().apply_config(None)['debug'] == False (given the factory default False).

## Fix Strategy
Make create_config return a shallow copy of DEFAULTS so callers get an independent dict (changed `config = DEFAULTS` to `config = dict(DEFAULTS)`). Also make ConfigMiddleware.apply_config copy the cached base before applying per-request overrides (changed `cfg = self._base` to `cfg = dict(self._base)`). These two changes ensure per-request updates mutate only the returned per-request dict and cannot change the cached base or the module DEFAULTS, preventing override leakage between requests.

from config import create_config


class ConfigMiddleware:
    """Middleware that loads config once and applies per-request overrides."""

    def __init__(self):
        self._base = create_config()  # cached at init time

    def apply_config(self, request_overrides=None):
        """Return config for this request, applying any overrides."""
        # Copy the cached base so per-request overrides don't mutate the cached object.
        cfg = dict(self._base)
        if request_overrides:
            cfg.update(request_overrides)
        return cfg
