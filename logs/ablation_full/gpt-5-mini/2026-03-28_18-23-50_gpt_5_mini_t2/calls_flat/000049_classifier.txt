# Developer's Reasoning

## Root Cause
In the function enqueue the parameter 'queue' uses a mutable default value defined as [] in the function signature (def enqueue(task, queue=[]):). That default list object is created once at function definition time and reused by every call that omits the 'queue' argument, so multiple calls append to the same list.

## Failure Mechanism
Concretely, calling enqueue(make_task('a')) returns ['a'] on the first call, but a subsequent call enqueue(make_task('b')) (with no explicit queue) returns ['a', 'b'] because both calls used the same default list object. This violates the expectation in the module docstring and also causes process(queue) to process tasks from previous unrelated calls (for example process(enqueue(make_task('b'))) will yield ['done:a', 'done:b'] instead of ['done:b']).

## Broken Invariant
The module-level invariant (documented in enqueue's docstring) is: for any call enqueue(t) that omits the 'queue' parameter, the returned list must contain exactly one element equal to t. In other words, two successive calls enqueue(a) and enqueue(b) without passing an explicit queue must have the second call return a list of length 1 containing only b. The current implementation violates this.

## Fix Strategy
I replaced the mutable default list with None and create a fresh list inside the function when queue is None. Specifically, I changed the signature to def enqueue(task, queue=None): and added if queue is None: queue = []. This ensures each call that omits 'queue' receives a newly allocated list (breaking the unwanted sharing), while preserving the ability to append to an explicitly provided queue.
