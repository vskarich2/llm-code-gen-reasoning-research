# Developer's Reasoning

## Root Cause
The bug is in make_increment_steps(): step_read stores a snapshot in captured['current'] using get(), but step_write uses that stale captured['current'] to compute the new value (calling _set(captured['current'] + 1)). Because step_write bases its update on the previously captured value instead of the actual current _value at write time, a later write can overwrite a concurrent increment rather than incrementing it.

## Failure Mechanism
Concrete scenario in interleaved_double_increment(): reset() sets _value = 0. read_a() runs and sets captured['current'] = 0. read_b() runs and sets its own captured['current'] = 0. write_a() calls _set(captured['current'] + 1) => _set(0 + 1) sets _value to 1. write_b() then calls _set(captured['current'] + 1) => _set(0 + 1) sets _value to 1 again, overwriting the increment made by write_a. As a result get() returns 1 instead of 2.

## Broken Invariant
For any interleaving of the read/write steps produced by N calls to make_increment_steps(), the final counter value must equal the initial counter value plus N. Concretely, after two increments starting from 0 (as exercised by interleaved_double_increment()), get() must be 2.

## Fix Strategy
Change step_write so it computes the increment from the actual current value at write time (call get() inside step_write) rather than using the stale captured['current']. This makes each write perform a read-modify-write based on the real current _value at the moment of the write, so a write that occurs after another write will increment the already-updated value instead of overwriting it with a stale increment. The code change replaces _set(captured['current'] + 1) with new_val = get() + 1; _set(new_val) and returns that new_val.

_value = 0


def reset():
    global _value
    _value = 0


def get():
    return _value


def _set(v):
    global _value
    _value = v


def run_steps(steps):
    results = []
    for fn, args in steps:
        results.append(fn(*args))
    return results


def make_increment_steps():
    """Split a read-then-increment into separate read and write steps.

    FIX: the write step computes the increment from the actual current
    value at write time (calls get()) instead of using the previously
    captured value. This prevents a later write from overwriting a
    concurrent update with a stale value.
    """
    captured = {}

    def step_read():
        captured["current"] = get()
        return ("read", captured["current"])

    def step_write():
        # Use the current counter value at the time of the write so we
        # don't overwrite concurrent increments with a stale snapshot.
        new_val = get() + 1
        _set(new_val)
        return ("write", new_val)

    return step_read, step_write


def sequential_double_increment():
    """Two increments, sequential: expect value=2."""
    reset()
    read_a, write_a = make_increment_steps()

    run_steps([(read_a, ()), (write_a, ()), (read_b, ()), (write_b, ())])
