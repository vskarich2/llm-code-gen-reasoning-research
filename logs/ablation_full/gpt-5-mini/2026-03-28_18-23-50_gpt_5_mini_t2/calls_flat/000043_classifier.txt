## Root Cause
client.py module-level assignment: the expression "_client_config = get_config()" captures the config dict at import time, causing the client to hold a reference to the old config instead of consulting get_config() on each access.

## Failure Mechanism
At import time client.py executes get_config() → _client_config is bound to the current config dict object → later reset_config() in config.py sets the module-level _config to None (so future get_config() calls will reload) but client._client_config still references the original dict → subsequent calls to client.get_timeout() read the stale value from _client_config['timeout'] → observable failure: client continues to return the old timeout even after reset_config() and reload.

## Broken Invariant

## Fix Strategy
Remove the module-level capture of the config object in client.py. Change client functions to call get_config() at the time of each access (e.g., in get_db_url() and get_timeout()) so that after reset_config() the next call will obtain the reloaded config. This breaks the causal chain because there is no longer a long-lived reference (_client_config) that preserves old values across resets; each access consults config.get_config() which either returns the existing config or lazily reloads it after reset.
