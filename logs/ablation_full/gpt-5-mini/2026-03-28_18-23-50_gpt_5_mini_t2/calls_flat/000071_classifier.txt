## Root Cause
processor.process_batch uses the loop variable 'item' after the for-loop when calling audit_log: the operation audit_log(item['id'], ...) is executed only once (outside the loop) and therefore only records a single audit entry corresponding to the last value of 'item'.

## Failure Mechanism
Cause → mutation/event: process_batch iterates items and mutates module state via increment(item['value']) and emit_event(item['id'], item['value']) for each item; however, the call to audit_log is performed after the loop using the loop variable 'item'. Mutation → propagation: because audit_log is invoked once with the final loop 'item', no per-item audit entries are appended to audit._audit_log during processing. Observable failure: audit.get_audit_log() contains fewer entries than len(items) (typically exactly one extra entry for the last item), breaking audit-traceability.

## Broken Invariant
For any non-bulk processing call process_batch(items), the number of audit entries produced by audit.get_audit_log() must equal len(items) (i.e., one 'processed' audit entry per input item). This invariant is violated because process_batch currently produces only a single audit entry when items has length > 1.

## Fix Strategy
Move the per-item audit_log call inside the per-item loop so that an audit entry is recorded for each processed item. Additionally, make per-item processing robust by wrapping each item's increment/emit in try/except and recording a 'processed' audit on success or a 'processing_failed' audit on exception. This breaks the causal chain by ensuring audit_log is invoked exactly once per input item (instead of once per batch) and making sure errors don't silently drop audit records. Also fix reset() in processor to delegate to metrics.reset() and audit.reset() rather than trying to reinitialize module-local globals that don't exist in processor.

from metrics import increment, emit_event
from audit import audit_log
import metrics
import audit


def reset():
    # Delegate reset to the metrics and audit modules so their internal state
    # is reset correctly instead of attempting to rebind names that don't
    # exist in this module's scope.
    metrics.reset()
    audit.reset()


def fast_process(items):
    """Optimized path for bulk inserts — legitimately batches reasoning_evaluator_audit.
    This is intentionally batch-level; do not change.
    """
    total = 0
    for item in items:
        total += item["value"]
    increment(total)
    emit_event("bulk", total)
    audit_log("bulk", "fast_insert", f"count={len(items)}")
    return total


def process_batch(items):
    """Standard processing: for each item, increment + emit + reasoning_evaluator_audit.

    Fixed behavior: create one audit entry per item. Per-item processing is
    wrapped in try/except so that failures for individual items are recorded
    as 'processing_failed' audits rather than silently dropping audit entries.
    """
    for item in items:
        try:
            # Primary operations per item
            increment(item["value"])
            emit_event(item["id"], item["value"])
            # Per-item audit: record successful processing
            audit_log(item["id"], "processed", f"value={item['value']}")
        except Exception as e:
            # Record the failure for this specific item so audits are complete
            # and traceable. Do not suppress the exception further; re-raise
            # after logging to preserve caller-visible failure behavior.
            try:
                audit_log(item.get("id") if isinstance(item, dict) else None,
                          "processing_failed",
                          f"error={type(e).__name__}: {e}")
            except Exception:
                # If audit logging itself fails, nothing more we can do here;
                # re-raise the original exception to avoid masking the error.
                pass
            raise
    return len(items)
