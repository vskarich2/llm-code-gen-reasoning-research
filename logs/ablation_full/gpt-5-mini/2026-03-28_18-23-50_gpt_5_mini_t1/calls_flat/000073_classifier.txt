## Root Cause
In transform(), the function uses the module-level variable _last_result and returns it unconditionally at the end. Because the assignment to _last_result only happens inside the 'if data:' branch, when data is empty or falsy the function skips assigning and returns the previously stored _last_result instead of producing a fresh list.

## Failure Mechanism
Concrete scenario: call transform([1, 2]) -> inside 'if data:' a new local result list [2, 4] is created and assigned to _last_result, then returned. Next call transform([]) -> 'if data:' is false so the body is skipped and the function returns the module-level _last_result (the stale [2, 4]) rather than an empty list. The stale list is returned even though the current input is empty.

## Broken Invariant

The updated transform() builds result as [item * 2 for item in data] when data is truthy, otherwise sets result = []. Because result is always a newly created list and is returned directly, the function no longer can return stale state from prior calls.
