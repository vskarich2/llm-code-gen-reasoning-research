# Developer's Reasoning

## Root Cause
In code_snippets_v2/silent_default_c/flags.py the _ENV_KEY_MAP entry for the 'dark_mode' flag is wrong: it maps 'dark_mode' -> 'FEATURE_DARKMODE' but the env layer exposes 'FEATURE_DARK_MODE' (see env._ENV). Because flags.is_enabled used that wrong key, env.get_env / get_env_bool never saw the real env var and the environment layer was effectively ignored for dark_mode. In addition, is_enabled previously used get_env_bool(env_key) and only returned True when that call returned True, treating an explicit env value of 'false' as if the env var were absent (so an explicit False env override was not honored).

## Failure Mechanism
Given env._ENV contains 'FEATURE_DARK_MODE': 'true', flags._ENV_KEY_MAP points to 'FEATURE_DARKMODE' so get_env/get_env_bool are called with the wrong key and return None/False as if the env var were absent. is_enabled then falls back to config.get_config_bool('dark_mode') and returns the config value (True in _FILE_CONFIG), so an environment override is ignored. Similarly, if the env had 'FEATURE_DARK_MODE': 'false', the previous code's use of get_env_bool() and the 'if env_val: return True' pattern would skip returning False and fall through to config, again ignoring an explicit False override.

## Broken Invariant
For any flag_name present in _ENV_KEY_MAP, if env.get_env(_ENV_KEY_MAP[flag_name]) is not None then is_enabled(flag_name) must return the boolean value of get_env_bool(_ENV_KEY_MAP[flag_name]) and get_flag_source(flag_name) must return 'env'. This invariant is violated for flag_name='dark_mode' because _ENV_KEY_MAP pointed to the wrong env var name and is_enabled also failed to honor explicit False values from the environment.

## Fix Strategy
Fixes: (1) Correct the env var name in _ENV_KEY_MAP for 'dark_mode' to 'FEATURE_DARK_MODE' so the environment layer is looked up with the actual key present in env._ENV. (2) Change is_enabled to detect presence of the env variable using get_env(env_key) and, when present, return get_env_bool(env_key) (so both True and False env overrides are honored). (3) Ensure config is only used when config.get_config(flag_name) reports a value is present, otherwise fall back to HARDCODED_DEFAULTS. These changes ensure the environment layer correctly overrides config and hardcoded defaults, including explicit False values.

```python
"""Feature flag system with env -> config -> hardcoded fallback chain.

Lookup order:
  1. Environment variable (via env.get_env_bool)
  2. Config file (via config.get_config_bool)
  3. Hardcoded defaults
"""

from env import get_env_bool, get_env
from config import get_config_bool, get_config


HARDCODED_DEFAULTS = {
    "dark_mode": False,
    "beta": False,
    "analytics": False,
}

# Maps flag names to their env var keys
_ENV_KEY_MAP = {
    "dark_mode": "FEATURE_DARK_MODE",
    "beta": "FEATURE_BETA",
    "analytics": "FEATURE_ANALYTICS",
}


def is_enabled(flag_name):
    """Check if a feature flag is enabled.

    Checks env first, then config, then hardcoded defaults.
    """
    env_key = _ENV_KEY_MAP.get(flag_name)
    if env_key:
        # Use get_env to detect presence; if present, honor the env value
        if get_env(env_key) is not None:
            return get_env_bool(env_key)

    # Use the config value only if the config explicitly provides one
    if get_config(flag_name) is not None:
        return get_config_bool(flag_name)

    return HARDCODED_DEFAULTS.get(flag_name, False)


def get_flag_source(flag_name):
    """Return which layer provides the flag value (for debugging)."""
    env_key = _ENV_KEY_MAP.get(flag_name)
    if env_key:
        if get_env(env_key) is not None:
            return "env"

    if get_config(flag_name) is not None:
        return "config"

    return "hardcoded"

```
