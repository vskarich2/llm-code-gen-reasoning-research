# Developer's Reasoning

## Root Cause
In sender.send_with_retry the retry loop (for attempt in range(max_retries)) does not stop after a successful send; it continues iterating. Because send() calls append(msg) and notify(msg) on each successful invocation and increments the module-level _attempt_count, a later iteration after a success will call append/notify again, producing duplicate messages in the store.

## Failure Mechanism
Example: call send_with_retry('hello', max_retries=3, fail_first=True). On attempt 1 send() raises (transient failure). On attempt 2 send() succeeds and calls append('hello') and notify('hello'). Because send_with_retry does not break/return after that success, the loop proceeds to attempt 3 and calls send() a third time, which also succeeds and calls append('hello') again. The store ends up with two entries for the same message.

## Broken Invariant
When send_with_retry(msg, ...) returns successfully, the message must have been appended to the store exactly once (i.e., store.message_count() should increase by 1). Currently a successful send_with_retry can append the same msg multiple times when max_retries > the number of attempts needed to succeed.

## Fix Strategy
After a successful send() we immediately return True to stop further retry iterations and prevent additional append/notify calls. If all attempts fail we raise the last ConnectionError so failures aren't silently swallowed. I also fixed sender.reset to only reset the attempt counter (it previously created module-level _messages/_notifications which belong to store). These changes ensure that once send() succeeds, no subsequent loop iteration will duplicate the message.

"""Message sender with retry and store integration."""

from store import append, notify, get_messages, get_notifications

_attempt_count = 0


def reset():
    global _attempt_count
    # Only reset the attempt counter here. The message/notification lists belong to store.py.
    _attempt_count = 0


def send(msg, fail_first=False):
    """Send a message: store it and notify.

    If fail_first is True, raises on first call to simulate transient error.
    """
    global _attempt_count
    _attempt_count += 1
    if fail_first and _attempt_count == 1:
        raise ConnectionError("transient failure")
    append(msg)
    notify(msg)
    return True


def send_with_retry(msg, max_retries=2, fail_first=False):
    """Retry send on transient errors.

    Attempts up to max_retries times. Returns True on first successful send.
    Raises the last ConnectionError if all attempts fail.
    """
    last_error = None
    # Use 1-based attempt counting to make the final-attempt check straightforward.
    for attempt in range(1, max_retries + 1):
        try:
            send(msg, fail_first=fail_first)
            # Success: stop retrying to avoid duplicate append/notify calls.
            return True
        except ConnectionError as e:
            last_error = e
            if attempt == max_retries:
                # Exhausted retries — propagate the last error.
                raise last_error
            # otherwise continue to next attempt
            continue


def get_attempt_count():
    return _attempt_count
