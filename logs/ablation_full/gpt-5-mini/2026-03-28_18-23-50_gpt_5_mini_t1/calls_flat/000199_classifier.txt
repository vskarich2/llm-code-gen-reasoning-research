# Developer's Reasoning

## Root Cause
There were two separate functions in cache_writer.py—refresh_user_snapshot and sync_user_to_cache—that performed the same conceptual operation (storing a user's display name in the in-memory cache) but used different underlying semantics: refresh_user_snapshot called cache_put_if_absent(f"user:{user['id']}", user["name"]) while sync_user_to_cache called cache_put(f"user:{user['id']}", user["name"]). The coexistence of both functions led to callers using different update semantics depending on which helper they imported.

## Failure Mechanism
Because rename_user in user_service.py called refresh_user_snapshot(updated) (which delegates to cache_put_if_absent), a rename that updated the database would not update the cached name if an entry for that user already existed. Concretely: db.update_name(user_id, new_name) updates UserDB, lookup_user returns the updated object, but refresh_user_snapshot uses cache_put_if_absent and therefore leaves the old value in _store. As a result get_display_name(user_id) (which reads from cache_writer._store) continued to return the old name after a rename.

## Broken Invariant
After rename_user(user_id, new_name) completes with an existing cached entry, get_display_name(user_id) should equal new_name. In the original code, rename_user(user_id, new_name) can leave get_display_name(user_id) unchanged when the cache already had an entry, violating this invariant.

## Fix Strategy
I consolidated the two helpers into a single function cache_user(user, overwrite=False) in cache_writer.py that exposes both behaviors via an explicit overwrite flag (overwrite=True performs cache_put; overwrite=False performs cache_put_if_absent). Then I updated all callers in user_service.py to use cache_user with the appropriate flag: save_user and bulk_warm_cache use the warm/populate behavior (overwrite=False to preserve prior put_if_absent semantics), while rename_user uses overwrite=True so the cache is updated after a rename. This removes the duplicated helpers and makes the choice of semantics explicit at call sites, ensuring rename_user updates the cache as intended.
