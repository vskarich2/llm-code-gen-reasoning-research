## Root Cause

Because get_settings stored a reference to the original DEFAULTS-backed dict, later changes (reset_defaults assigning a new DEFAULTS or callers mutating settings via apply_overrides) caused unexpected stale or aliased state.

## Failure Mechanism
Sequence that demonstrates the failure: 1) First call get_settings() -> create_config() returns the DEFAULTS object and _cached_settings is set to that dict. 2) reset_defaults() assigns a new dict to the module-level DEFAULTS variable. 3) Subsequent get_settings() returns the previously cached dict (the old DEFAULTS object), not reflecting the new DEFAULTS. Also, apply_overrides used settings.update(overrides) on the cached dict, mutating the object aliased to DEFAULTS and causing cross-call side effects. The cause is the shared object returned by create_config combined with caching in app.get_settings.

## Fix Strategy
