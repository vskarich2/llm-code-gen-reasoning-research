## Root Cause
config.create_config returns the module-level DEFAULTS object (config = DEFAULTS) instead of a copy, and middleware.ConfigMiddleware.apply_config assigns cfg = self._base and then calls cfg.update(...). Because create_config returns the same DEFAULTS dict, updates in apply_config mutate the shared DEFAULTS object (via self._base) and those mutations are observed by subsequently created middleware instances.

## Failure Mechanism
Sequence: handler.handle_debug_request calls handle_request({'debug': True}), which constructs a new ConfigMiddleware(); ConfigMiddleware.__init__ calls create_config() and receives the module DEFAULTS object (no copy). apply_config sets cfg = self._base (the DEFAULTS reference) and cfg.update({'debug': True}), which mutates DEFAULTS. A later request creates a new ConfigMiddleware; its __init__ again calls create_config() and receives the already-mutated DEFAULTS, so the subsequent request incorrectly sees debug=True even though that request did not request it.

## Broken Invariant
create_config(overrides=None) must not mutate or return a direct reference to the module-level DEFAULTS. Specifically, after calling handle_request({'debug': True}) then handle_request() the second call must return debug == False (i.e., per-request overrides must not persist globally).

## Fix Strategy
Return a fresh dict from create_config and avoid mutating the cached base in middleware. create_config now builds a shallow copy with dict(DEFAULTS) and applies overrides to that copy. ConfigMiddleware.apply_config now creates a shallow copy of self._base (cfg = dict(self._base)) before applying request_overrides, so per-request updates do not change the cached base or the module-level DEFAULTS. These changes prevent cross-request leakage of overrides.
