# Developer's Reasoning

## Root Cause
In pipeline.pipeline the variable 'cleaned' (the result of normalize(data)) is passed into compute_raw_stats: raw_stats = compute_raw_stats(cleaned). compute_raw_stats is implemented to compute statistics on untransformed data (raw_max/raw_min/raw_sum). Passing 'cleaned' (normalized values) instead of the original 'data' causes the wrong inputs to compute_raw_stats.

## Failure Mechanism
For example, given input data = [10, 20, 30], normalize(data) returns [0.0, 0.5, 1.0]. The current code calls compute_raw_stats(cleaned), so compute_raw_stats sees [0.0, 0.5, 1.0] and returns {'raw_max': 1.0, 'raw_min': 0.0, 'raw_sum': 1.5}. The expected raw stats for the original data are {'raw_max': 30, 'raw_min': 10, 'raw_sum': 60}. Thus the pipeline returns raw statistics that reflect the normalized values rather than the original values.

## Broken Invariant
The pipeline function must satisfy: pipeline(data)['raw_stats'] == compute_raw_stats(data) for any input data. Currently this invariant is violated because compute_raw_stats is called with 'cleaned' instead of the original 'data', causing pipeline(data)['raw_stats'] to equal compute_raw_stats(cleaned) rather than compute_raw_stats(data).

## Fix Strategy
Change the call in pipeline.pipeline to compute_raw_stats(data) so compute_raw_stats operates on the original untransformed input. This preserves the intended order (normalize afterwards for 'cleaned' and 'display') and ensures 'raw_stats' reflect the raw input. No changes are required in transforms.py because compute_raw_stats already implements the correct raw-stat contract.
