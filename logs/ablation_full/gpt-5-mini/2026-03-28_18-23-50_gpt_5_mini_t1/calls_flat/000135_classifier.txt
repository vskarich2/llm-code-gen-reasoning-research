## Failure Mechanism

This off-by-one propagates to the system allowing one more request than the specified limit (observable failure: more than 'limit' requests are accepted).

This breaks the causal chain because previously (count == limit) → allowed; now (count == limit) → blocked, preventing the extra request.

def is_rate_limited(count, limit):
    """Check if the request count has reached the rate limit.

    Args:
        count: current number of requests made (non-negative integer)
        limit: maximum allowed requests (non-negative integer)

    Returns:
        True if the caller should be blocked, False if allowed.
    """
    # Ensure values are non-negative (defensive). This avoids silently
    # accepting negative counts/limits which would mask incorrect usage.
    if count < 0 or limit < 0:
        raise ValueError("count and limit must be non-negative")

    # Correct comparison: block when the current count is greater than or
    # equal to the allowed limit. Previously this used '>' and allowed one
    # extra request when count == limit.
    return count >= limit


def check_and_increment(current_count, limit):
    """Check rate limit and return (blocked, new_count).

    If not blocked, increments the count.
    """
    if is_rate_limited(current_count, limit):
        return True, current_count
    return False, current_count + 1
