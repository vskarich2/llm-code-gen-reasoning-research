## Root Cause

## Failure Mechanism
Concrete sequence: add_product writes to _db; a subsequent get_product checks the cache, finds nothing, and executes put(product_id, dict(product)) to cache a copy of the product. Later update_product(product_id, price=new_price) executes _db[product_id].update(fields) (the DB is changed) but does not call invalidate(product_id). A later get_product(product_id) calls get(product_id) and returns the cached dict (containing the old price) instead of the updated DB value. The code location of the put is in get_product (put(product_id, dict(product))) and the missing invalidate is in update_product (there is a comment '# BUG: should call invalidate(product_id) but doesn't').

## Broken Invariant

Testable statement: if update_product(pid, price=42.0) returns True, then get_product(pid)['price'] == 42.0. The current code can return the old price because the cache was not invalidated.

## Fix Strategy

"""Product catalog using external cache module."""

from cache import get, put, invalidate

_db = {}


def add_product(product_id, name, price):
    """Add a product to the database."""
    _db[product_id] = {"name": name, "price": price}


def get_product(product_id):
    """Get product, checking cache first."""
    cached = get(product_id)
    if cached is not None:
        return cached
    product = _db.get(product_id)
    if product is not None:
        put(product_id, dict(product))
    return _db.get(product_id)


def update_product(product_id, **fields):
    """Update product in DB.

    Invariant: subsequent get_product() must reflect the update.
    """
    if product_id not in _db:
        return False
    _db[product_id].update(fields)
    # Ensure cached entry is removed so subsequent get_product() returns updated data
    invalidate(product_id)
    return True


def reset():
    """Clear DB and cache."""
    _db.clear()
    from cache import clear
    clear()
