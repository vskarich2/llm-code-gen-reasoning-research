# Developer's Reasoning

## Root Cause
The bug is in function enqueue: the parameter queue has a mutable default value (queue=[]). Because Python evaluates default arguments once at function definition time, the single list object bound to the default parameter is shared across calls. The code then calls queue.append(task) which mutates that shared list.

## Failure Mechanism
Concretely, calling enqueue('a') with no explicit queue returns ['a'] the first time. A subsequent call enqueue('b') with no explicit queue will append to the same default list and return ['a', 'b'] rather than ['b']. The cause-effect chain is: enqueue defined with queue=[] -> default list object is created once -> each call that omits queue receives that same object -> queue.append(task) mutates that shared object -> tasks accumulate across independent calls.

## Broken Invariant
Invariant violated by the code: "For any call to enqueue(task) without passing an explicit queue argument, the returned list must contain only that single task (i.e., have length 1 and contain the provided task)." The current implementation can return a list containing previous tasks when called multiple times without an explicit queue.

## Fix Strategy
I changed the enqueue signature to use queue=None and created a fresh list inside the function when queue is None. This ensures each call that omits queue receives a new list, so queue.append(task) mutates a per-call list rather than a shared object. The change preserves the ability to pass an explicit queue (the function still appends to and returns the provided list).
