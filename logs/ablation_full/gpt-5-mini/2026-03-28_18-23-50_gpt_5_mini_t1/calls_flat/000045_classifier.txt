# Developer's Reasoning

## Root Cause
In client.py the module-level variable _client_cfg is assigned once at import time by calling config.get_config(). That stores a reference to the configuration dictionary returned at import time. When config.reset_config() sets config._config = None and later config.get_config() returns a new dict, client._client_cfg still points to the old (stale) dict.

## Failure Mechanism
Sequence: import client -> client._client_cfg = get_config() binds to initial dict A. Later code calls config.reset_config(), which sets config._config = None. Then code calls config.set_config('api_key', 'new-key') which calls get_config(), creating a new dict B and mutating B['api_key']='new-key'. client.get_api_key() still reads from client._client_cfg (dict A) and returns the old API key, so handler.make_request() built via client.get_api_key()/get_base_url() reflects the stale values from dict A instead of the current values in dict B.

## Broken Invariant
Handler.make_request(endpoint) must reflect the current configuration: after config.reset_config() and subsequent config.set_config(key, value) or get_config() calls, get_api_key() and get_base_url() (and thus handler.make_request()) MUST return the values from the most recently loaded configuration dict. Currently they can return values from a previously captured dict.

## Fix Strategy
Remove the import-time snapshot in client.py so each accessor calls config.get_config() at call time. This ensures client functions always read the current config object that config.get_config() returns after reset_config(). The change replaces the module-level _client_cfg = get_config() with direct calls to get_config() inside get_api_key() and get_base_url(), so no stale reference is kept.
