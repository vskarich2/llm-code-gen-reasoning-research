## Root Cause
cache_writer.refresh_user_snapshot uses cache_put_if_absent on _store via cache_put_if_absent(f"user:{user['id']}", user['name']) — the use of cache_put_if_absent (operation) prevents updating an existing cached display name when callers expect the cache to reflect the current DB value.

## Failure Mechanism
rename_user or save_user → call refresh_user_snapshot(user) → refresh_user_snapshot calls cache_put_if_absent which checks if key exists and does nothing if present → existing cache entry (old name) remains unchanged → cache_reader.get_display_name(user_id) returns stale name → callers that format or display the name observe the old value instead of the updated DB name.

## Broken Invariant

## Fix Strategy
Consolidate the two similar functions into a single function sync_user_to_cache(user, overwrite=False) in cache_writer.py. Implement it so when overwrite=True it uses cache_put (always write) and when overwrite=False it uses cache_put_if_absent (warm-only). Update all callers in user_service.py to call the unified function. Specifically: save_user and rename_user should call sync_user_to_cache(..., overwrite=True) to ensure the cache reflects the persisted DB state after changes; bulk_warm_cache should call sync_user_to_cache(..., overwrite=False) to preserve warm-only behavior. This breaks the causal chain by removing the separate refresh_user_snapshot (which used cache_put_if_absent unconditionally) and providing explicit control over overwriting the cache so callers that mutate the DB force a cache update.
