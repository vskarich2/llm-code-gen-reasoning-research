# Developer's Reasoning

## Root Cause
In order_service.place_order the except block for process(...) simply re-raises the ValueError without invoking release(product_id, qty) or remove_audit_entry(order_id). That means the local variables _reserved in inventory.py (updated by reserve) and _audit_log in payment.py (updated by add_audit_entry) are not reverted when payment.process raises, leaving stale reservation and audit entry.

## Failure Mechanism
Concrete scenario: place_order('P1', 2, 10) calls reserve('P1', 2) which increments inventory._reserved['P1'], then add_audit_entry(...) appends an entry to payment._audit_log. If payment._gateway_fail is True, process(...) raises ValueError. place_order's except clause immediately re-raises that ValueError without calling release('P1', 2) or remove_audit_entry('ORD-P1-2'). Result: inventory.get_reserved('P1') remains increased and payment.get_audit_log() still contains the order entry even though payment failed, so the system now has inconsistent state (reserved stock held for a failed order and a dangling audit entry).

## Broken Invariant
After place_order raises a ValueError due to payment failure, the system must satisfy: inventory.get_reserved(product_id) equals the value before calling place_order (i.e., the reservation is released) AND payment.get_audit_log() contains no entry with order_id == f'ORD-{product_id}-{qty}'. The current code violates this: reserved counter remains incremented and the audit log still contains the order entry.

## Fix Strategy
I modified order_service.place_order to perform a best-effort rollback inside the except ValueError handler: it calls release(product_id, qty) to undo the prior reserve and remove_audit_entry(order_id) to delete the audit entry, then re-raises the original ValueError. Each rollback call is invoked in a way that does not mask the original payment exception (we still re-raise) and is guarded so failures in rollback do not hide the payment error. This restores both inventory._reserved and payment._audit_log when payment.process fails.
