## Root Cause
In update_profile, when the 'name' key is present in changes the function sets user['name'] but does not update user['display_name']. The code comment even points to this omission: in update_profile the branch 'if key == "name": user["name"] = value' lacks any assignment to user['display_name'], so changing the name leaves display_name stale.

## Failure Mechanism
Given a user like {'name': 'Bob', 'display_name': 'Bob', 'email': 'b@example.com', 'age': 30}, calling update_profile(user, {'name': 'Robert'}) will execute the 'name' branch and set user['name'] = 'Robert' but will not touch user['display_name']. The result is {'name': 'Robert', 'display_name': 'Bob', ...}, i.e. name and display_name diverge. Any consumer that reads display_name (for example rendering a UI) will see the old value while other logic reads the new name.

## Broken Invariant

## Fix Strategy

To make the intent clear and avoid duplication, introduce a small helper _sync_display_name(user) and call it after updating name. This ensures the code updates display_name immediately when name changes and preserves the invariant.

def _sync_display_name(user):
    """Ensure display_name is always kept in sync with name.

    This helper centralizes the invariant that display_name is derived from
    name and must equal it.
    """
    user["display_name"] = user.get("name")


def update_profile(user, changes):
    """Update user profile fields from changes dict.

        elif key == "display_name":

            continue
        else:
            # Unknown fields are ignored to preserve existing user structure.
            continue
    return user
