The variable _charge_cache is checked to short-circuit re-charging, but because log_charge is only invoked in the non-cached branch, repeated calls for the same txn_id skip log_charge entirely.

## Failure Mechanism

A subsequent call charge('tx1', 100) hits the if txn_id in _charge_cache branch and returns the cached result immediately. Because log_charge is not invoked on the cached path, the reasoning_evaluator_audit _log does not get an entry for the second call; the ledger remains correct (no double-charge) but the audit trail is missing entries for cached calls.

Concretely: for N calls to charge (including repeated calls for the same txn_id), audit.get_log() must have at least N entries corresponding to those calls (each entry matching the txn_id and amount logged by that invocation). Currently, repeated cached calls violate this invariant because they do not append to audit._log.

## Fix Strategy

This preserves the cache semantics (no extra ledger.record calls) while guaranteeing every call to charge results in an audit entry, restoring the invariant that each charge() invocation is logged.
