# Developer's Reasoning

## Root Cause
The deadlock is introduced in make_transfer_b_to_a_steps: its step_lock_b() acquires lock 'B' first and step_lock_a_and_transfer() later acquires lock 'A', which is the opposite order of make_transfer_a_to_b_steps (which acquires 'A' then 'B'). The shared _locks dict is used as the simulated lock table, so holding 'A' in one transfer while holding 'B' in the other creates a circular wait on _locks and triggers the RuntimeError in acquire().

## Failure Mechanism
In interleaved_transfers(), the sequence run_steps([ (lock_ab, ()), (lock_ba, ()), (do_ab, ()), ... ]) executes lock_ab which calls acquire('A') and sets _locks['A']=True, then lock_ba which calls acquire('B') and sets _locks['B']=True. Next do_ab tries acquire('B') but _locks.get('B') is True so acquire('B') raises RuntimeError('deadlock: B already locked'). Because make_transfer_b_to_a_steps acquired B before A, and make_transfer_a_to_b_steps acquired A before B, the two transfers can hold opposite locks and block each other, causing the RuntimeError and preventing completion.

## Broken Invariant
For any transfer that touches both resources 'A' and 'B', the code must always acquire locks in a consistent global order. Concretely: after calling make_transfer_a_to_b_steps(amount) and make_transfer_b_to_a_steps(amount) the first step returned by each must not attempt to acquire the opposite resources in reversed order — i.e., every transfer that needs both 'A' and 'B' must call acquire('A') before acquire('B') (alphabetical order). This invariant is violated by the original make_transfer_b_to_a_steps, which results in testable deadlock when interleaving lock_ab then lock_ba.

## Fix Strategy
I changed make_transfer_b_to_a_steps so it acquires locks in the same order as make_transfer_a_to_b_steps (acquire('A') first, then acquire('B')). By enforcing a consistent global lock ordering (A before B) across both transfer kinds, the interleaving that previously allowed one transfer to hold A while the other held B is impossible. The change removes the circular wait on the _locks dict and therefore prevents the RuntimeError deadlock raised by acquire().

_state = {"A": 100, "B": 100}


def reset():
    _locks.clear()

    _state["B"] = 100


def acquire(resource):
    """Simulate lock. Raises RuntimeError if already held (deadlock)."""
    if _locks.get(resource):
        raise RuntimeError(f"deadlock: {resource} already locked")
    _locks[resource] = True


def release(resource):
    _locks[resource] = False


def get_state():
    return dict(_state)


def run_steps(steps):
    results = []
    for fn, args in steps:
        results.append(fn(*args))
    return results


def make_transfer_a_to_b_steps(amount):
    """Transfer A→B: lock A first, then B."""

    def step_lock_a():
        acquire("A")
        return "locked_A"

    def step_lock_b_and_transfer():
        acquire("B")
        _state["A"] -= amount
        _state["B"] += amount
        release("B")
        release("A")
        return "transferred_a_to_b"

    return step_lock_a, step_lock_b_and_transfer


def make_transfer_b_to_a_steps(amount):
    """Transfer B→A: FIX — acquire locks in the same global order as A→B (A then B) to avoid deadlock."""

    # Acquire A first to match the ordering used by make_transfer_a_to_b_steps.
    def step_lock_a():
        acquire("A")
        return "locked_A"

    def step_lock_b_and_transfer():
        acquire("B")
        _state["B"] -= amount
        _state["A"] += amount
        release("B")
        release("A")
        return "transferred_b_to_a"

    return step_lock_a, step_lock_b_and_transfer


def sequential_transfers():
    """A→B then B→A. Sequential: works fine."""
    reset()
    lock_ab, do_ab = make_transfer_a_to_b_steps(10)
    lock_ba, do_ba = make_transfer_b_to_a_steps(10)
    run_steps([
        (lock_ab, ()), (do_ab, ()),
        (lock_ba, ()), (do_ba, ()),
    ])
    return get_state()


def interleaved_transfers():
    """A→B and B→A interleaved: previously DEADLOCK, now safe because both acquire A then B."""
    reset()

            (lock_ba, ()),   # B→A now also locks A (same order)
            (do_ab, ()),     # both will then acquire B in the next step without circular wait
            (do_ba, ()),     # complete transfers
        ])
        return get_state()
