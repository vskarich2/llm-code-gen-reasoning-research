## Root Cause
pipeline.process_batch/process_incremental removed the call to commit() while reducers.stage(st, processed) only sets st['pending'] and st['view'] (does not set st['stable']), causing st['stable'] to remain empty when materialize() reads it.

## Failure Mechanism
process_batch/process_incremental → call stage(st, merged) which only assigns st['pending'] and st['view'] and increments st['meta']['version'] → commit() was intentionally omitted as 'redundant' in pipeline → st['stable'] is never populated (remains empty list) and st['meta']['frozen'] remains False → materialize(st) returns items: list(st['stable']) as empty and API get_committed_total(st) returns None because meta['frozen'] is False → observable failures: materialized items are empty and 'total' is None in ingest/update flows.

## Broken Invariant
After a batch or incremental processing that intends to produce a materialized output, st['stable'] must contain the committed entries (i.e., st['stable'] == st['pending'] when the pipeline intends to commit) and st['meta']['frozen'] must be True so get_committed_total() and materialize() return meaningful values. This invariant is violated: st['stable'] remains empty after process_batch/process_incremental.

## Fix Strategy
Add an explicit commit behavior to staging when the pipeline intends to commit, without changing preview semantics. Concretely: modify reducers.stage to accept an optional parameter (do_commit=False). stage will always set st['pending'], st['view'], and increment st['meta']['version']. If do_commit is True, stage will also set st['stable'] = list(st['pending']) and st['meta']['frozen'] = True. Update pipeline.process_batch and pipeline.process_incremental to call stage(st, merged, do_commit=True) so stable is populated and frozen flag set. Keep preview using stage with do_commit=False so preview remains non-committal. This breaks the causal chain by ensuring that when the pipeline intends to commit, st['stable'] is populated immediately (materialize reads stable successfully) while preserving preview-only behavior.

def normalize(entries):
    seen = set()
    out = []
    for e in entries:
        k = e["id"]
        if k not in seen:
            seen.add(k)
            out.append(e)
    return out


def project(entries):
    return [{"id": e["id"], "label": e.get("label", ""), "val": e.get("val", 0)} for e in entries]


def collapse(entries):
    merged = {}
    for e in entries:
        k = e["id"]
        if k in merged:
            merged[k]["val"] = merged[k]["val"] + e.get("val", 0)
        else:
            merged[k] = dict(e)
    return list(merged.values())


def stage(st, processed, do_commit=False):
    """
    Stage processed entries into pending and view. If do_commit is True, also copy pending into stable and mark frozen.
    """
    st["pending"] = list(processed)
    st["view"] = project(processed)
    st["meta"]["version"] += 1
    if do_commit:
        st["stable"] = list(st["pending"])
        st["meta"]["frozen"] = True


def commit(st):
    st["stable"] = list(st["pending"])
    st["meta"]["frozen"] = True


def freeze_view(st):
    st["view"] = project(st["stable"])


def materialize(st):
    return {
        "items": list(st["stable"]),
        "display": list(st["view"]),
        "v": st["meta"]["version"],
    }


from state import make_state, copy_state
from reducers import normalize, collapse, stage, materialize, project


def process_batch(entries):
    st = make_state(entries)
    raw = st["raw"]

    # dedupe
    cleaned = normalize(raw)

    # merge values for same id
    merged = collapse(cleaned)

    # stage and commit in one step: stage will populate pending, view and also stable when do_commit=True
    stage(st, merged, do_commit=True)

def process_incremental(prev_state, new_entries):
