# Developer's Reasoning

## Root Cause
The bug is in the function is_enabled which looks up flags in the module-level dictionary FLAGS. is_enabled calls FLAGS.get(flag_name, False) without normalizing input names, but callers sometimes pass camelCase names (e.g. "darkMode") while FLAGS uses snake_case keys (e.g. "dark_mode"). Because FLAGS.get silently returns the default False for unknown keys, camelCase inputs appear disabled instead of matching the existing snake_case flag.

## Failure Mechanism
Concrete scenario: a caller calls is_enabled('darkMode'). is_enabled uses FLAGS.get('darkMode', False). Since FLAGS contains 'dark_mode' (not 'darkMode'), .get returns the default False, so the feature is reported as disabled even though FLAGS['dark_mode'] is True. Similarly, a typo like is_enabled('newDashbord') also returns False silently rather than surfacing that the flag name is unknown.

## Broken Invariant
The module claims that is_enabled(flag_name) reflects the state of a declared flag key, but currently is_enabled('X') can return False for both declared-but-true flags (when caller uses camelCase) and for genuinely absent flags. A testable invariant that is broken: for every declared key k in FLAGS, is_enabled(k) should be True exactly when FLAGS[k] is True; additionally, passing an unrecognized flag name should not silently return False. Concretely, with FLAGS['dark_mode'] == True, the call is_enabled('darkMode') should return True, but it currently returns False.

## Fix Strategy
I normalized incoming flag names to snake_case before lookup and made missing/unknown flag names raise a KeyError instead of silently returning False. Concretely, I added a helper _to_snake(name) that converts camelCase or PascalCase to snake_case, validated the input type, and updated is_enabled to (1) normalize the provided name, (2) check membership in FLAGS, returning the stored boolean when present, and (3) raise a KeyError listing available flags when absent. This fixes the mechanism by ensuring camelCase names map to the correct snake_case key and by preventing silent failures for typos or unknown flags.

```python
"""Feature flag system with snake_case keys.

This module documents that FLAGS keys are snake_case. is_enabled now accepts
camelCase or snake_case input by normalizing to snake_case before lookup and
raises a KeyError for unknown flags instead of silently returning False.
"""

import re

FLAGS = {
    "dark_mode": True,
    "beta_features": False,
    "new_dashboard": True,
    "analytics_v2": False,
}


def _to_snake(name):
    """Convert camelCase or PascalCase to snake_case.

    If the input is already snake_case it will be returned lower-cased.
    """
    if not isinstance(name, str):
        raise TypeError("flag_name must be a str")
    # Insert underscores between lower-upper and upper-lower transitions, then lowercase
    s1 = re.sub('(.)([A-Z][a-z]+)', r'\1_\2', name)
    snake = re.sub('([a-z0-9])([A-Z])', r'\1_\2', s1).replace('-', '_').lower()
    return snake


def is_enabled(flag_name):
    """Check if a feature flag is enabled.

    Args:
        flag_name: the flag key to look up. Accepts snake_case ("dark_mode") or
            camelCase/PascalCase ("darkMode", "DarkMode").

    Returns:
        True if the flag is enabled, False if the flag exists and is set to False.

    Raises:
        KeyError: if the provided flag_name does not correspond to any declared flag.
        TypeError: if flag_name is not a str.
    """
    normalized = _to_snake(flag_name)
    if normalized in FLAGS:
        return bool(FLAGS[normalized])
    # Explicit failure instead of silently returning False for unknown keys.
    available = ", ".join(sorted(FLAGS.keys()))
    raise KeyError(f"Unknown feature flag: '{flag_name}' (normalized: '{normalized}'). Available flags: {available}")


def list_flags():
    """Return all flag names (snake_case) as a list."""
    return list(FLAGS.keys())
```
