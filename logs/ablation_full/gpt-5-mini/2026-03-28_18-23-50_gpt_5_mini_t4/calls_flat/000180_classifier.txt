## Root Cause
reducers.stage only set st['pending'] and st['view'] while reducers.commit set st['stable'] and st['meta']['frozen']; reducers.freeze_view rebuilt st['view'] from st['stable']. Pipeline functions process_batch and process_incremental call stage(...) but pipeline.py had removed the calls to commit(...) and freeze_view(...). Because stage did not populate st['stable'] and the pipeline no longer invoked commit, st['stable'] remained empty and st['meta']['frozen'] remained False even after processing. Concretely: stage(st, merged) executed st['pending'] = list(processed) and st['view'] = project(processed) (reducers.py), but without commit(st) the stable list was left as [] (make_state initialized it empty), and freeze_view was unnecessary duplication.

## Failure Mechanism
When ingest() calls process_batch(entries): process_batch creates st = make_state(entries), normalizes and collapses into merged, then calls stage(st, merged). Because the pipeline had removed commit and freeze_view, st['stable'] stayed empty and st['meta']['frozen'] stayed False. materialize(st) therefore returned items: list(st['stable']) == [] while display contained the staged view. get_committed_total(st) (used by ingest) sees st['meta']['frozen'] == False and returns None. The observable effect: ingest returns no committed total and materialized.items is empty despite input entries being processed into the view. This is caused by the redundancy split between stage/commit/freeze_view and the pipeline omitting commit/freeze_view.

## Broken Invariant
After process_batch or process_incremental completes, st['stable'] must contain the committed items (the merged result) and st['meta']['frozen'] must be True, so that materialize(st)['items'] reflects the committed items and get_committed_total(st) can return the sum. The existing code violated this: stage built the view and pending but did not populate stable, while pipeline omitted commit(), so st['stable'] remained empty.

## Fix Strategy
Make the single 'stage' operation be the authoritative commit step: have reducers.stage populate st['pending'], st['stable'], and st['view'], increment version, and mark st['meta']['frozen']=True. Remove the separate commit() and freeze_view() functions (they were redundant) and remove their imports from pipeline.py. This ensures process_batch/process_incremental can call stage(...) once and the state will contain stable copies and a frozen flag, satisfying materialize() and get_committed_total() without extra pipeline steps.

def normalize(entries):
    seen = set()
    out = []
    for e in entries:
        k = e["id"]
        if k not in seen:
            seen.add(k)
            out.append(e)
    return out


def project(entries):
    return [{"id": e["id"], "label": e.get("label", ""), "val": e.get("val", 0)} for e in entries]


def collapse(entries):
    merged = {}
    for e in entries:
        k = e["id"]
        if k in merged:
            merged[k]["val"] = merged[k]["val"] + e.get("val", 0)
        else:
            merged[k] = dict(e)
    return list(merged.values())


def stage(st, processed):
    # stage now also commits: write pending, stable, view and mark frozen.
    st["pending"] = list(processed)
    st["stable"] = list(processed)
    st["view"] = project(processed)
    st["meta"]["version"] += 1
    st["meta"]["frozen"] = True


def materialize(st):
    return {
        "items": list(st["stable"]),
        "display": list(st["view"]),
        "v": st["meta"]["version"],
    }


from state import make_state, copy_state

def process_batch(entries):

    raw = st["raw"]

    # dedupe

    # merge values for same id

def process_incremental(prev_state, new_entries):
