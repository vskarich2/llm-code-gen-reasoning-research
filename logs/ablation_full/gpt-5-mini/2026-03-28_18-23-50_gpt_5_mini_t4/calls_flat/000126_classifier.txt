## Root Cause
In auth.py, the dispatch table variable _ROLE_DISPATCH is missing the 'guest' key. Although guest_access() is imported from roles.py, _ROLE_DISPATCH does not map the string 'guest' to the guest_access function, so get_access cannot select the intended handler for the 'guest' role.

## Failure Mechanism
When get_access('guest') is called, it executes handler = _ROLE_DISPATCH.get(role, _default_access). Because 'guest' is not a key in _ROLE_DISPATCH, .get() returns the default _default_access function. get_access then returns _default_access(), i.e. {'read': False, 'write': False, 'delete': False}. As a result, can_read('guest') returns False, even though roles.guest_access() would have returned {'read': True, 'write': False, 'delete': False}. The missing mapping causes the code path to fall through to the no-access default instead of invoking guest_access.

## Fix Strategy

This directly changes the dispatch lookup result for role == 'guest' (the single-line modification in _ROLE_DISPATCH), ensuring the returned dict matches roles.guest_access().

"""Authentication and authorization dispatch."""

from roles import admin_access, user_access, moderator_access, guest_access


# Dispatch table mapping roles to access handlers
_ROLE_DISPATCH = {
    "admin": admin_access,
    "user": user_access,
    "moderator": moderator_access,
    "guest": guest_access,
}


def _default_access():
    """Default: no access for unknown roles."""
    return {"read": False, "write": False, "delete": False}


def get_access(role):
    """Return the access dict for a given role."""
    handler = _ROLE_DISPATCH.get(role, _default_access)
    return handler()


def can_read(role):
    """Check if role has read access."""
    return get_access(role).get("read", False)
