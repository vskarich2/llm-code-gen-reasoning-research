# Developer's Reasoning

## Root Cause
In make_withdraw_steps the closure-local variable result['approved'] is set by step_check using check_balance(name, amount) but step_act blindly calls do_withdraw(name, amount) if result['approved'] is True. Concretely, step_check writes result['approved'] based on the current _accounts balance, and step_act uses that stale flag without revalidating the current _accounts state before calling do_withdraw.

## Failure Mechanism
Starting state: create_account('alice', 100). Two withdrawal step pairs are created with amount=80. The interleaved run_steps call in interleaved_withdrawals executes (check_a,()), (check_b,()), (act_a,()), (act_b,()). check_a sets result['approved']=True because _accounts['alice']==100 >= 80. check_b also sets its own result['approved']=True for the same reason. act_a sees its result['approved']==True and calls do_withdraw('alice', 80), reducing balance to 20. act_b then sees its result['approved']==True (set earlier) and calls do_withdraw('alice', 80) again, reducing balance to -60. The root cause is that step_act used the previously set result['approved'] flag without re-checking _accounts, so two approvals based on the same snapshot both led to debits.

## Broken Invariant
do_withdraw(name, amount) is invoked only when _accounts[name] >= amount. Equivalently, for any account the public operations must never cause get_balance(name) to become negative (e.g., after running interleaved_withdrawals(), get_balance('alice') must be >= 0).

## Fix Strategy
I changed step_act inside make_withdraw_steps to re-check the current balance with check_balance(name, amount) immediately before calling do_withdraw. The code now clears result['approved'] if the re-check fails and only calls do_withdraw when check_balance returns True. This prevents an act from using a stale approval produced earlier by step_check: in the interleaved scenario the first act will subtract 80 (leaving 20) and the second act will re-check, see insufficient funds, and not call do_withdraw, so balance cannot go negative.

_accounts = {}


def reset():
    _accounts.clear()


def create_account(name, balance):
    _accounts[name] = balance


def get_balance(name):
    return _accounts.get(name, 0)


def check_balance(name, amount):
    """CHECK: is balance sufficient?"""
    return _accounts.get(name, 0) >= amount


def do_withdraw(name, amount):
    """ACT: decrement balance. Assumes caller verified."""
    _accounts[name] = _accounts.get(name, 0) - amount


def run_steps(steps):
    results = []
    for fn, args in steps:
        results.append(fn(*args))
    return results


def make_withdraw_steps(name, amount):
    """Split withdrawal into separate check and act steps.

    BUG: under interleaving, both checks pass before either debits.
    """
    result = {"approved": False}

    def step_check():
        result["approved"] = check_balance(name, amount)
        return ("check", result["approved"])

    def step_act():
        # Re-validate the current balance immediately before acting.
        # Only call do_withdraw if the balance is still sufficient.
        if result["approved"]:
            if check_balance(name, amount):
                do_withdraw(name, amount)
            else:
                # approval is stale; clear it to reflect actual outcome
                result["approved"] = False
        return ("act", result["approved"])

    return step_check, step_act


def sequential_withdrawals():
    """Two withdrawals of 80 from balance=100. Sequential: second denied."""
