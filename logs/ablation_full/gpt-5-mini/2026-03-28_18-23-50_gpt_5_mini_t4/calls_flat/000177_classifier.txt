# Developer's Reasoning

## Root Cause
In code_snippets_v2/silent_default_c/flags.py the environment lookup is broken in two ways: (1) the _ENV_KEY_MAP entry for the 'dark_mode' flag uses the wrong env var name 'FEATURE_DARKMODE' instead of the actual env var key 'FEATURE_DARK_MODE', so get_env/get_env_bool never see the real env var; (2) is_enabled() only treats an environment value as an override when get_env_bool(env_key) is truthy (True), so an explicit env=false is ignored and the lookup falls through to config or hardcoded values.

## Failure Mechanism
When the environment sets FEATURE_DARK_MODE='false' but the config file has dark_mode=True, flags.is_enabled('dark_mode') should return False (env overrides). Instead, because _ENV_KEY_MAP maps 'dark_mode' -> 'FEATURE_DARKMODE', get_env('FEATURE_DARKMODE') returns None and the env layer is never detected; even if the mapping were correct, is_enabled() currently only returns early when get_env_bool(...) is truthy, so an explicit 'false' value would not be returned and the code falls back to config.get_config_bool('dark_mode'), which yields True from the file config. The net effect is that an env var intended to disable the feature is ignored and the feature remains enabled.

## Broken Invariant
For any flag_name and its corresponding environment variable key, if the environment variable exists (i.e., env.get_env(env_key) is not None), then is_enabled(flag_name) must return the boolean value derived from that environment variable and must not consult config or hardcoded defaults.

## Fix Strategy
Correct the env var name mapping for 'dark_mode' and change is_enabled() to detect the presence of the env var via get_env(env_key) and, if present, return get_env_bool(env_key) (so both true and false env values override lower-priority layers). Also check presence of the config value via config.get_config(flag_name) before calling get_config_bool, so we only use config when a value exists there. These changes ensure the env layer properly overrides config/hardcoded values in both True and False cases.

```python
Lookup order:
  1. Environment variable (via env.get_env_bool)
  2. Config file (via config.get_config_bool)
  3. Hardcoded defaults
"""

from env import get_env_bool
from config import get_config_bool


HARDCODED_DEFAULTS = {
    "dark_mode": False,
    "beta": False,
    "analytics": False,
}

# Maps flag names to their env var keys
_ENV_KEY_MAP = {
    "dark_mode": "FEATURE_DARK_MODE",
    "beta": "FEATURE_BETA",
    "analytics": "FEATURE_ANALYTICS",
}


def is_enabled(flag_name):
    """Check if a feature flag is enabled.

    Checks env first, then config, then hardcoded defaults.
    """
    env_key = _ENV_KEY_MAP.get(flag_name)
    if env_key:
        from env import get_env
        # If the env var exists (even if it's "false"), it should override lower layers.
        if get_env(env_key) is not None:
            return get_env_bool(env_key)

    from config import get_config
    # Only use config if a value is present there.
    if get_config(flag_name) is not None:
        return get_config_bool(flag_name)

    return HARDCODED_DEFAULTS.get(flag_name, False)


def get_flag_source(flag_name):
    """Return which layer provides the flag value (for debugging)."""
    env_key = _ENV_KEY_MAP.get(flag_name)
    if env_key:
        from env import get_env
        if get_env(env_key) is not None:
            return "env"

    from config import get_config
    if get_config(flag_name) is not None:
        return "config"

    return "hardcoded"

```
