# Developer's Reasoning

## Root Cause
config.create_config returns the module-level DEFAULTS dictionary object itself (config = DEFAULTS) instead of a fresh copy. ConfigMiddleware.__init__ stores that returned object in self._base, and ConfigMiddleware.apply_config mutates self._base via cfg.update(request_overrides), so the same DEFAULTS-backed dict is shared and mutated across requests.

## Failure Mechanism
When handle_debug_request() calls handle_request({'debug': True}), ConfigMiddleware.apply_config updates the cached self._base dict to set 'debug': True. Because create_config returned (and middleware cached) the original DEFAULTS dict reference, that mutation persists. A subsequent call to handle_request() without overrides will see debug=True even though no override was passed, leaking per-request overrides into later requests.

## Broken Invariant
create_config() must return an independent configuration dictionary for each caller (i.e., callers must not receive a reference to a mutable module-level DEFAULTS). Additionally, ConfigMiddleware.apply_config(request_overrides) must not mutate the cached base configuration (self._base). A failing test would be: call handle_request({'debug': True}) then call handle_request() and assert the second call's 'debug' is False — currently that test fails.

## Fix Strategy
Return a shallow copy from create_config() (dict(DEFAULTS)) so callers get a separate object. In middleware.apply_config, copy the cached base (cfg = dict(self._base)) before applying request_overrides, so updates don't mutate the cached base. These changes ensure per-request overrides are applied to a fresh dict and do not leak into subsequent requests.

class ConfigMiddleware:

    def __init__(self):

        """Return config for this request, applying any overrides.

        cfg = dict(self._base)
