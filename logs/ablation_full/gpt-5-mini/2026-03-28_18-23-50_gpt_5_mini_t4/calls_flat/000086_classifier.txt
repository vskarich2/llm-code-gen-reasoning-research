## Root Cause
In retry_send (file sender.py) the conditional is inverted: the code uses 'if not result: continue' after calling send(msg). Because send returns True on success, the loop does not break on a successful send and instead proceeds to subsequent iterations, causing send to be called multiple times when the first attempt succeeds.

## Failure Mechanism
Concrete scenario: reset() is called, then retry_send('m', max_retries=3). On attempt 0 send('m') returns True and appends 'm' to _sent. The condition 'if not result: continue' is false, so the loop does not exit; attempt 1 runs and calls send('m') again, appending another 'm', then attempt 2 repeats once more. The final _sent becomes ['m', 'm', 'm'] even though the first send succeeded, demonstrating duplicate sends instead of stopping after success.

## Broken Invariant
If send(msg) returns True on the first attempt, retry_send(msg, max_retries=N) must call send exactly once and return True. This is testable: after reset(); retry_send('x', max_retries=3); get_sent() should equal ['x'] and retry_send should return True. The current implementation violates this invariant.

## Fix Strategy
I changed retry_send to stop retrying as soon as send returns True by returning True immediately when success is observed. If all attempts fail, the function now returns False. I also clarified the loop to iterate attempts in a 1..max_retries range and renamed the result variable to 'success' for readability. Additionally, I implemented clear_log() to actually clear the internal _sent list. These changes ensure a successful send is not repeated and restore the documented behavior.

    """Send with retry.
