# Developer's Reasoning

## Root Cause
In catalog.update_product the function calls invalidate_shared(product_id) but does not call invalidate_local(product_id). Because API.get_product first checks the local cache via get_local(product_id), a stale value can remain in _local after update_product modifies _db. The missing call to invalidate_local(product_id) in update_product is the direct cause of stale data being returned.

## Failure Mechanism
Example sequence: add_product(42, 'Widget', 10) populates the DB. A client calls get_product(42): api.get_product calls get_local(42) -> miss, then get_shared(42) -> miss, then db_get(42) -> returns {'name':'Widget','price':10}, api.put_shared(42, ...) and put_local(42, ...) store that value in _shared and _local. Later update_product(42, price=12) runs: it updates _db[42]['price'] to 12 and calls invalidate_shared(42) but does not call invalidate_local(42). The local cache _local[42] still holds the old {'name':'Widget','price':10}. A subsequent call to api.get_product(42) will return get_local(42) -> the stale old dict, so the client sees price 10 instead of the updated 12. The chain of functions involved is: catalog.update_product updates _db but omits invalidate_local, cache.get_local still returns the stale entry, and api.get_product returns it without consulting DB.

## Broken Invariant
After calling update_product(product_id, ...), all cache layers must be invalidated for that product_id such that a subsequent get_product(product_id) returns data equal to db_get(product_id). Specifically: for any product_id present in _db, calling update_product(product_id, **fields) must cause get_local(product_id) to return None (so the API cannot return stale local data).

## Fix Strategy
Call invalidate_local(product_id) inside update_product immediately after updating the DB (in addition to the existing invalidate_shared call). This ensures _local no longer holds the old value so api.get_product will miss the local cache and either fetch from shared (if populated) or from db_get, thereby returning the updated data. Only catalog.py is changed to add the missing invalidation; cache.py and api.py remain unchanged.

"""Product catalog with two-layer cache integration."""

from cache import put_local, put_shared, invalidate_shared, invalidate_local

_db = {}


def add_product(product_id, name, price):
    """Add product to database."""
    _db[product_id] = {"name": name, "price": price}


def db_get(product_id):
    """Raw DB lookup."""
    p = _db.get(product_id)
    return dict(p) if p else None


def update_product(product_id, **fields):
    """Update product in DB and invalidate caches.

    Invariant: after update, all cache layers must be invalidated.
    """
    if product_id not in _db:
        return False
    _db[product_id].update(fields)
    invalidate_shared(product_id)
    invalidate_local(product_id)
    return True


def reset():
    """Clear DB."""
    _db.clear()
