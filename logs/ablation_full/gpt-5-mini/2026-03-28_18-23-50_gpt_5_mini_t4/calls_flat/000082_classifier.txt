The bug is in pipeline.find_best: the local variable best is only assigned inside the for-loop when a record exceeds threshold, but when no record meets the threshold the code takes the else branch and sets best = _last_best. Because _last_best can contain a value from a prior call, find_best returns stale data instead of None. Concretely, the causal chain is: find_best iterates valid (from load_and_validate), never sets best if no rec has rec['value'] > threshold, then else: best = _last_best causes a previous successful result to be reused.

## Failure Mechanism

This manifests as returning stale data when no current record qualifies.

This enforces the contract that find_best returns None when no current record qualifies and prevents reuse of a prior _last_best.
