# Developer's Reasoning

## Root Cause
cache_writer.refresh_user_snapshot uses cache_put_if_absent on _store (operation: cache_put_if_absent -> _store[f"user:{user['id']}"] not overwritten), causing updates to be ignored when a cached entry already exists.

## Failure Mechanism
rename_user(user_id, new_name) → user_repo.db.update_name mutates DB row → lookup_user returns updated user object → refresh_user_snapshot(user) calls cache_put_if_absent which checks _store and DOES NOT overwrite existing entry → _store keeps the old display name → cache_reader.get_display_name(user_id) returns stale name → callers observe stale display name after a rename.

## Broken Invariant
After updating a user's name in the DB via rename_user(user_id, new_name), the cache must reflect the new name: cache_reader.get_display_name(user_id) == new_name. This property is violated because refresh_user_snapshot uses a put-if-absent behavior.

## Fix Strategy
Replace the two small helpers (refresh_user_snapshot and sync_user_to_cache) with a single consolidated function sync_user_to_cache(user, force=False) in cache_writer.py. The consolidated function will call cache_put(user_key, name) when force=True, and cache_put_if_absent(...) when force=False. Update all callers: replace calls to refresh_user_snapshot with sync_user_to_cache; keep default behavior (force=False) for save_user and bulk_warm_cache to preserve warm-only semantics, but use force=True in rename_user so cache is overwritten after a DB rename. This breaks the causal chain by ensuring rename_user will explicitly overwrite the existing cached name instead of being ignored by the put-if-absent operation.
