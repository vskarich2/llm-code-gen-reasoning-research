# Developer's Reasoning

## Root Cause
There were two separate cache helper functions in cache_writer.py: refresh_user_snapshot (which calls cache_put_if_absent) and sync_user_to_cache (which calls cache_put). This duplication caused callers to import and use the wrong variant depending on context. In particular, user_service.rename_user calls refresh_user_snapshot(updated) which uses cache_put_if_absent and therefore deliberately avoids overwriting an existing cache entry.

## Failure Mechanism
Because rename_user uses refresh_user_snapshot (cache_put_if_absent), renaming a user in the DB does not update the cached display name when an entry for that user already exists. Example: save_user inserts the user and calls refresh_user_snapshot, creating a cached name 'Alice'. Later rename_user updates the DB to 'Alicia' but calls refresh_user_snapshot again, which leaves the cache as 'Alice' because cache_put_if_absent does not overwrite; get_display_name(user_id) continues to return 'Alice' while the DB contains 'Alicia'.

## Broken Invariant
After a successful rename_user(user_id, new_name), the cache key 'user:{user_id}' must equal the DB's current name for that user (i.e., cache_reader.get_display_name(user_id) == user_repo.lookup_user(user_id)['name']). The original code violated this because rename_user used the non-overwriting refresh_user_snapshot.

## Fix Strategy
I removed the duplicate refresh_user_snapshot and consolidated both behaviors into a single function sync_user_to_cache(user, replace=False) in cache_writer.py. The function performs a put-if-absent when replace is False (preserving the original refresh_user_snapshot behavior) and an unconditional put when replace is True (preserving the original sync_user_to_cache behavior). I updated all callers in user_service.py: save_user and bulk_warm_cache call sync_user_to_cache(...) with the default replace=False to keep put-if-absent behavior, and rename_user calls sync_user_to_cache(updated, replace=True) so the cache is updated on name changes. This guarantees the cache is overwritten on rename while preserving prior semantics elsewhere.
