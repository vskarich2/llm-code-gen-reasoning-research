## Root Cause
process() checks the module-level flag _initialized and unconditionally logs an error and returns without storing the item when _initialized is False (operation: _log.append('error:not_init:{item}') and return False). This causes items to be dropped when process() is invoked before init().

## Failure Mechanism
Caller calls process('a') → process() sees _initialized == False → process() performs _log.append(f"error:not_init:{item}") and returns False (mutation: no storage of 'a' into any buffer) → later init() runs but there is no record of 'a' to recover (propagation: missing item) → observable failure: missing 'processed:a' entry in _log (item lost).

## Broken Invariant
For any sequence of calls where init() is invoked at least once before shutdown(), every call process(item) made before shutdown() must produce a corresponding 'processed:{item}' entry in _log by the time shutdown() is called. This invariant is violated when process() is called before init().

## Fix Strategy
When process(item) is called while _initialized is False, enqueue the item into a module-level FIFO buffer (_buffer) instead of logging an error and dropping it. When init() is called, set _initialized True, append 'init' to _log, then drain _buffer in FIFO order and process each buffered item (append 'processed:{item}' to _log). This breaks the causal chain by preventing the early-return/drop in process(): items are retained and later processed once initialization occurs.
