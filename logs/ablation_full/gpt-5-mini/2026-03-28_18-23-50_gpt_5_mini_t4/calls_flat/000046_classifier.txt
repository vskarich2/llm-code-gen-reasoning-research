# Developer's Reasoning

## Root Cause
In client.py the module-level variable _client_cfg is assigned once at import time by calling get_config(). That binds client._client_cfg to the single dict instance returned by config.get_config(). Later, config.reset_config() in config.py sets the module's _config to None and causes get_config() to create and return a new dict on the next call, but client._client_cfg continues to reference the old dict. The specific variables/functions: client._client_cfg (stale reference) and config.reset_config (which replaces config._config) are the causal pair.

## Failure Mechanism
Concrete sequence: (1) When client.py is imported it executes _client_cfg = get_config() and _client_cfg becomes the original dict {'api_key': 'default-key', 'base_url': 'https://api.example.com'}. (2) Code calls handler.make_request('ping') which uses client.get_api_key()/get_base_url() and returns values from the old _client_cfg. (3) Later code calls config.reset_config() which sets config._config = None, and then calls config.set_config('api_key', 'rotated-key') which creates a new dict via get_config() and mutates that new dict. (4) Because client._client_cfg still points to the original dict, subsequent handler.make_request('ping') continues to return 'default-key' even though config.get_config() now holds {'api_key': 'rotated-key'}. The stale reference in client._client_cfg prevents config resets and reloads from propagating to the client/handler.

## Broken Invariant
Invariant: handler.make_request(endpoint) must reflect the current configuration produced by config.get_config(); e.g., after calling config.reset_config() followed by config.set_config('api_key','new-key'), handler.make_request('x')['api_key'] == 'new-key'. This is testable and currently violated because client.get_api_key() reads a stale _client_cfg captured at import time.

## Fix Strategy
Remove the import-time capture of the config dict in client.py. Instead of storing _client_cfg = get_config() at module import, have client getters call get_config() each time they need a value. This ensures that after config.reset_config() creates a new dict, subsequent calls to client.get_api_key()/get_base_url() obtain the current dict from config.get_config(). The change is implemented by deleting the module-level _client_cfg and making get_api_key() and get_base_url() call get_config() directly.
