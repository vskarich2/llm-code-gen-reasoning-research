Concretely, the mismatch is in the add_entry implementation where _labels.insert(position, label) is paired with _values.append(value), causing label and value arrays to diverge when position is provided.

## Failure Mechanism

A subsequent get_entry(1) returns ('c', 2) rather than the expected ('c', 3). The misalignment arises because the label was inserted at index 1 while the value was appended to the end, so index-based access methods (get_entry, get_all) return incorrect label/value pairings.

The bug violates this invariant for any insertion with a non-None position (i.e., adds where position is used).

## Fix Strategy

This ensures the parallel lists remain aligned. The change is minimal and preserves existing behavior for the append case (position is None).

_values = []


def add_entry(label, value, position=None):
    """Add an entry to the report.

    """

        _values.insert(position, value)
    else:
        _labels.append(label)
        _values.append(value)
