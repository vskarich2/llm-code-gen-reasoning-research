# Developer's Reasoning

## Root Cause
The bug is in limiter.should_allow: the return expression uses 'not expired and under_limit or exempt' which relies on Python operator precedence. Because 'and' binds tighter than 'or', a True value for 'exempt' can make the whole expression True even when 'expired' is True. In other words, the variables 'expired' and 'exempt' are combined incorrectly in a single expression, so an expired token can still be allowed if is_exempt(client_id, exempt_list) is True.

## Failure Mechanism
Concretely, when is_expired(timestamp, now, window_seconds) returns True and is_exempt(client_id, exempt_list) returns True, the current code evaluates the return as: (not expired and under_limit) or exempt -> (False and under_limit) or True -> False or True -> True. That causes should_allow to return True for an expired token for exempt clients. For example, if expired=True, under_limit=False, exempt=True, the function incorrectly allows the request instead of rejecting it.

## Broken Invariant
If is_expired(timestamp, now, window_seconds) is True, then should_allow(...) must always return False regardless of is_exempt(client_id, exempt_list) or is_under_limit(count, limit). This invariant is violated by the current implementation where an exempt client can be allowed despite an expired token.

## Fix Strategy
I replaced the single boolean expression with an explicit evaluation order: first check expired and immediately return False if expired (so expired tokens are always rejected), then check exempt and return True if exempt, otherwise return the under_limit result. This removes reliance on operator precedence and enforces the invariant that expired tokens are always rejected while exempt clients still bypass rate limits when not expired.

```python
"""Core rate limiter logic."""

from policy import is_expired, is_under_limit, is_exempt


def should_allow(client_id, count, limit, timestamp, now,
                 window_seconds, exempt_list):
    """Decide whether to allow a request.

    Allow if:
      - token is not expired AND (under limit OR exempt)

    Exempt clients bypass the rate limit even if over it,
    but expired tokens are always rejected.
    """
    expired = is_expired(timestamp, now, window_seconds)
    # If the token is expired, always reject regardless of exempt status.
    if expired:
        return False

    # If not expired, exempt clients bypass the limit.
    exempt = is_exempt(client_id, exempt_list)
    if exempt:
        return True

    # Otherwise allow only if under the configured limit.
    under_limit = is_under_limit(count, limit)
    return under_limit

```
