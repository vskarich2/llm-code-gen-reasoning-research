## Root Cause
api.checkout: the parameter 'use_new_pricing' is accepted by checkout but is not passed into the call invoice = create_invoice(customer, items). This omission (the call site operation) causes the explicit flag to be unused, so downstream functions compute_price and get_pricing_version rely solely on flags.is_enabled('new_pricing').

## Failure Mechanism
caller → calls checkout(customer, items, use_new_pricing=True) → checkout ignores the use_new_pricing parameter and calls create_invoice(customer, items) without the flag → create_invoice calls compute_price(item['base'], item['qty']) and get_pricing_version() which call flags.is_enabled('new_pricing') → global flag (False) is used instead of the caller intent → invoice lines, total and pricing_version reflect global flag rather than the requested use_new_pricing=True → observable failure: invoice shows v1 pricing and un-discounted totals despite the caller requesting v2.

## Broken Invariant
For any explicit argument use_new_pricing in checkout(..., use_new_pricing=X where X is True or False), the produced invoice must have invoice['pricing_version'] == ('v2' if X else 'v1') and line amounts must use the matching pricing formula. This property is currently violated when checkout receives use_new_pricing but does not propagate it.

## Fix Strategy
Propagate the caller's intent explicitly through the call chain instead of relying on global state. Changes to implement: (1) Make compute_price and get_pricing_version accept an optional use_new_pricing parameter (default None). If use_new_pricing is None they fall back to flags.is_enabled('new_pricing'); otherwise they use the provided boolean. (2) Update billing.create_invoice to accept a use_new_pricing parameter (default None) and pass it through to compute_price and get_pricing_version. (3) Update api.checkout to forward its use_new_pricing parameter to create_invoice. This breaks the causal chain because the explicit caller-provided value no longer gets dropped; when a caller passes True or False the computation uses that value to select pricing behavior rather than the global flags state. Default behavior (when use_new_pricing is None) still falls back to global flags, preserving backward compatibility when the flag is omitted.

from flags import is_enabled


def compute_price(base, qty, use_new_pricing=None):
    """Compute price using v2 pricing when use_new_pricing is True.

    If use_new_pricing is None, fall back to the global feature flag.
    """
    if use_new_pricing is None:
        enabled = is_enabled("new_pricing")
    else:
        enabled = use_new_pricing

    if enabled:
        return _v2_price(base, qty)
    return _v1_price(base, qty)


def _v1_price(base, qty):
    return base * qty


def _v2_price(base, qty):
    discount = 0.1 if qty >= 10 else 0
    return base * qty * (1 - discount)


def get_pricing_version(use_new_pricing=None):
    if use_new_pricing is None:
        enabled = is_enabled("new_pricing")
    else:
        enabled = use_new_pricing
    return "v2" if enabled else "v1"


from pricing import compute_price, get_pricing_version
from flags import is_enabled

_invoices = []


def create_invoice(customer, items, use_new_pricing=None):
    """Create invoice for customer using optional use_new_pricing override.

    If use_new_pricing is None, pricing functions will consult the global flag.
    """
    total = 0
    lines = []
    for item in items:
        price = compute_price(item["base"], item["qty"], use_new_pricing=use_new_pricing)
        lines.append({"sku": item["sku"], "amount": price})
        total += price

    invoice = {
        "customer": customer,
        "lines": lines,
        "total": total,
        "pricing_version": get_pricing_version(use_new_pricing=use_new_pricing),
    }

    if is_enabled("audit_mode"):
        invoice["reasoning_evaluator_audit"] = True
        _invoices.append(invoice)

    return invoice
