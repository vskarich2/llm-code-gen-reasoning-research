# Developer's Reasoning

## Root Cause
_default_host is assigned once at module import from _settings (line: _default_host = _settings["host"]) and get_host() returns that captured variable. Because get_host() reads _default_host instead of the live _settings dict, subsequent calls to configure() or reset_settings() that modify _settings do not affect the value returned by get_host().

## Failure Mechanism
Sequence demonstrating the bug: 1) Module is imported and _default_host is set to "localhost" from the initial _settings. 2) configure(host="example.com") is called, which updates _settings["host"] to "example.com". 3) get_host() is called and returns the stale _default_host value "localhost" (not "example.com") because _default_host was captured at import time and never updated.

## Broken Invariant
After calling configure(host=<new_host>), get_host() must return <new_host>. Concretely, calling configure(host='example.com') followed by get_host() should return 'example.com', but with the original code it returns 'localhost'.

## Fix Strategy
I removed the eagerly captured module-level _default_host and introduced a DEFAULT_SETTINGS constant. get_host() now reads the current host from the live _settings dict, and reset_settings() reinitializes _settings from DEFAULT_SETTINGS. This ensures configure() mutations of _settings are observed by get_host(), restoring the invariant that get_host() reflects the latest configured host.

    """Return the current host setting."""

    """Return the current settings dict."""
    return dict(_settings)


def reset_settings():
    """Reset settings to default values (e.g., for testing)."""
    global _settings
    _settings = dict(DEFAULT_SETTINGS)


def configure(host=None, port=None, debug=None):
    """Update settings."""
    if host is not None:

    if port is not None:
