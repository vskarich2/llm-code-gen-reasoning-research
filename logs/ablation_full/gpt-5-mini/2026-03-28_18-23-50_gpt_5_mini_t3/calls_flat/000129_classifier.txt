## Root Cause
In auth.authorize the role variable (ctx['role']) is matched only against 'admin', 'moderator', 'user', and 'guest'. There is no branch for 'service_account', so a request where middleware.authenticate sets ctx['role'] == 'service_account' falls through to the final else and is denied.

## Failure Mechanism
When middleware.authenticate(request) returns {'role': 'service_account', 'allowed': True, ...} (middleware recognizes service_account and marks it allowed), authorize(request) executes its if/elif chain comparing role to string literals. Because 'service_account' is not one of the handled strings, authorize hits the final else and returns {'can_read': False, 'can_write': False, 'can_admin': False'}. In concrete terms: service account requests that middleware marks allowed are rejected by authorize due to the missing branch.

## Broken Invariant
If authenticate(request) returns a context with 'allowed': True for a recognized role R, then authorize(request) must grant the permissions appropriate for R. Specifically, for request with role == 'service_account' authenticate yields allowed == True, and authorize must return can_read == True, can_write == True, and can_admin == True. Currently that invariant is violated because authorize returns all-false for 'service_account'.

## Fix Strategy
Replace the brittle string-only branching in authorize with logic based on get_role_level(role). The change uses numeric role levels (from roles.get_role_level) and threshold checks (level >= 100, >= 80, >= 60, >= 40, >= 10) so that 'service_account' (level 80) is handled by the >=80 branch and receives the correct permissions. This ensures service_account requests that middleware marked allowed are no longer denied; using the numeric levels also preserves the original permission mapping for admin, moderator, user, and guest.

```python
"""Authorization handler: decides what a role can do."""

from middleware import authenticate
from roles import get_role_level


def authorize(request):
    """Authorize a request by checking middleware + handler logic.

    Returns dict with 'can_read', 'can_write', 'can_admin'.
    """
    ctx = authenticate(request)
    if not ctx.get("allowed"):
        return {"can_read": False, "can_write": False, "can_admin": False}

    role = ctx["role"]
    level = get_role_level(role)

    # Use numeric role levels to cover all known roles, including service_account.
    if level >= 100:
        return {"can_read": True, "can_write": True, "can_admin": True}
    elif level >= 80:
        # service_account: elevated but below admin -> full access here
        return {"can_read": True, "can_write": True, "can_admin": True}
    elif level >= 60:
        return {"can_read": True, "can_write": False, "can_admin": True}
    elif level >= 40:
        return {"can_read": True, "can_write": True, "can_admin": False}
    elif level >= 10:
        return {"can_read": True, "can_write": False, "can_admin": False}
    else:
        # Unknown/zero-level role — no access
        return {"can_read": False, "can_write": False, "can_admin": False}


def get_authorization_summary(request):
    """Return a human-readable summary of authorization."""
    result = authorize(request)
    perms = [k for k, v in result.items() if v]
    return {"role": request.get("role"), "permissions": perms}

```
