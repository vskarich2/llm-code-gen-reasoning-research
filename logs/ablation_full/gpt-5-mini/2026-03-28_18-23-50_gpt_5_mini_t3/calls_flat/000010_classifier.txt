## Root Cause
In config.create_config (config.py) the code assigns config = DEFAULTS and returns that object. Because DEFAULTS is a module-level dict, callers who update the returned dict (for example middleware.ConfigMiddleware.apply_config) end up mutating DEFAULTS itself. The specific variables are config (local) and DEFAULTS (module-level); the causal relationship is that returning the DEFAULTS reference allows later .update() calls to change the module-global DEFAULTS.

## Failure Mechanism
Sequence that demonstrates the bug: ConfigMiddleware.__init__ calls create_config(), which returned DEFAULTS by reference, so self._base points at DEFAULTS. When handler.handle_request({'debug': True}) calls mw.apply_config({'debug': True}), apply_config sets cfg = self._base (no copy) and then cfg.update(request_overrides), which mutates self._base and thus DEFAULTS. On the next request handle_request() (no overrides), the returned config still has 'debug': True because DEFAULTS was mutated. Concretely: create_config -> returns DEFAULTS reference -> middleware._base points to DEFAULTS -> apply_config uses that same reference and update() mutates it -> subsequent requests observe the mutated value.

## Broken Invariant
create_config must return a fresh, independent dict so that modifying the returned dict does not change the module-global DEFAULTS. Testable assertions that fail under the bug: (1) after create_config({'debug': True}), DEFAULTS['debug'] must still be False; (2) after handle_request({'debug': True}), a subsequent handle_request() call without overrides must return debug == False. Both assumptions were violated because create_config returned the DEFAULTS reference and apply_config mutated it.

## Fix Strategy
Return independent copies instead of references. create_config now returns dict(DEFAULTS) so callers get a fresh dict and can't mutate DEFAULTS. Additionally, apply_config now makes a copy of the cached base (cfg = dict(self._base)) before applying request_overrides, so per-request updates do not mutate the middleware's cached base. These two changes prevent mutations from leaking into DEFAULTS or the cached base.
