# Developer's Reasoning

## Root Cause
In create_config(), the line `config = DEFAULTS` returns a direct reference to the module-level dictionary DEFAULTS instead of a fresh mapping. Because create_config returns that same object, subsequent updates to the returned mapping mutate DEFAULTS itself.

## Failure Mechanism
Concrete sequence: (1) create_config() executes `config = DEFAULTS` and returns that object. (2) Caller mutates the returned dict, e.g. `cfg = create_config(); cfg['timeout'] = 10`. Because cfg is DEFAULTS, DEFAULTS['timeout'] becomes 10. (3) The original reset_defaults() tried to restore defaults by reassigning the module name (`DEFAULTS = { ... }`), which creates a new dict object; any previously returned references (like cfg) continue to point at the mutated old dict and are not restored. The two code locations involved are the `config = DEFAULTS` line in create_config and the `DEFAULTS = {...}` rebinding in reset_defaults.

## Broken Invariant
For any call result = create_config(), the returned mapping must be independent of the module DEFAULTS mapping: id(result) != id(DEFAULTS) and mutations to result must not change DEFAULTS. This is violated by the current implementation because create_config returns DEFAULTS itself.

## Fix Strategy
create_config now returns a shallow copy of DEFAULTS (DEFAULTS.copy()) so callers receive an independent dict and cannot mutate the module-level defaults. reset_defaults no longer rebinds the name DEFAULTS; instead it restores DEFAULTS in-place via DEFAULTS.clear() and DEFAULTS.update(_FACTORY_DEFAULTS). An immutable snapshot _FACTORY_DEFAULTS is kept to know the original values. These changes ensure returned configs are independent (preventing unintended mutation of DEFAULTS) and ensure reset_defaults restores the module-level mapping for any existing references to DEFAULTS.

# The canonical, mutable defaults mapping used by create_config() as a base.
DEFAULTS: Dict[str, Any] = {"timeout": 30, "retries": 3, "debug": False}

# Immutable snapshot of the original factory defaults so we can restore them.
_FACTORY_DEFAULTS = DEFAULTS.copy()


def create_config(overrides: Optional[Dict[str, Any]] = None) -> Dict[str, Any]:
    """Return a NEW config dict based on DEFAULTS, with optional overrides.

    Important: Returns a shallow copy so callers may mutate the returned
    mapping without affecting the module-level DEFAULTS object.
    """
    config = DEFAULTS.copy()
    if overrides:
        config.update(overrides)
    return config


def reset_defaults() -> None:
    """Restore DEFAULTS to the original factory values in-place.

    This mutates the existing DEFAULTS dict object (clearing and updating it)
    so that any existing references to DEFAULTS keep seeing the restored
    values. Do not rebind the module-level name DEFAULTS, because that would
    leave external references pointing to the old object.
    """
    DEFAULTS.clear()
    DEFAULTS.update(_FACTORY_DEFAULTS)
