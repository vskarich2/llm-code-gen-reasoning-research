# Developer's Reasoning

## Root Cause
In code_snippets_v2/silent_default_c/flags.py the _ENV_KEY_MAP entry for the 'dark_mode' flag is wrong: it maps 'dark_mode' to 'FEATURE_DARKMODE' while the env layer defines 'FEATURE_DARK_MODE'. Additionally, is_enabled(flag_name) calls get_env_bool(env_key) and treats a False return value as 'no env override' (it only returns when env_val is truthy). Because get_env_bool returns the default False when the env var is missing, is_enabled cannot distinguish between "env present and false" and "env absent", so explicit false env values are ignored.

## Failure Mechanism
Example: _ENV contains 'FEATURE_DARK_MODE': 'false' but _ENV_KEY_MAP maps 'dark_mode' -> 'FEATURE_DARKMODE'. In is_enabled('dark_mode'): env_key becomes 'FEATURE_DARKMODE', get_env_bool('FEATURE_DARKMODE') returns False (because the key is missing, get_env() returns None then get_env_bool returns its default False). The code only returns early when env_val is truthy, so it proceeds to read the config value. config._FILE_CONFIG sets 'dark_mode': True, so is_enabled returns True even though the environment explicitly set FEATURE_DARK_MODE=false. Thus a concrete env override (false) is ignored because of the wrong mapping and because is_enabled treats False as "no env override."

## Broken Invariant
For any flag_name that has a mapped environment variable in _ENV_KEY_MAP, if that environment variable is present in env._ENV then is_enabled(flag_name) must return the boolean value represented by that environment variable. Currently, is_enabled does not satisfy this: an env var present and set to 'false' may be ignored and a lower-priority layer used instead.

## Fix Strategy
I corrected the env var name in _ENV_KEY_MAP for 'dark_mode' to 'FEATURE_DARK_MODE' so the env lookup accesses the actual env var. I also changed is_enabled to detect env presence by calling get_env(env_key) (so presence is distinguishable from absence) and, if present, return get_env_bool(env_key) immediately (honoring both true and false). To keep layer precedence consistent and to avoid config defaults shadowing hardcoded defaults, I similarly detect config presence via get_config(flag_name) and only call get_config_bool when a config value exists; otherwise the hardcoded default is returned. These changes ensure an explicit env value (true or false) always overrides lower-priority layers.

```python
Lookup order:
  1. Environment variable (via env.get_env_bool)
  2. Config file (via config.get_config_bool)
  3. Hardcoded defaults
"""

from env import get_env_bool
from config import get_config_bool


HARDCODED_DEFAULTS = {
    "dark_mode": False,
    "beta": False,
    "analytics": False,
}

# Maps flag names to their env var keys
_ENV_KEY_MAP = {
    "dark_mode": "FEATURE_DARK_MODE",
    "beta": "FEATURE_BETA",
    "analytics": "FEATURE_ANALYTICS",
}


def is_enabled(flag_name):
    """Check if a feature flag is enabled.

    Checks env first, then config, then hardcoded defaults.
    If an environment variable (per _ENV_KEY_MAP) exists, its boolean
    value is authoritative (both true and false).
    """
    env_key = _ENV_KEY_MAP.get(flag_name)
    if env_key:
        from env import get_env
        # Use get_env to detect presence vs absence
        env_raw = get_env(env_key)
        if env_raw is not None:
            # Env is present; return its boolean interpretation
            return get_env_bool(env_key)

    from config import get_config
    cfg_raw = get_config(flag_name)
    if cfg_raw is not None:
        return get_config_bool(flag_name)

    return HARDCODED_DEFAULTS.get(flag_name, False)


def get_flag_source(flag_name):
    """Return which layer provides the flag value (for debugging)."""
    env_key = _ENV_KEY_MAP.get(flag_name)
    if env_key:
        from env import get_env
        if get_env(env_key) is not None:
            return "env"

    from config import get_config
    if get_config(flag_name) is not None:
        return "config"

    return "hardcoded"

```
