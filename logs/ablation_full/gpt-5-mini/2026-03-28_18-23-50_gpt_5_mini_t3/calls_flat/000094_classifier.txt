# Developer's Reasoning

## Root Cause
The primary bug is in pipeline.ingest: the for-loop that calls send_with_retry(msg, ...) lacks a break after a successful send, so the pipeline will call send_with_retry again even after the message has been stored. Contributing to the confusion, sender.send_with_retry previously returned True even if all retries failed (it swallowed ConnectionError), preventing the pipeline from distinguishing success vs. final failure.

## Failure Mechanism
Example: ingest(msg, max_pipeline_retries=2) calls send_with_retry(msg, max_retries=2). If the first call to send transiently fails then succeeds on a retry, send appended/notify the message. Because pipeline.ingest did not break after success, it calls send_with_retry a second time; send_with_retry will attempt its own retries and on success append/notify the same message again. With nested retry counts (pipeline 2 x sender 2) this can produce 2-4 append/notify calls for one logical ingest. The duplicate sends come from pipeline.ingest invoking send_with_retry multiple times for the same logical message.

## Broken Invariant
Ingesting a single logical message (one call to ingest(msg)) must result in exactly one append(msg) and exactly one notify(msg) recorded in store (i.e., store.message_count() increases by 1 and store.get_notifications() gains exactly one entry for that msg). Currently a single ingest can append/notify the same msg multiple times.

## Fix Strategy
Stop the pipeline from calling the sender again after a successful send and make sender.send_with_retry propagate a ConnectionError when all attempts are exhausted. Concretely: (1) add a break in pipeline.ingest immediately after a successful send_with_retry so the pipeline doesn't cause duplicate invocations; (2) change sender.send_with_retry to return on success and re-raise ConnectionError when retries are exhausted so callers (including pipeline) know when to retry or fail. This ensures pipeline retries only when the lower-level sender truly failed, and it prevents repeated successful sends for the same logical ingest.
