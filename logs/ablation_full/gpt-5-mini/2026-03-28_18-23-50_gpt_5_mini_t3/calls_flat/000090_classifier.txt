# Developer's Reasoning

## Root Cause
In sender.py, the function send_with_retry calls send() inside a for-loop but does not exit the loop after a successful send. The missing break/return causes send() to be invoked again on subsequent iterations (when max_retries > number of attempts already used), which calls append(msg) and notify(msg) multiple times.

## Failure Mechanism
Example: call send_with_retry('hello', max_retries=2, fail_first=False). On the first iteration send() succeeds, storing and notifying the message (append and notify). Because send_with_retry does not break or return after success, the loop proceeds to the next iteration and calls send() again, causing append('hello') and notify('hello') to run a second time. The store then contains duplicate messages/notifications even though the network operation succeeded once.

## Broken Invariant
After a successful send_with_retry(msg, ...), the store must contain exactly one appended message for msg and exactly one corresponding notification. Concretely: calling send_with_retry(msg) should increment store.message_count() by 1 and create a single notification for that msg; the current implementation can increment message_count() by more than 1.

## Fix Strategy
Return immediately from send_with_retry when send(msg, ...) succeeds, preventing further loop iterations and therefore preventing multiple calls to append() and notify(). Additionally, if all attempts raise ConnectionError, re-raise the last ConnectionError instead of silently returning True, so callers receive a proper failure signal. The change replaces the missing break with an immediate return True on success and raises last_error after exhausting retries.

```python
"""Message sender with retry and store integration."""

from store import append, notify, get_messages, get_notifications

_attempt_count = 0


def reset():
    global _attempt_count, _messages, _notifications
    _attempt_count = 0
    _messages = []
    _notifications = []


def send(msg, fail_first=False):
    """Send a message: store it and notify.

    If fail_first is True, raises on first call to simulate transient error.
    """
    global _attempt_count
    _attempt_count += 1
    if fail_first and _attempt_count == 1:
        raise ConnectionError("transient failure")
    append(msg)
    notify(msg)
    return True


def send_with_retry(msg, max_retries=2, fail_first=False):
    """Retry send on transient errors."""
    last_error = None
    for attempt in range(max_retries):
        try:
            send(msg, fail_first=fail_first)
            # Success: return immediately to avoid duplicate sends on further iterations
            return True
        except ConnectionError as e:
            last_error = e
            continue
    # If we exhausted retries, propagate the last error so callers know the send failed
    if last_error:
        raise last_error
    return False


def get_attempt_count():
    return _attempt_count

```
