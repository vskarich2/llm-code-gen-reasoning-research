# Developer's Reasoning

## Root Cause
make_increment_steps uses a per-increment closure variable captured['current'] to hold the value read by step_read, and step_write blindly writes captured['current'] + 1. Because step_write uses the stale captured value instead of the current global _value, a later write can overwrite a previous increment.

## Failure Mechanism
In interleaved_double_increment: reset() sets _value = 0. read_a() (from make_increment_steps A) stores captured_a['current'] = 0. read_b() (from B) stores captured_b['current'] = 0. write_a() does _set(captured_a['current'] + 1) => _set(1). write_b() then does _set(captured_b['current'] + 1) => _set(1) again, so the second increment overwrites the first and the final get() returns 1 instead of 2. The code paths are in make_increment_steps: step_read assigns the stale snapshot; step_write uses that stale snapshot to compute the new global value.

## Broken Invariant
For any two increments produced by make_increment_steps and executed (their read and write steps) in any interleaving, the global _value must increase by 2 from its initial value. Concretely, after reset() and executing two increments' read and write steps in any order, get() must return 2.

## Fix Strategy
Modify step_write to compute the new value from the current global state by calling get() at write time (i.e., _set(get() + 1)) instead of using the previously captured snapshot. This ensures each write bases its update on the up-to-date _value at the moment of the write, preventing later writes from clobbering earlier increments when steps are interleaved. The read step remains informational.

    """Counter with non-atomic read-modify-write, simulated via step functions."""

    _value = 0


    def reset():
        global _value
        _value = 0


    def get():
        return _value


    def _set(v):
        global _value
        _value = v


    def run_steps(steps):
        results = []
        for fn, args in steps:
            results.append(fn(*args))
        return results


    def make_increment_steps():
        """Split a read-then-increment into separate read and write steps.

        FIX: compute the new value at write time from the current global _value
        (call get() inside step_write) instead of using the captured snapshot.
        This prevents a later write from overwriting an earlier increment when
        steps from different increments are interleaved.
        """
        captured = {}

        def step_read():
            captured["current"] = get()
            return ("read", captured["current"])

        def step_write():
            # Use the current global value at write time to avoid writing a
            # stale snapshot. This makes the write idempotent with respect to
            # interleavings of other increments' write steps.
            new_val = get() + 1
            _set(new_val)
            return ("write", new_val)

        return step_read, step_write


    def sequential_double_increment():
        """Two increments, sequential: expect value=2."""
        reset()
        read_a, write_a = make_increment_steps()
        read_b, write_b = make_increment_steps()
        run_steps([(read_a, ()), (write_a, ()), (read_b, ()), (write_b, ())])
        return get()


    def interleaved_double_increment():
        """Two increments, interleaved: fixed — both increments are applied."""
        reset()
        read_a, write_a = make_increment_steps()
        read_b, write_b = make_increment_steps()
        run_steps([(read_a, ()), (read_b, ()), (write_a, ()), (write_b, ())])
        return get()
