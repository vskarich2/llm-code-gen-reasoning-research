## Root Cause

## Failure Mechanism

The membership test 'delete' in set() therefore evaluates to False even though moderators were intended to have moderation/delete rights.

## Fix Strategy

Also add ALL_ROLES and an is_valid_role() helper to make the set of known roles explicit and improve readability. The change preserves the previous fallback behavior for unknown roles (get_permissions returns an empty set) while ensuring moderator checks succeed.

```python
'''Access control: map roles to permission sets.

This module defines the permissions associated with each role and provides
helpers to query those permissions.

Previously the 'moderator' role was missing from ROLE_PERMISSIONS allowing
get_permissions('moderator') to fall through to an empty set. The mapping
is now explicit and a small helper was added for clarity.
'''

ROLE_PERMISSIONS = {
    'admin': {'read', 'write', 'delete', 'manage_users'},
    'moderator': {'read', 'delete'},
    'user': {'read', 'write'},
}

ALL_ROLES = frozenset(ROLE_PERMISSIONS.keys())


def is_valid_role(role):
    '''Return True if the given role is known.'''
    return role in ROLE_PERMISSIONS


def get_permissions(role):
    '''Return the set of permissions for the given role.

    Unknown roles return an empty set (preserving previous behavior).
    '''
    return ROLE_PERMISSIONS.get(role, set())


def has_permission(role, action):
    '''Check whether a role has a specific permission.

    Unknown roles do not have any permissions.
    '''
    return action in get_permissions(role)

```
