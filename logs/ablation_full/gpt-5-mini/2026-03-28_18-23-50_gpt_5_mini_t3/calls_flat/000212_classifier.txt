# Developer's Reasoning

## Root Cause
api.update_product calls both writer_a.write_fresh and writer_b.write_cached. writer_b.write_cached uses the module-level _cache and calls store.write(key, _cache[key]) without passing a version, so it can overwrite the freshly computed, versioned value that writer_a wrote. The causal chain is: api.update_product -> write_fresh(...) (writes value with a new version) -> write_cached(...) (writes cached value without updating store._versions), so the unversioned writer overwrites the correct value.

## Failure Mechanism
Concrete scenario: store starts with value 'A' at version 5 and writer_b._cache contains 'A'. compute_fn produces 'B'. update_product(product_id, compute_fn) does: (1) write_fresh increments _counter and calls store.write(product_id, 'B', version=6), so store now has value 'B' at version 6; (2) write_cached sees the product_id in _cache, writes store.write(product_id, 'A') with no version argument, so store._data becomes 'A' but store._versions remains 6. The system now serves value 'A' (stale) while get_version(product_id) returns 6 (reflecting the fresh update)—a stale payload with a newer version, caused by the unversioned write_cached call overwriting the fresh write.

## Broken Invariant
After update_product(product_id, compute_fn) returns, the store must contain the value produced by compute_fn for product_id and the store's version for product_id must reflect the writer_fresh increment. Formally: let prev_v = get_version(product_id) before the call and new_val = compute_fn(); then read(product_id) == new_val and get_version(product_id) == prev_v + 1. This invariant is violated when write_cached overwrites the fresh write without updating version.

## Fix Strategy
Remove the redundant unversioned writer call from api.update_product so only the versioned writer (write_fresh) updates the store. By deleting the write_cached call and its import in api.py, no unversioned overwrite can follow a versioned write, ensuring the store value equals compute_fn() and the version was incremented by write_fresh. The change is limited to api.py: it now calls only write_fresh and returns the read value.
