# Developer's Reasoning

## Root Cause
In pipeline.pipeline the call compute_raw_stats uses the variable 'cleaned' (the normalized data) instead of the original 'data'. Specifically the line raw_stats = compute_raw_stats(cleaned) passes normalized values to compute_raw_stats, so raw_stats are computed from normalized data rather than the untransformed input.

## Failure Mechanism
When pipeline(data) is called, normalize(data) produces 'cleaned' and then compute_raw_stats(cleaned) computes max/min/sum of those normalized values. For example, given data = [10, 20, 30], normalize(data) returns [0.0, 0.5, 1.0]; compute_raw_stats(cleaned) will return {'raw_max': 1.0, 'raw_min': 0.0, 'raw_sum': 1.5} instead of {'raw_max': 30, 'raw_min': 10, 'raw_sum': 60}. This causes any consumers of pipeline()['raw_stats'] to observe statistics of the normalized data rather than the original measurements.

## Broken Invariant
compute_raw_stats MUST be called on the original input 'data' before any transforms. Concretely: for any non-empty input list 'data', pipeline(data)['raw_stats']['raw_max'] must equal max(data), raw_min must equal min(data), and raw_sum must equal sum(data). The current code violates this because it computes those values from the normalized list 'cleaned'.

## Fix Strategy
Call compute_raw_stats with the original 'data' instead of 'cleaned'. Changing raw_stats = compute_raw_stats(cleaned) to raw_stats = compute_raw_stats(data) ensures compute_raw_stats observes untransformed values and restores the invariant that raw_stats reflect the original data. No other behavior is changed; summarize_for_display remains computed from the normalized 'cleaned' list.
