## Root Cause
In add_entry(), when position is not None the code calls _labels.insert(position, label) but then calls _values.append(value) instead of inserting into _values at the same position. The faulty line is _values.append(value) inside the position branch, which causes labels and values to diverge.

## Failure Mechanism
If the report already contains entries and add_entry('x', 99, position=1) is called, _labels becomes ['a', 'x', 'b'] because _labels.insert(position, label) shifts labels into the requested index, but _values becomes [1, 2, 99] because _values.append(value) appends to the end. As a result get_all() or get_entry() will return mismatched pairs (e.g. [('a', 1), ('x', 2), ('b', 99)]), because the labels and values arrays are no longer aligned.

## Broken Invariant
The module must maintain the invariant len(_labels) == len(_values) and that for every index i the label at _labels[i] corresponds to the value at _values[i] (i.e. add_entry must perform the same insert/append operation on both lists). The current code violates this when inserting at a specific position.

## Fix Strategy
Change the update in add_entry so that when position is provided both _labels.insert(position, label) and _values.insert(position, value) are used, ensuring the two lists are modified symmetrically. I also added an internal _assert_aligned() call after modifications to detect any future divergence. This directly fixes the mechanism by making the lists always updated in the same way.

    """Raise RuntimeError if the internal lists have diverged in length."""

        )


def add_entry(label, value, position=None):
    """Add an entry to the report.

    If position is given, insert both label and value at that index. Otherwise,
    append both to the end. This keeps the two internal lists aligned.
    """
    if position is not None:
        # Insert both label and value at the same index to keep lists aligned.
        _labels.insert(position, label)

        _values.append(value)
