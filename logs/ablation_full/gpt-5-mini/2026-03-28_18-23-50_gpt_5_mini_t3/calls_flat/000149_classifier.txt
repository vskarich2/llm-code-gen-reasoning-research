# Developer's Reasoning

## Root Cause
In payment.process_payment, the early return when txn_id is found in the module-level cache (_cache) causes the function to exit before calling ledger.record. The variable _cache is checked and used for an immediate return, which prevents ledger.record from being invoked for duplicate calls.

## Failure Mechanism
When the same txn_id is submitted more than once, e.g. process_payment('tx123', 100) followed by process_payment('tx123', 100) again, the first call records an entry via record(...). The second call hits the if txn_id in _cache branch and returns the cached result immediately. Because the early return happens before record(...) is called, the ledger only contains one entry even though process_payment was invoked twice, causing ledger.verify(expected_count) to fail if expected_count equals the number of process_payment calls.

## Broken Invariant
After N calls to process_payment (including repeated txn_id values), ledger.get_summary()['count'] (or len of ledger entries) must equal N. Currently, this invariant is violated for N > 1 when any txn_id is repeated because duplicates are not recorded.

## Fix Strategy
Ensure every call to process_payment records an entry in the ledger before returning. Concretely, when a txn_id is cached, call record(txn_id, amount, cached_status) and then return the cached result instead of returning early. This preserves the original caching behavior while guaranteeing the ledger count increments for each call. The change adds a call to record(...) in the duplicate branch and returns the cached object afterwards.

```python
"""Payment processor with duplicate detection."""

from ledger import record, verify, reset_ledger

_cache = {}


def process_payment(txn_id, amount):
    """Process a payment. Detects duplicates via txn_id cache.

    Every call — including duplicates — must be recorded in the ledger
    so that verify() counts match total process_payment calls.
    """
    # For cached results we must still record the call in the ledger
    # so ledger counts reflect every invocation of process_payment.
    if txn_id in _cache:
        cached = _cache[txn_id]
        # Record this duplicate invocation. Use the provided amount
        # (call-level value) and the cached status to reflect what
        # happened for this call in the ledger.
        record(txn_id, amount, cached["status"])
        return cached

    result = {"txn_id": txn_id, "amount": amount, "status": "charged"}
    record(txn_id, amount, "charged")
    _cache[txn_id] = result
    return result


def get_cached(txn_id):
    """Retrieve a cached payment result."""
    return _cache.get(txn_id)


def reset():
    """Reset payment state."""
    _cache.clear()
    reset_ledger()

```
