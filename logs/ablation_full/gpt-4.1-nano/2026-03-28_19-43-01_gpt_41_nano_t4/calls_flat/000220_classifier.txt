## Root Cause
The function make_withdraw_steps creates separate check and act steps that rely on a shared 'result' dictionary. During interleaving, both check steps for two withdrawals pass before either act step executes, leading to both withdrawals being approved based on the initial balance of 100. Consequently, both withdrawals of 80 are executed, reducing the balance to -60, which violates the invariant that the balance should never be negative.

## Failure Mechanism
In interleaved execution, the two check steps for the two withdrawals both succeed because they both see the initial balance of 100 before any withdrawal occurs. Both act steps then execute, each deducting 80, resulting in a total deduction of 160 from an initial 100, leaving the balance at -60. This occurs because the check-then-act sequence is not atomic and the shared 'result' state is not protected against concurrent modifications, allowing both withdrawals to proceed despite insufficient funds.

## Broken Invariant
The account balance must never become negative after any sequence of withdrawal operations.

## Fix Strategy
Modify the make_withdraw_steps function to perform the check and withdrawal atomically within a single function, ensuring that the balance is checked and decremented in one step without interference. This can be achieved by combining check_balance and do_withdraw into a single function that verifies sufficient funds before performing the withdrawal, preventing overdraft even under interleaving. The code is updated to include an atomic withdraw function that enforces this invariant.

"""Bank with non-atomic check-then-act withdrawal, simulated via steps."""

_accounts = {}

def reset():
    _accounts.clear()

def create_account(name, balance):
    _accounts[name] = balance

def get_balance(name):
    return _accounts.get(name, 0)

def check_balance(name, amount):
    """CHECK: is balance sufficient?"""
    return _accounts.get(name, 0) >= amount

def do_withdraw(name, amount):
    """ACT: decrement balance. Assumes caller verified."""
    _accounts[name] = _accounts.get(name, 0) - amount

def run_steps(steps):
    results = []
    for fn, args in steps:
        results.append(fn(*args))
    return results

def make_withdraw_steps(name, amount):
    """Split withdrawal into separate check and act steps.

    BUG: under interleaving, both checks pass before either debits.
    """
    result = {"approved": False}

    def step_check():
        result["approved"] = check_balance(name, amount)
        return ("check", result["approved"])

    def step_act():
        if result["approved"]:
            do_withdraw(name, amount)
        return ("act", result["approved"])

    return step_check, step_act

def sequential_withdrawals():
    """Two withdrawals of 80 from balance=100. Sequential: second denied."""
    reset()
    create_account("alice", 100)
    check_a, act_a = make_withdraw_steps("alice", 80)
    check_b, act_b = make_withdraw_steps("alice", 80)
    run_steps([(check_a, ()), (act_a, ()), (check_b, ()), (act_b, ())])
    return get_balance("alice")
