# Developer's Reasoning

## Root Cause
The make_increment_steps() function captures the current value in a local variable 'captured' during the read step, but when two increments are interleaved, both read the same initial value (e.g., 0) because the read steps are executed before either write occurs. Consequently, both write steps set the counter to the same incremented value, causing the second increment to overwrite the first, resulting in only a single increment overall.

## Failure Mechanism
When two threads or steps execute the read steps concurrently, both capture the same initial counter value (e.g., 0). Then, each proceeds to the write step, both writing back the same incremented value (e.g., 1). As a result, the counter only increases by 1 instead of 2, because the second write overwrites the first, losing one update.

## Broken Invariant
After executing two concurrent increments, the counter value should increase by 2, i.e., starting from 0, the final value should be 2.

## Fix Strategy
Modify make_increment_steps() so that the read and write steps operate directly on the shared global counter without capturing the value in a local variable. Specifically, the read step should return the current value of the counter, and the write step should increment the counter based on the value read, ensuring that each increment reflects the latest counter state at the time of the write. This prevents both increments from reading the same initial value and overwriting each other's updates.



# Task Description
