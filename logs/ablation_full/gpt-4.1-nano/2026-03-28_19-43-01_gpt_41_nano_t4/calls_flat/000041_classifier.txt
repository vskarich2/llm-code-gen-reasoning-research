# Developer's Reasoning

## Root Cause
The client.py module captures the configuration in the variable _client_config at import time by calling get_config(), which loads the config only once. Therefore, subsequent calls to get_config() or reset_config() do not affect _client_config, causing the client to use stale configuration values.

## Failure Mechanism
After calling reset_config() to clear the cached configuration, the client still returns the old timeout value because _client_config was initialized at import time and is not updated when the configuration is reset, leading to inconsistent behavior where the client does not reflect the latest configuration changes.

## Broken Invariant
The client should always use the current configuration returned by get_config() whenever get_db_url() or get_timeout() is called, reflecting any resets or updates to the configuration.

## Fix Strategy
By removing the eager capture of get_config() into _client_config at import time and instead calling get_config() within get_db_url() and get_timeout() functions, the client will always retrieve the latest configuration, including after reset_config() is called.
