## Root Cause
In the place_order function, if wallet.charge() raises a ValueError due to insufficient funds, the inventory reservation made earlier is not released, leading to an inconsistent state where inventory is reserved but not paid for.

## Failure Mechanism
When a customer attempts to place an order with insufficient wallet balance, inventory.reserve(qty) is called successfully, reserving the stock. However, wallet.charge() then raises a ValueError, and because the exception is re-raised without releasing the reservation, the inventory remains reserved indefinitely, causing a mismatch between reserved stock and actual sales.

## Broken Invariant
The inventory's reserved stock must be released if the wallet charge fails, ensuring that reserved inventory does not remain reserved without corresponding payment.

## Fix Strategy
Adding a finally block that releases the inventory reservation if an exception occurs during wallet.charge() ensures that the reservation is always released upon failure, maintaining consistency between inventory reservations and wallet charges.

"""Order fulfillment with inventory and wallet."""


class Inventory:
    def __init__(self, stock):
        self.stock = stock
        self.reserved = 0

    def reserve(self, qty):
        if qty > self.stock - self.reserved:
            raise ValueError("insufficient stock")
        self.reserved += qty

    def release(self, qty):
        self.reserved -= qty

    def available(self):
        return self.stock - self.reserved


class Wallet:
    def __init__(self, balance):
        self.balance = balance

    def charge(self, amount):
        if amount > self.balance:
            raise ValueError("insufficient funds")
        self.balance -= amount


def place_order(inventory, wallet, qty, price):
