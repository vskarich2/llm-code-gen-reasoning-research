# Developer's Reasoning

## Root Cause
The client.py module assigns the variable _client_cfg to the result of get_config() at import time, capturing a reference to the config dictionary. When reset_config() is called in config.py, _config is set to None, and subsequent get_config() calls return a new dictionary, but _client_cfg in client.py still points to the old, stale dictionary.

## Failure Mechanism
After reset_config() is invoked, the config in config.py is reset to None, and get_config() loads a new dictionary. However, since _client_cfg was assigned at import time, it continues referencing the old config dictionary. As a result, functions like get_api_key() and get_base_url() in client.py return outdated values, causing the client to operate with stale configuration data.

## Broken Invariant
The variable _client_cfg in client.py must always reflect the current configuration returned by get_config(), ensuring that any changes to the configuration are visible to client functions, especially after reset_config() is called.

## Fix Strategy
I moved the assignment of _client_cfg from the module level to within each function that needs the current config, specifically by calling get_config() inside get_api_key(), get_base_url(), and build_headers(). This ensures that each function retrieves the latest configuration, reflecting any resets or updates, thus fixing the stale reference issue.
