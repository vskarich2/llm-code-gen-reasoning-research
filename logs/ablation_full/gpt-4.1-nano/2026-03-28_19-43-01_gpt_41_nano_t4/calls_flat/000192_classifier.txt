## Root Cause
The execute_transfer function directly calls logging and audit functions (record_transfer_attempt, emit_transfer_event, emit_failure_alert) within its core business logic, mixing observability with state changes. This coupling makes it difficult to isolate the core transfer logic from side effects.

## Failure Mechanism
When execute_transfer is invoked, it performs the transfer steps and logs events simultaneously. If a transient failure occurs after deducting the sender's balance but before crediting the receiver, the logs and audit events are already recorded, leading to inconsistent state and observability data that does not accurately reflect the final transfer outcome.

## Broken Invariant
The core transfer logic should be independent of logging and observability concerns, ensuring that the transfer either completes fully with all side effects or not at all, maintaining consistency between account balances and recorded events.

## Fix Strategy
I extracted the core transfer steps into a separate helper function that performs the balance updates without any logging or audit calls. The execute_transfer function now acts as a wrapper that calls this helper and surrounds it with the observability calls, ensuring that logging is only performed after successful completion of the core transfer logic.

```python
import random
from models import Account
from ledger import record_debit, record_credit, record_transfer_attempt
from audit import emit_transfer_event, emit_failure_alert


def validate_transfer(sender, amount):
    if amount <= 0:
        raise ValueError("amount must be positive")
    if sender.balance < amount:
        raise ValueError("insufficient funds")


def perform_transfer_core(sender, receiver, amount):
    sender.balance -= amount
    record_debit(sender.account_id, amount)

    if random.random() < 0.3:
        raise RuntimeError("transient failure during credit")

    receiver.balance += amount
    record_credit(receiver.account_id, amount)


def execute_transfer(sender, receiver, amount):
    validate_transfer(sender, amount)

    record_transfer_attempt(sender.account_id, receiver.account_id, amount)

    try:
        perform_transfer_core(sender, receiver, amount)
    except Exception as e:
        emit_failure_alert(
            sender.account_id, receiver.account_id, amount,
            str(e),
        )
        raise
    else:
        emit_transfer_event(sender.account_id, receiver.account_id, amount)

```
