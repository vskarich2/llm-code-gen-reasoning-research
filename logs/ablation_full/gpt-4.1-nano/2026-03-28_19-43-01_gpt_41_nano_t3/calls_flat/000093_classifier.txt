## Root Cause
In pipeline.py, the ingest() function calls send_with_retry() inside a for loop but does not check whether the message was successfully sent, nor does it break out of the loop upon success. This causes the message to be sent multiple times if transient errors occur, especially since send_with_retry() itself already implements retries. The variable _attempt_count in pipeline.py is also unused and unrelated to the actual send attempts, leading to confusion.

## Failure Mechanism
When ingest() is called, it repeatedly calls send_with_retry() in a loop without verifying success. If send_with_retry() succeeds on the first attempt, the loop continues, causing the message to be sent multiple times. Conversely, if send_with_retry() fails, the loop retries until max_pipeline_retries is exhausted, resulting in multiple sends for a single message. This leads to duplicate messages appearing 3-4 times, especially when combined with the deduplication logic.

## Broken Invariant
The ingest() function guarantees that each message is sent exactly once per call, regardless of transient errors, and does not produce duplicate messages due to multiple send attempts within the pipeline retry loop.

## Fix Strategy
I added a break statement after a successful send_with_retry() call within the try block in ingest(), ensuring that the loop exits once the message has been successfully sent. I also removed the unused _attempt_count variable from pipeline.py to prevent confusion. This change ensures each message is sent only once per ingest() invocation, respecting the intended retry logic and preventing duplicate messages.
