# Developer's Reasoning

## Root Cause
The process_batch function in worker.py uses a default argument 'seen=set()', which is evaluated only once at function definition time, causing the set to persist across multiple calls. This leads to valid tasks being skipped in subsequent batches if their 'name' was seen in previous calls.

## Failure Mechanism
When process_batch is called multiple times with different task batches, the 'seen' set retains its state from previous calls, causing tasks with the same 'name' in later batches to be incorrectly skipped, even if they are valid and new in the current batch.

## Broken Invariant
Each call to process_batch with a new batch must process all tasks in that batch, regardless of previous calls, and only skip tasks that have been processed in prior calls.

## Fix Strategy
Changing the default value of 'seen' from a mutable default argument to a local variable initialized within the function ensures that each call to process_batch starts with a fresh 'seen' set, preventing cross-call state persistence and ensuring all valid tasks are processed in each batch.

"""Worker that processes task batches."""

from queue import create_task


def process_batch(tasks, seen=None):
    """Process a batch of tasks, skipping already-seen ones.

    Invariant: each call to process_batch with a fresh batch must
    process ALL tasks in that batch, regardless of prior calls.
    """
    if seen is None:
        seen = set()
    results = []
    for task in tasks:
        task_id = task["name"]
        if task_id in seen:
            continue
        seen.add(task_id)
        results.append({"name": task["name"], "result": "processed"})
    return results


def summarize(results):
    """Summarize processing results (distractor)."""
    return f"{len(results)} tasks processed"
