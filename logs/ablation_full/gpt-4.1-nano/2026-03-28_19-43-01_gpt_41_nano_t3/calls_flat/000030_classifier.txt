# Developer's Reasoning

## Root Cause
The update_product function modifies the _db dictionary directly without invalidating the corresponding cache entry, causing get_product to return stale data with old prices.

## Failure Mechanism
When update_product is called to change a product's price, the cache for that product remains unchanged. Subsequent calls to get_product retrieve the cached data, which still contains the old price, leading to outdated product information being shown.

## Broken Invariant
After update_product is called to modify a product, get_product must return the product with the latest updated fields, including the new price, reflecting the change in the database.

## Fix Strategy
Adding a call to invalidate(product_id) within update_product ensures that the cache entry for the product is removed whenever the product is updated, forcing get_product to fetch fresh data from _db and update the cache accordingly.



# Task Description
Products show old prices after updates. Fix the catalog. Return the updated code.

# Code Produced
```python
"""Product catalog using external cache module."""

from cache import get, put, invalidate

_db = {}


def add_product(product_id, name, price):
    """Add a product to the database."""
    _db[product_id] = {"name": name, "price": price}


def get_product(product_id):
    """Get product, checking cache first."""
    cached = get(product_id)
    if cached is not None:
        return cached
    product = _db.get(product_id)
    if product is not None:
        put(product_id, dict(product))
    return _db.get(product_id)


def update_product(product_id, **fields):
    """Update product in DB.

    Invariant: subsequent get_product() must reflect the update.
    """
    if product_id not in _db:
        return False
    _db[product_id].update(fields)
    invalidate(product_id)
    return True


def reset():
    """Clear DB and cache."""
    _db.clear()
    from cache import clear
    clear()
```
