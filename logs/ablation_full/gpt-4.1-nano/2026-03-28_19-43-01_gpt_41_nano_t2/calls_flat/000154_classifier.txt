## Root Cause
The add_entry function inserts a label at the specified position but always appends the value to the end of the _values list, regardless of the position parameter. This causes a mismatch between labels and values when inserting at a specific index.

## Failure Mechanism
When add_entry is called with a position argument, the label is inserted at that index in _labels, but the value is appended to the end of _values. This results in label-value pairs being misaligned, leading to incorrect data retrieval and inconsistent report entries.

## Broken Invariant
For every index i, _labels[i] and _values[i] must correspond to the same report entry, maintaining alignment between labels and values.

## Fix Strategy
Modify the add_entry function so that when a position is specified, the value is also inserted at that position in _values, ensuring label-value alignment. This is achieved by replacing _values.append(value) with _values.insert(position, value) within the conditional block.
