# Developer's Reasoning

## Root Cause
The client.py module captures the configuration in the variable _client_config at import time by calling get_config(), which loads the config only once. Therefore, subsequent calls to reset_config() do not affect _client_config, and the client continues to use the old configuration values.

## Failure Mechanism
When reset_config() is called, it resets the global _config variable in config.py, but the client.py module's _client_config variable remains unchanged because it was set at import time. As a result, get_db_url() and get_timeout() continue to return the old configuration values, ignoring the reset.

## Broken Invariant
The client should always reflect the current configuration after reset_config() is called, meaning get_db_url() and get_timeout() should return the updated values from get_config() rather than stale cached values.

## Fix Strategy
Remove the _client_config variable from client.py and replace its usage with direct calls to get_config() within get_db_url() and get_timeout(). This ensures that each call retrieves the latest configuration, including after reset_config() is invoked.
