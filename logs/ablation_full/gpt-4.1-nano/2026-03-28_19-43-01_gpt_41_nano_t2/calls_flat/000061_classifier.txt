## Root Cause
In the process_batch function, the snapshot() function is called only once after processing all items, which results in only a single snapshot being recorded regardless of the number of items processed. This occurs because snapshot() is called outside the for loop, so it does not record a snapshot after each individual item.

## Failure Mechanism
When process_batch is called with multiple items, only one snapshot is taken at the end of the batch, failing to record the counter state after each item. This causes verify_consistency to report fewer snapshots than the number of items processed, violating the expectation that each item should produce one snapshot.

## Broken Invariant
The number of snapshots recorded should equal the number of items processed in process_batch, ensuring each item has a corresponding snapshot.

## Fix Strategy
Move the call to snapshot() inside the for loop so that a snapshot is taken after processing each individual item, aligning the number of snapshots with the number of items processed.
