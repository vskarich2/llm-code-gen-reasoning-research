# Developer's Reasoning

## Root Cause
The process_batch function in worker.py uses a default argument 'seen=set()', which is evaluated only once at function definition time, causing the set to persist across multiple calls. This leads to valid tasks being skipped in subsequent batches if their 'name' has been seen before, even if they are part of a new batch.

## Failure Mechanism
When process_batch is called multiple times with different task batches, the 'seen' set retains tasks from previous calls. As a result, tasks with unique 'name's in later batches are incorrectly identified as duplicates and skipped, causing valid tasks to be omitted from processing.

## Broken Invariant
Each call to process_batch with a new batch must process all tasks in that batch, regardless of previous calls, and should not skip tasks based on prior batch processing.

## Fix Strategy
Changing the default value of 'seen' from 'set()' to None and initializing a new set inside the function if 'seen' is None ensures that each call to process_batch starts with a fresh set, preventing cross-call contamination and ensuring all tasks in each batch are processed.

"""Worker that processes task batches."""

from queue import create_task

def process_batch(tasks, seen=None):
    """Process a batch of tasks, skipping already-seen ones.

    Invariant: each call to process_batch with a fresh batch must
    process ALL tasks in that batch, regardless of prior calls.
    """
    if seen is None:
        seen = set()
    results = []
    for task in tasks:
        task_id = task["name"]
        if task_id in seen:
            continue
        seen.add(task_id)
        results.append({"name": task["name"], "result": "processed"})
    return results


def summarize(results):
    """Summarize processing results (distractor)."""
    return f"{len(results)} tasks processed"
