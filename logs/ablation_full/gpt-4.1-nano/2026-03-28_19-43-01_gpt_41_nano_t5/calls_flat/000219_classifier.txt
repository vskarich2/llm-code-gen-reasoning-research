# Developer's Reasoning

## Root Cause
The function make_withdraw_steps creates separate check and act steps that do not coordinate, leading to both checks passing before either withdrawal occurs. Specifically, the check_balance function verifies sufficient funds based on the current balance, but between the two checks, the balance remains unchanged, allowing both approvals. Consequently, both do_withdraw calls execute, each subtracting 80, resulting in an overdraft of -60.

## Failure Mechanism
During interleaved execution, the two check steps both return True because the balance is initially 100, and neither has yet performed a withdrawal. Both act steps then execute, each subtracting 80, reducing the balance from 100 to -60. This occurs because the check-then-act sequence is not atomic, and the code does not prevent concurrent withdrawals from exceeding the initial balance.

## Broken Invariant
The account balance must never become negative after any sequence of withdrawal operations, regardless of interleaving or concurrency, provided each withdrawal is only approved if sufficient funds are available at the time of check.

## Fix Strategy
Modify the make_withdraw_steps function to perform the check and withdrawal atomically within a single function, ensuring that once a withdrawal is approved, the balance is immediately decremented, preventing subsequent withdrawals from overdrawn accounts. This can be achieved by replacing the separate check and act steps with a single function that performs both operations under a lock or atomic context, or by restructuring the code to verify and perform the withdrawal in one step.

def reset():

def create_account(name, balance):

def check_balance(name, amount):
    """CHECK: is balance sufficient?"""
    return _accounts.get(name, 0) >= amount


def do_withdraw(name, amount):
    """ACT: decrement balance. Assumes caller verified."""
    _accounts[name] = _accounts.get(name, 0) - amount


def run_steps(steps):
    results = []
    for fn, args in steps:
        results.append(fn(*args))
    return results


def make_withdraw_steps(name, amount):
    """Split withdrawal into separate check and act steps.

    BUG: under interleaving, both checks pass before either debits.
    """
    result = {"approved": False}

    def step_check():
        result["approved"] = check_balance(name, amount)
        return ("check", result["approved"])

    def step_act():
        if result["approved"]:
            do_withdraw(name, amount)
        return ("act", result["approved"])

    return step_check, step_act


def sequential_withdrawals():
