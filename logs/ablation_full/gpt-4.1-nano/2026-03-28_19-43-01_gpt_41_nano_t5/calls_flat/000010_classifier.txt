## Root Cause
In middleware.py, the apply_config method assigns self._base directly to cfg, which is a reference to the DEFAULTS dictionary created by create_config(). When request_overrides are applied, cfg.update(request_overrides) mutates this shared dictionary, causing subsequent requests to inherit unintended modifications. This occurs because create_config() returns the DEFAULTS dictionary directly without copying it.

## Failure Mechanism
When handle_request is called with overrides, the middleware's apply_config method updates the shared self._base dictionary in place. As a result, the DEFAULTS dictionary is mutated, leading to altered default values for future requests. For example, if a request sets debug to True, subsequent requests will see debug as True even if not overridden, because the original DEFAULTS have been changed.

## Broken Invariant
The apply_config method must return a new configuration dictionary for each request without mutating the original base configuration, ensuring that defaults remain unchanged across requests.

## Fix Strategy
In middleware.py, modify apply_config to create a copy of self._base before applying overrides, preventing mutation of the cached base configuration. This is achieved by replacing 'cfg = self._base' with 'cfg = dict(self._base)'.
