## Root Cause
The enqueue function uses a mutable default argument 'queue=[]', which is shared across all calls, causing tasks to accumulate unintentionally.

## Failure Mechanism
When enqueue is called multiple times without specifying a queue, each call adds tasks to the same shared list, leading to tasks from previous calls persisting and accumulating, violating expected queue behavior.

## Broken Invariant
Each call to enqueue with a single task (and no explicit queue) must return a new list containing only that task, ensuring no task accumulation from previous calls.

## Fix Strategy
Changing the default argument of 'queue' from a mutable list to None and initializing a new list inside the function if 'queue' is None prevents shared state, ensuring each call with a single task returns a fresh queue containing only that task.
