## Root Cause
In the place_order function, if wallet.charge() raises a ValueError due to insufficient funds, the inventory.reserve(qty) call is not rolled back, leaving the inventory reservation in place even though the order failed.

## Failure Mechanism
When reserve() is called to hold inventory and then wallet.charge() fails, the inventory remains reserved because there is no release step in the exception handling, causing inventory to be incorrectly marked as reserved despite the order not completing.

## Broken Invariant
The inventory's reserved quantity must accurately reflect only the items reserved for successful orders; if an order fails after reserving inventory, the reservation must be released to maintain consistency.

## Fix Strategy
Wrap the wallet.charge() call in a try-except block and add a finally clause to release the inventory reservation if an exception occurs, ensuring that reservations are always correctly released on failure.

"""Order fulfillment with inventory and wallet."""


class Inventory:
    def __init__(self, stock):
        self.stock = stock
        self.reserved = 0

    def reserve(self, qty):
        if qty > self.stock - self.reserved:
            raise ValueError("insufficient stock")
        self.reserved += qty

    def release(self, qty):
        self.reserved -= qty

    def available(self):
        return self.stock - self.reserved


class Wallet:
    def __init__(self, balance):
        self.balance = balance

    def charge(self, amount):
        if amount > self.balance:
            raise ValueError("insufficient funds")
        self.balance -= amount


def place_order(inventory, wallet, qty, price):
    """Reserve inventory, then charge wallet. Release on failure."""
    inventory.reserve(qty)
    try:
        wallet.charge(qty * price)
    except ValueError:
        # Release inventory reservation if charging fails
        inventory.release(qty)
        raise
    return {"status": "confirmed", "qty": qty, "total": qty * price}
