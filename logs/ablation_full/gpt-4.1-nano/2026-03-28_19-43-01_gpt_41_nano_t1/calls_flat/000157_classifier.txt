# Developer's Reasoning

## Root Cause
In the add_entry function, when position is provided, the label is inserted at the specified index using _labels.insert(position, label), but the value is always appended to _values with _values.append(value). This causes the label and value arrays to become misaligned, as the value is not inserted at the same position as the label.

## Failure Mechanism
When add_entry is called with a specific position, the label is inserted at that position in _labels, but the corresponding value is appended to _values, resulting in mismatched label-value pairs at the same index. This misalignment leads to incorrect retrieval of entries and inconsistent report data.

## Broken Invariant
For every index i, _labels[i] and _values[i] must correspond to the same report entry, maintaining alignment between labels and values.

## Fix Strategy
Changing _values.append(value) to _values.insert(position, value) when position is specified ensures that both label and value are inserted at the same index, preserving their alignment and maintaining the invariant.

_labels = []
_values = []


def add_entry(label, value, position=None):
    """Add an entry to the report.

    If position is given, insert at that index.
    Otherwise, append to the end.
    """
    if position is not None:
        _labels.insert(position, label)
        # Fix: insert value at the same position to keep arrays aligned
        _values.insert(position, value)
    else:
        _labels.append(label)
        _values.append(value)


def get_entry(index):
    """Return (label, value) at the given index."""
    return (_labels[index], _values[index])

    """Return list of (label, value) tuples."""
    return list(zip(_labels, _values))
