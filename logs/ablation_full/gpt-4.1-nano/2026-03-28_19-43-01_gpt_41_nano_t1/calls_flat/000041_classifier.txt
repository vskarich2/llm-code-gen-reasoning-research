## Root Cause
The client.py module captures the result of get_config() at import time into the variable _client_config, which is initialized before any reset or change to the configuration occurs.

## Failure Mechanism
When reset_config() is called, it resets the global _config variable in config.py, but the client continues to use the stale _client_config variable, which was set at import time, thus still returning old timeout and db_url values.

## Broken Invariant

## Fix Strategy
Change the client.py code to call get_config() dynamically within get_db_url() and get_timeout() functions, ensuring it retrieves the latest configuration each time, rather than relying on a stale cached value.
