## Root Cause
The bug is in the 'process_batch' function where the 'emit_event' call is outside the loop. This means only the last item's event is emitted, leading to a mismatch between the number of processed items and emitted events.

## Failure Mechanism
When processing a batch of items, if there are multiple items, only the last item's event is emitted because 'emit_event' is called after the loop. For example, if there are three items, only the event for the third item is recorded, while the first two are ignored.

## Broken Invariant
The number of emitted events must equal the number of processed items. This invariant is violated because only one event is emitted regardless of how many items are processed.

## Fix Strategy
By moving the 'emit_event' call inside the loop, each item's event will be emitted immediately after it is processed. This ensures that the number of emitted events matches the number of processed items.
