## Root Cause
The removal of the commit() function and freeze_view() function in the pipeline.py file leads to the state not being properly transitioned from pending to stable, and the view not being updated accordingly. Specifically, the 'stable' and 'view' keys in the state dictionary are not populated with the correct data.

## Failure Mechanism
When the process_batch function is called, it stages the data but does not commit it. As a result, the 'stable' list remains empty, and the 'view' list is not updated to reflect the committed data. This causes the get_committed_total function to return None, as it checks if the state is frozen, which it is not, leading to incorrect total calculations.

## Broken Invariant
The invariant that the total of committed items should only be calculated when the state is committed (frozen) is violated. The system fails to provide a valid total when the state is not properly committed, leading to inconsistent results.

## Fix Strategy
Restoring the commit() and freeze_view() functions in the pipeline.py file ensures that the pending entries are promoted to stable and the view is updated accordingly. This change reinstates the correct state transitions, allowing the get_committed_total function to return accurate totals.

def stage(st, data):
    st["pending"] = list(data)

def commit(st):
    """Promote pending to stable. Sorts by id for canonical ordering. Sets frozen gate."""
