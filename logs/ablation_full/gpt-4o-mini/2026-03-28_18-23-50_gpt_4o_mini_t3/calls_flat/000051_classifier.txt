## Root Cause
The bug is in the 'process_batch' function where the 'seen' set is defined as a default argument. This causes it to persist across multiple calls to the function, leading to valid tasks being skipped if they have been processed in a previous call.

## Failure Mechanism
For example, if the first batch contains tasks 'A' and 'B', and both are processed, the 'seen' set will contain {'A', 'B'}. If the second batch contains 'B' and 'C', the function will skip 'B' because it is already in the 'seen' set, even though it is a valid task in the new batch.

## Broken Invariant
Each call to 'process_batch' with a fresh batch must process ALL tasks in that batch, regardless of prior calls. The current implementation violates this by skipping tasks that have been seen in previous batches.

## Fix Strategy
By changing the 'seen' parameter to be a local variable initialized within the function, it ensures that each call to 'process_batch' starts with a fresh set of seen tasks, allowing all tasks in the current batch to be processed.

# Code Produced
```python
def process_batch(tasks, seen=None):
    """Process a batch of tasks, skipping already-seen ones.

    Invariant: each call to process_batch with a fresh batch must
    process ALL tasks in that batch, regardless of prior calls.
    """
    if seen is None:
        seen = set()
    results = []
    for task in tasks:
        task_id = task["name"]
        if task_id in seen:
            continue
        seen.add(task_id)
        results.append({"name": task["name"], "result": "processed"})
    return results


def summarize(results):
    """Summarize processing results (distractor)."""
    return f"{len(results)} tasks processed"
```
