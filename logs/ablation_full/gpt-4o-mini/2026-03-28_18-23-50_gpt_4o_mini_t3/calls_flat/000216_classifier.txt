## Failure Mechanism
In the `interleaved_withdrawals` function, both `check_a` and `check_b` are executed before either `act_a` or `act_b`. This means that both checks see a balance of 100, approve the withdrawals, and then both attempt to withdraw 80, resulting in a negative balance of -60.

## Broken Invariant
The balance of an account should never be negative after a withdrawal operation. This invariant is violated when both withdrawals are approved and executed, leading to an overdraft.

## Fix Strategy
To fix the issue, I will modify the `step_act` function to re-check the balance right before the withdrawal occurs. This ensures that the balance is still sufficient at the time of the withdrawal, preventing any overdraft.

def reset():
    _accounts.clear()

def create_account(name, balance):
    _accounts[name] = balance

def get_balance(name):
    return _accounts.get(name, 0)

def check_balance(name, amount):
    """CHECK: is balance sufficient?"""
    return _accounts.get(name, 0) >= amount

def do_withdraw(name, amount):
    """ACT: decrement balance. Assumes caller verified."""
    _accounts[name] = _accounts.get(name, 0) - amount

def run_steps(steps):
    results = []
    for fn, args in steps:
        results.append(fn(*args))
    return results

def make_withdraw_steps(name, amount):
    """Split withdrawal into separate check and act steps.

    BUG: under interleaving, both checks pass before either debits.
    """
    result = {"approved": False}

    def step_check():
        result["approved"] = check_balance(name, amount)
        return ("check", result["approved"])

    def step_act():
        if check_balance(name, amount):  # Re-check balance before withdrawal
            do_withdraw(name, amount)
        return ("act", result["approved"])

    return step_check, step_act

def sequential_withdrawals():
    """Two withdrawals of 80 from balance=100. Sequential: second denied."""
