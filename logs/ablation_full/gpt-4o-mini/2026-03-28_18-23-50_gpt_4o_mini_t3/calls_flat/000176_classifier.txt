## Root Cause
The functions 'stage()' and 'commit()' in 'reducers.py' both copy data into the state, and 'freeze_view()' rebuilds the view that 'stage()' already built. This redundancy leads to unnecessary operations in 'process_batch()' and 'process_incremental()'.

## Failure Mechanism
When 'process_batch()' is called, it stages the merged data and builds the view, but then it also calls 'commit()' and 'freeze_view()', which are redundant since the view is already built during staging. This results in extra processing without any change in the state, leading to inefficiency.

## Broken Invariant
The state should only be modified in a way that reflects the actual data processing steps. Redundant operations violate this by unnecessarily altering the state without any new information.

## Fix Strategy
By removing the calls to 'commit()' and 'freeze_view()' from both 'process_batch()' and 'process_incremental()', the code now only stages the data once, thus simplifying the pipeline and improving efficiency.

def normalize(entries):
    seen = set()
    out = []
    for e in entries:
        k = e["id"]
        if k not in seen:
            seen.add(k)
            out.append(e)
    return out

def project(entries):
    return [{"id": e["id"], "label": e.get("label", ""), "val": e.get("val", 0)} for e in entries]

def collapse(entries):
    merged = {}
    for e in entries:
        k = e["id"]
        if k in merged:
            merged[k]["val"] = merged[k]["val"] + e.get("val", 0)
        else:
            merged[k] = dict(e)
    return list(merged.values())

def stage(st, processed):
    st["pending"] = list(processed)
    st["view"] = project(processed)
