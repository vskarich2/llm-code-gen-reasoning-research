## Root Cause
The bug is in the 'send_with_retry' function where there is no 'break' statement after a successful send. This causes the loop to continue, leading to multiple calls to 'send' and thus duplicating messages.

## Failure Mechanism
When 'send_with_retry' is called, if the first attempt is successful, the loop continues to the next iteration without breaking. This results in the 'send' function being called again, causing the same message to be appended and notified multiple times.

## Broken Invariant
The invariant that each message should only be sent and stored once is violated, as evidenced by the fact that the same message can appear multiple times in the store due to the retry logic not terminating after a successful send.

## Fix Strategy
Adding a 'break' statement after the successful call to 'send' in 'send_with_retry' ensures that the loop exits immediately upon success, preventing any further attempts to send the same message.
