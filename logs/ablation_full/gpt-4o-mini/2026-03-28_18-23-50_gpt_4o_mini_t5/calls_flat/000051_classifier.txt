## Root Cause
The bug is in the 'process_batch' function where the 'seen' set is defined as a default argument. This causes it to persist across multiple calls to the function, leading to valid tasks being skipped if they were processed in a previous call.

## Failure Mechanism
For example, if the first batch contains tasks 'A' and 'B', and both are processed, the 'seen' set will contain {'A', 'B'}. If a second batch contains task 'B' again, it will be skipped because 'B' is already in the 'seen' set, even though it is a valid task in the new batch.

## Broken Invariant
Each call to 'process_batch' with a fresh batch must process ALL tasks in that batch, regardless of prior calls. This is violated when valid tasks are skipped due to the persistent 'seen' set.

## Fix Strategy
By changing the definition of 'seen' to be a local variable within the 'process_batch' function instead of a default argument, the 'seen' set will be reset for each call, ensuring that all tasks in the current batch are processed.

# Code Produced
```python
def process_batch(tasks, seen=None):
    """Process a batch of tasks, skipping already-seen ones.

    Invariant: each call to process_batch with a fresh batch must
    process ALL tasks in that batch, regardless of prior calls.
    """
    if seen is None:
        seen = set()
    results = []
    for task in tasks:
        task_id = task["name"]
        if task_id in seen:
            continue
        seen.add(task_id)
        results.append({"name": task["name"], "result": "processed"})
    return results
```
