# Developer's Reasoning

## Root Cause
The bug is in the `apply_config` method of the `ConfigMiddleware` class, specifically with the variable `cfg`. It references the cached `_base` configuration, which is a mutable dictionary. When `cfg.update(request_overrides)` is called, it mutates the cached reference, causing subsequent requests to see the modified configuration.

## Failure Mechanism
If two requests are processed in sequence, the first request may modify the configuration by providing overrides. When the second request is processed, it will see the modified configuration instead of the original defaults, leading to unexpected behavior.

## Broken Invariant
Each request should operate with its own independent configuration, ensuring that overrides do not affect subsequent requests. This means that the configuration returned for each request must be a fresh copy, not a reference to a mutable object.

## Fix Strategy
The code change involves creating a copy of the base configuration in the `apply_config` method before applying any overrides. This ensures that each request receives a fresh configuration dictionary, preventing unintended side effects from previous requests.

# Code Produced
```python
from config import create_config


class ConfigMiddleware:
    """Middleware that loads config once and applies per-request overrides."""

    def __init__(self):
        self._base = create_config()  # cached at init time

    def apply_config(self, request_overrides=None):
        """Return config for this request, applying any overrides."""
        cfg = dict(self._base)  # Create a copy of the base config
        if request_overrides:
            cfg.update(request_overrides)  # Mutates the copy, not the cached reference
        return cfg

    def get_timeout(self):
        return self._base.get("timeout", 30)
```
