# Developer's Reasoning

## Root Cause
The bug is in the `update_product` function in `catalog.py`, specifically the lack of a call to `invalidate_local(product_id)`. This means that when a product is updated, the local cache is not invalidated, allowing stale data to persist.

## Failure Mechanism
When a product is updated using `update_product`, the local cache still holds the old data. If `get_product` is called afterward, it retrieves the stale data from the local cache instead of fetching the updated data from the database, leading to incorrect product information being displayed.

## Broken Invariant
After updating a product, all cache layers must reflect the most current data. The invariant is violated because the local cache still contains outdated information, which can be served to users.

## Fix Strategy
By adding a call to `invalidate_local(product_id)` in the `update_product` function, the local cache will be cleared of the outdated product data whenever an update occurs. This ensures that subsequent calls to `get_product` will fetch the updated data from the database.

_db = {}

def add_product(product_id, name, price):

    """Raw DB lookup."""
    p = _db.get(product_id)
    return dict(p) if p else None

def update_product(product_id, **fields):
    """Update product in DB and invalidate caches.

    Invariant: after update, all cache layers must be invalidated.
    """
    if product_id not in _db:
        return False
    _db[product_id].update(fields)
    invalidate_shared(product_id)
    invalidate_local(product_id)  # Added to invalidate local cache
    return True
