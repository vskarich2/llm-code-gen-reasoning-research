The bug is caused by the variable '_client_config' in 'client.py', which captures the configuration at import time by calling 'get_config()'. This means that any subsequent changes to the configuration, such as those made by 'reset_config()' or 'set_config()', will not affect '_client_config'.

For example, if 'set_config('timeout', 60)' is called after 'reset_config()', 'get_timeout()' will still return the old timeout value of 30 instead of the updated value of 60.

This ensures that any updates to the configuration are reflected immediately. The change is made by modifying the 'get_timeout()' and 'get_db_url()' functions to call 'get_config()' each time they are invoked.
