The bug occurs in the 'place_order' function where, upon a payment failure, the inventory reservation is not released. Specifically, the variable '_reserved' remains unchanged because the 'release' function is never called in the exception handling block.

## Failure Mechanism

This results in the inventory being stuck as reserved, preventing future orders for that product until the reservation is manually reset.

## Broken Invariant
The invariant that is violated is that inventory reservations must be released if a payment fails. Specifically, after a failed payment, the available stock should reflect the previously reserved quantity, ensuring that the system accurately represents the current inventory state.

## Fix Strategy
The fix involves adding a call to the 'release' function within the exception handling block of the 'place_order' function. This ensures that if a payment fails, the reserved quantity is released, restoring the inventory state to what it was before the reservation.
