## Root Cause
The function 'update_product' in 'api.py' calls both 'write_fresh' and 'write_cached', leading to redundant writes of product data. This redundancy can cause stale data issues since 'write_cached' does not update the version.

## Failure Mechanism
When 'update_product' is called, it first computes and writes fresh data with a new version using 'write_fresh'. Then, it may write stale cached data using 'write_cached', which does not update the version. This can result in the product data being read with an outdated version, leading to inconsistencies.

## Broken Invariant
The product data should always be written with the latest version when updated. The current implementation allows for a scenario where the version does not reflect the most recent write, violating the expectation that the latest data corresponds to the latest version.

## Fix Strategy
By removing the call to 'write_cached' in 'update_product', we ensure that only the fresh data is written with a version update. This change guarantees that the product data is always up-to-date and correctly versioned.
