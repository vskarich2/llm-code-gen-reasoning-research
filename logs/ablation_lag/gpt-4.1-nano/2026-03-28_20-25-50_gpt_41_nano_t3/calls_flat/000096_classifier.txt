# Developer's Reasoning

## Root Cause
In the place_order function, if wallet.charge(qty * price) raises a ValueError due to insufficient funds, the inventory reservation made earlier is not released, leading to an inconsistent state where inventory is reserved but not paid for.

## Failure Mechanism
When a customer attempts to place an order with insufficient wallet balance, the inventory.reserve(qty) call succeeds, reserving stock. However, the subsequent wallet.charge(qty * price) raises a ValueError, and because the exception is re-raised without releasing the reservation, the inventory remains reserved indefinitely, causing resource leakage and inconsistency.

## Broken Invariant
The inventory's reserved stock must be released if the wallet charge fails, ensuring that reserved inventory always corresponds to successfully paid orders.

## Fix Strategy
Adding a finally block that releases the inventory reservation if an exception occurs during wallet charging ensures that reservations are not left dangling, maintaining the invariant that reserved inventory only exists for confirmed payments.

"""Order fulfillment with inventory and wallet."""


class Inventory:
    def __init__(self, stock):
        self.stock = stock
        self.reserved = 0

    def reserve(self, qty):
        if qty > self.stock - self.reserved:
            raise ValueError("insufficient stock")
        self.reserved += qty

    def release(self, qty):
        self.reserved -= qty

    def available(self):
        return self.stock - self.reserved


class Wallet:
    def __init__(self, balance):
        self.balance = balance

    def charge(self, amount):
        if amount > self.balance:
            raise ValueError("insufficient funds")
        self.balance -= amount


def place_order(inventory, wallet, qty, price):
    """Reserve inventory, then charge wallet. Release on failure."""
    inventory.reserve(qty)
    try:
        wallet.charge(qty * price)
    except ValueError:

    finally:

            inventory.release(qty)
