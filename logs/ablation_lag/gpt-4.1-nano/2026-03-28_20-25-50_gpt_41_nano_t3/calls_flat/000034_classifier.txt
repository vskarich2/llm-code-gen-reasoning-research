## Root Cause
The update_product function in catalog.py updates the product data in the _db but only invalidates the shared cache via invalidate_shared(product_id). It does not invalidate the local cache, which may still hold stale data because get_product first checks the local cache before shared cache or database.

## Failure Mechanism
When a product is updated via update_product, the shared cache is invalidated but the local cache remains unchanged. Subsequent calls to get_product for that product_id will retrieve the stale data from the local cache, causing the API to return outdated product information despite the database being updated.

## Broken Invariant

## Fix Strategy
Adding invalidate_local(product_id) in update_product ensures that both cache layers are invalidated after a product update, forcing get_product to fetch fresh data from the database on subsequent calls, thus preventing stale data from being returned.
