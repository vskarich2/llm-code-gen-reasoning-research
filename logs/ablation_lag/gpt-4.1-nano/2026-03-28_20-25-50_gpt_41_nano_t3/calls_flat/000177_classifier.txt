# Developer's Reasoning

## Root Cause
In process_batch and process_incremental, the functions commit() and freeze_view() are called after stage(), which already updates the state with the merged data, and freeze_view() rebuilds the view from the stable data. This results in redundant copying of data into the state and unnecessary rebuilding of the view, violating the intended pipeline flow.

## Failure Mechanism
When process_batch or process_incremental are called, they invoke stage() to update pending and view, then call commit() to copy pending to stable, and freeze_view() to rebuild the view from stable. Since stage() already sets the view, and commit() and freeze_view() redundantly copy or rebuild the view, the pipeline performs unnecessary data copying and view rebuilding, leading to inefficiency and potential inconsistencies.

## Broken Invariant
The view in the state should be built once during stage() and should not be redundantly rebuilt or copied afterward, ensuring that the view always reflects the latest pending or stable data without unnecessary recomputation.

## Fix Strategy
Removing the calls to commit() and freeze_view() from process_batch and process_incremental eliminates redundant copying and rebuilding, relying solely on stage() to update the view. This simplifies the pipeline and maintains the invariant that the view is built during stage(), avoiding unnecessary operations.

def normalize(entries):
    seen = set()

        k = e["id"]
        if k not in seen:
            seen.add(k)
            out.append(e)
    return out


def project(entries):
    return [{"id": e["id"], "label": e.get("label", ""), "val": e.get("val", 0)} for e in entries]


def collapse(entries):
    merged = {}
    for e in entries:
        k = e["id"]
        if k in merged:
            merged[k]["val"] = merged[k]["val"] + e.get("val", 0)
        else:
            merged[k] = dict(e)
    return list(merged.values())


def stage(st, processed):
