## Root Cause
In the process_batch function, the snapshot() function is called only once after processing all items, which results in only a single snapshot being recorded regardless of the number of items processed. This occurs because snapshot() is called outside the for loop, so it does not record a snapshot after each individual item.

## Failure Mechanism
When process_batch is called with multiple items, the counter is incremented for each item, but only one snapshot is taken at the end. As a result, verify_consistency() reports fewer snapshots than the number of items processed, violating the expectation that each item should produce one snapshot.

## Broken Invariant
For each item processed in process_batch, exactly one snapshot should be recorded, so the number of snapshots should equal the total number of items processed.

## Fix Strategy
Move the call to snapshot() inside the for loop in process_batch so that a snapshot is taken after each item is processed, ensuring the number of snapshots matches the number of items processed.
