# Developer's Reasoning

## Root Cause
The process_batch function in worker.py uses a default argument 'seen=set()', which is evaluated once at function definition time, causing the same set to persist across multiple calls, including processing of subsequent batches.

## Failure Mechanism
When process_batch is called multiple times, the 'seen' set retains tasks from previous batches, leading to valid tasks in the second batch being recognized as duplicates and skipped, even if they are new and unprocessed in that batch.

## Broken Invariant
Each call to process_batch with a new batch of tasks must process all tasks in that batch, regardless of previous calls, and should not skip valid tasks due to prior state.

## Fix Strategy
Change the default value of 'seen' from a mutable default argument to None, and initialize a new set inside the function if 'seen' is None, ensuring each call starts with a fresh set, thus preventing state leakage across calls.
