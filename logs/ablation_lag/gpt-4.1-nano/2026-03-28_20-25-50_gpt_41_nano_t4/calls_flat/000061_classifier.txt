## Root Cause
In the process_batch function, the snapshot() function is called only once after processing all items, which results in only a single snapshot being recorded regardless of the number of items processed. This occurs because snapshot() is called outside the for loop, so it does not record a snapshot after each individual item.

## Failure Mechanism
When process_batch is called with multiple items, only one snapshot is taken at the end, failing to record the counter state after each item. This causes verify_consistency to report fewer snapshots than the number of items processed, violating the expectation that each item should produce one snapshot.

## Broken Invariant
For each item processed in process_batch, exactly one snapshot should be recorded, so that the number of snapshots equals the number of items processed.

## Fix Strategy
Moving the snapshot() call inside the for loop ensures that a snapshot is taken after each item, aligning the number of snapshots with the number of items processed, thus maintaining the invariant that each item produces one snapshot.
