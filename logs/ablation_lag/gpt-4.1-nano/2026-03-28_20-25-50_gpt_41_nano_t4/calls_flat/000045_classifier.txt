# Developer's Reasoning

## Root Cause
The client.py module assigns the value of get_config() to the variable _client_cfg at import time, capturing a reference to the config dictionary before any reset occurs. When reset_config() is called in config.py, _config is set to None, and subsequent get_config() calls return a new dictionary, but _client_cfg in client.py still points to the old, stale dictionary.

## Failure Mechanism
After calling reset_config() in config.py, the global _config becomes None, and get_config() loads a new dictionary. However, since _client_cfg was assigned at import time to the old config dictionary, it does not reflect the updated configuration. As a result, functions like get_api_key() and get_base_url() in client.py return outdated values, causing the client to operate with stale configuration data.

## Broken Invariant
The variable _client_cfg in client.py must always reference the current configuration dictionary returned by get_config(), ensuring that any configuration resets are propagated to the client functions.

## Fix Strategy
Remove the static assignment of _client_cfg in client.py and instead call get_config() within each client function to retrieve the latest configuration, ensuring that resets in config.py are reflected immediately. This change makes the client functions always access the current config, maintaining the invariant that they reflect the latest configuration state.
