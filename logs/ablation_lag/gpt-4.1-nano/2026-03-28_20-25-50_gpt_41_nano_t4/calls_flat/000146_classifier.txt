## Root Cause
In payment.py, the process_payment function returns early when a transaction ID is found in _cache, skipping the call to record() and thus not recording duplicate transactions in the ledger.

## Failure Mechanism
When process_payment is called with a duplicate txn_id, it returns the cached result without calling record(), causing the ledger to miss recording this transaction. As a result, the ledger's transaction count does not match the number of process_payment calls, leading verify() to fail if expected_count includes duplicates.

## Broken Invariant

## Fix Strategy
Remove the early return that skips recording for duplicate txn_ids, ensuring record() is called on every process_payment invocation, so the ledger's count matches the total number of calls.

_cache = {}

def process_payment(txn_id, amount):

    Every call — including duplicates — must be recorded in the ledger
    so that verify() counts match total process_payment calls.
    """

    record(txn_id, amount, "charged")
    _cache[txn_id] = result
    return result
