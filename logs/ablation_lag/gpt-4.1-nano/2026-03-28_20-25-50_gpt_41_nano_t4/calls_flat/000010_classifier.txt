# Developer's Reasoning

## Root Cause
In config.py, the create_config() function assigns DEFAULTS directly to the variable 'config', which means it returns a reference to the original DEFAULTS dictionary instead of a copy. Consequently, when apply_config() in middleware.py calls self._base = create_config(), self._base references DEFAULTS. Later, in apply_config(), cfg.update(request_overrides) mutates this shared DEFAULTS reference, causing side effects across all instances and requests.

## Failure Mechanism
When handle_request() or handle_debug_request() invoke apply_config() via middleware, the first call sets self._base to DEFAULTS. If a request provides overrides, apply_config() updates the shared DEFAULTS dictionary directly, altering the default configuration globally. Subsequent requests then inherit these mutated defaults, leading to inconsistent or unintended configuration states.

## Broken Invariant
The middleware's self._base should remain immutable and represent the original default configuration, ensuring that per-request overrides do not mutate shared state. Specifically, apply_config() must not mutate self._base or DEFAULTS, but should instead work on a copy to preserve invariants across requests.

## Fix Strategy
I modified create_config() to return a shallow copy of DEFAULTS using dict(DEFAULTS), ensuring that each call produces an independent configuration dictionary. This prevents apply_config() from mutating shared defaults, maintaining the integrity of the default configuration across requests.

class ConfigMiddleware:
    """Middleware that loads config once and applies per-request overrides."""

    def __init__(self):
        self._base = create_config()  # cached at init time

    def apply_config(self, request_overrides=None):
        """Return config for this request, applying any overrides."""
        cfg = dict(self._base)  # work on a copy to prevent mutation
