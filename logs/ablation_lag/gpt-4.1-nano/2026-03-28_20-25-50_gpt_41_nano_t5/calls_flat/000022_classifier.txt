## Root Cause
In the update_profile function, when the email is changed and validated, the code updates user['email'] but does not set user['verified'] to False or clear user['cached_greeting'].

## Failure Mechanism
When a user updates their email address, the system updates the email field but leaves the 'verified' status as True and retains the old cached greeting, causing the greeting to display the old name even after the email change.

## Broken Invariant
Changing the email address should set user['verified'] to False and clear user['cached_greeting'] so that the greeting reflects the new name and the email requires re-verification.

## Fix Strategy
Adding 'user["verified"] = False' and 'user["cached_greeting"] = None' inside the email change branch ensures the user's verification status is reset and the greeting cache is cleared, prompting regeneration with the updated name.
