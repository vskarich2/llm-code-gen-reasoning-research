# Developer's Reasoning

## Root Cause
The process_batch function in worker.py uses a default argument 'seen=set()', which is evaluated only once at function definition time, causing the set to persist across multiple calls. This leads to valid tasks being skipped in subsequent batches if their IDs are already in the persistent 'seen' set.

## Failure Mechanism
When process_batch is called multiple times with different task batches, the 'seen' set retains tasks from previous calls. As a result, tasks in later batches that are valid and not duplicates within that batch are skipped if their IDs are present in the persistent 'seen' set, causing valid tasks to be ignored on the second batch.

## Broken Invariant
Each call to process_batch with a new batch must process all tasks in that batch, regardless of previous calls, and the 'seen' set should only contain tasks from the current batch processing context.

## Fix Strategy
Changing the default argument 'seen=set()' to 'seen=None' and initializing 'seen' to an empty set within the function if it is None ensures that each call to process_batch starts with a fresh 'seen' set, preventing cross-call persistence and ensuring all tasks in each batch are processed appropriately.

"""Worker that processes task batches."""

from queue import create_task


def process_batch(tasks, seen=None):
    """Process a batch of tasks, skipping already-seen ones.

    Invariant: each call to process_batch with a fresh batch must
    process ALL tasks in that batch, regardless of prior calls.
    """
    # Initialize seen set if not provided
    if seen is None:
        seen = set()
    results = []
    for task in tasks:
        task_id = task["name"]
        if task_id in seen:
            continue
        seen.add(task_id)
        results.append({"name": task["name"], "result": "processed"})
    return results

    return f"{len(results)} tasks processed"
