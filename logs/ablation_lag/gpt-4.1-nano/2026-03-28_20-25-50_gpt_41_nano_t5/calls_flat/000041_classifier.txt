# Developer's Reasoning

## Root Cause
The client.py module captures the configuration in the variable _client_config at import time by calling get_config(), which loads the config only once. Therefore, subsequent calls to reset_config() do not affect _client_config, and the client continues to use the old configuration values.

## Failure Mechanism
When reset_config() is called, it resets the global _config variable in config.py, but since client.py has already captured _client_config at import time, it continues to use the stale configuration stored in _client_config. As a result, get_timeout() still returns the old timeout value, ignoring the reset.

## Broken Invariant
The client should always use the latest configuration values returned by get_config(), especially after reset_config() is called, but currently it uses a cached configuration captured at import time.

## Fix Strategy
By removing the initial capture of get_config() into _client_config and instead calling get_config() dynamically within get_db_url() and get_timeout(), the client will always retrieve the current configuration, including after reset_config() is invoked.
