# Developer's Reasoning

## Root Cause
The process() function is called before init() has been executed, and since process() checks the _initialized flag, it logs an error and skips processing if init() has not yet run. In the broken_order() scenario, process('a') is invoked before init(), causing the item 'a' to be lost because it is not processed after initialization.

## Failure Mechanism
When run_steps executes process('a') before init(), _initialized is False, so process() logs an error and returns False without processing 'a'. Subsequent calls to process('b') and shutdown() proceed normally, but 'a' is never processed or logged as processed, leading to loss of item 'a' in the log.

## Broken Invariant
All items passed to process() must be processed and logged as 'processed:item' after init() has been called, regardless of the order in which process() is invoked relative to init().

## Fix Strategy
Modify run_steps to buffer items received by process() before init() is called, and process all buffered items once init() runs, ensuring that all items are eventually processed after initialization, regardless of their arrival order.



# Task Description
process() runs before init() and items are lost. Fix so all items are processed regardless of arrival order.

    global _initialized, _buffer
    _initialized = True
    # Process any buffered items
    for item in _buffer:

    """Buffer items if not initialized; process immediately if initialized."""
    if not _initialized:
        _buffer.append(item)
        return False
    _log.append(f"processed:{item}")
    return True


def shutdown():
    _log.append("shutdown")
    return list(_log)


def get_log():
    return list(_log)


def run_steps(steps):
    results = []
    for fn, args in steps:
        results.append(fn(*args))
    return results
