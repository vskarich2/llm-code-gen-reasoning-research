## Root Cause
The function make_withdraw_steps creates separate check and act steps that rely on a shared 'result' dictionary. During interleaving, both check steps for two withdrawals pass before either act step executes, because the check_balance function does not account for prior withdrawals. As a result, both checks approve, leading to both withdrawals being executed, which causes the balance to go negative.

## Failure Mechanism
In interleaved_withdrawals, the sequence runs check_a, check_b, then act_a, act_b. Both check steps see the initial balance of 100 as sufficient (>=80), so both approve. When act_a and act_b execute, they each deduct 80, resulting in a total deduction of 160 from the initial 100, leaving the balance at -60, violating the invariant that balance should never be negative.

## Broken Invariant
The account balance must never become negative after any sequence of withdrawals, i.e., get_balance('alice') >= 0 at all times, regardless of the interleaving of check and act steps.

## Fix Strategy
Modify make_withdraw_steps to perform the check and withdrawal atomically within a single function, or implement a locking mechanism or check-then-act pattern that verifies the balance again immediately before withdrawal, ensuring that no overdraft occurs even under interleaving. In the provided fix, the check and withdrawal are combined into a single step that re-verifies the balance before doing the withdrawal, preventing overdraft.

"""Bank with non-atomic check-then-act withdrawal, simulated via steps."""

_accounts = {}

def reset():
    _accounts.clear()

def create_account(name, balance):
    _accounts[name] = balance

def get_balance(name):
    return _accounts.get(name, 0)

def check_balance(name, amount):
    """CHECK: is balance sufficient?"""
    return _accounts.get(name, 0) >= amount

def do_withdraw(name, amount):
    """ACT: decrement balance. Assumes caller verified."""
    _accounts[name] = _accounts.get(name, 0) - amount

def run_steps(steps):
    results = []
    for fn, args in steps:
        results.append(fn(*args))
    return results

def make_withdraw_steps(name, amount):
    """Split withdrawal into separate check and act steps.

    BUG: under interleaving, both checks pass before either debits.
    """
    result = {"approved": False}

    def step_check():
        result["approved"] = check_balance(name, amount)
        return ("check", result["approved"])

    def step_act():
        if result["approved"]:
            do_withdraw(name, amount)
        return ("act", result["approved"])

    return step_check, step_act

def sequential_withdrawals():
    """Two withdrawals of 80 from balance=100. Sequential: second denied."""
    reset()
    create_account("alice", 100)
    check_a, act_a = make_withdraw_steps("alice", 80)
    check_b, act_b = make_withdraw_steps("alice", 80)
    run_steps([(check_a, ()), (act_a, ()), (check_b, ()), (act_b, ())])
    return get_balance("alice")
