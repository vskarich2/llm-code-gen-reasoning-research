# Developer's Reasoning

## Root Cause
The update_product function modifies the _db dictionary directly without invalidating the cache entry for the product_id, causing the cache to hold stale data after updates.

## Failure Mechanism
When update_product is called to change a product's details, the cache for that product_id remains unchanged. Subsequent calls to get_product retrieve the outdated cached data instead of the updated product information, leading to products showing old prices after updates.

## Broken Invariant
After calling update_product with new product fields, get_product(product_id) must return the latest product data, reflecting all updates, and not stale cached data.

## Fix Strategy
Adding a call to invalidate(product_id) within update_product ensures that the cache entry for the product is cleared whenever the product is updated, forcing get_product to fetch fresh data from _db on the next call.

```python
"""Product catalog using external cache module."""

from cache import get, put, invalidate

_db = {}


def add_product(product_id, name, price):
    """Add a product to the database."""
    _db[product_id] = {"name": name, "price": price}


def get_product(product_id):
    """Get product, checking cache first."""
    cached = get(product_id)
    if cached is not None:
        return cached
    product = _db.get(product_id)
    if product is not None:
        put(product_id, dict(product))
    return _db.get(product_id)


def update_product(product_id, **fields):
    """Update product in DB.

    Invariant: subsequent get_product() must reflect the update.
    """
    if product_id not in _db:
        return False
    _db[product_id].update(fields)
    invalidate(product_id)  # Invalidate cache to ensure fresh data
    return True


def reset():
    """Clear DB and cache."""
    _db.clear()
    from cache import clear
    clear()

```
