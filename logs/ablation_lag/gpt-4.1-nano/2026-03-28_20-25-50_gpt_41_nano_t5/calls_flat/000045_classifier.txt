# Developer's Reasoning

## Root Cause
The client.py module captures the config dictionary reference at import time by assigning _client_cfg = get_config() during module load, which is before any reset or modification of the config. Consequently, subsequent calls to get_config() in client.py do not reflect updates made after the initial import.

## Failure Mechanism
When reset_config() is called in config.py, _config is set to None, and get_config() loads a new dictionary. However, _client_cfg in client.py still points to the old, stale dictionary captured at import time. As a result, get_api_key() and get_base_url() in client.py return outdated values, causing the client to operate with stale configuration data.

## Broken Invariant
The client module's _client_cfg must always reflect the current configuration state, such that get_api_key() and get_base_url() return the latest values after any reset or update to the configuration.

## Fix Strategy
Remove the static assignment of _client_cfg in client.py and instead call get_config() within each function to retrieve the current configuration, ensuring that the latest config is always used. This change makes the client functions dynamically fetch the current config rather than relying on a stale snapshot.

    """Lazy-load config."""
    global _config
    if _config is None:

    """Reset config for testing or reload."""
    global _config

    """Override a single config value."""
    cfg = get_config()
