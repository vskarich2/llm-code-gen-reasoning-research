## Root Cause
In the process_batch function, the snapshot() function is called only once after processing all items, which results in only a single snapshot regardless of the number of items processed. This occurs because snapshot() is called outside the for loop, so it does not record the counter state after each individual item.

## Failure Mechanism
When process_batch is called with multiple items, the counter is incremented for each item, but only one snapshot is taken at the end. As a result, verify_consistency() will report only one snapshot for multiple items, violating the expectation that each item should produce a snapshot.

## Broken Invariant
For each item processed in process_batch, exactly one snapshot should be recorded, so that the number of snapshots equals the number of items processed.

## Fix Strategy
Move the call to snapshot() inside the for loop in process_batch so that a snapshot is taken after each item is processed, ensuring the number of snapshots matches the number of items processed.
