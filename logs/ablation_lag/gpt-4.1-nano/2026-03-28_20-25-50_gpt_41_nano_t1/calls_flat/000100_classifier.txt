# Developer's Reasoning

## Root Cause
In the order_service.py, the place_order function calls reserve() to reserve inventory but does not call release() to free the reservation if the payment process fails, leaving the inventory in a reserved state after a payment failure.

## Failure Mechanism
When a payment fails during place_order, the exception is raised and the function exits without releasing the reserved inventory, causing the inventory to remain reserved even though the order was not completed, leading to inventory being stuck as reserved after payment failure.

## Broken Invariant
The inventory reservation for a product must be released if the payment process fails, ensuring that available stock reflects only unreserved inventory after a failed payment attempt.

## Fix Strategy
Adding a call to release(product_id, qty) inside the except block in place_order ensures that the reservation is freed when payment fails, maintaining the invariant that reserved inventory is only for successful orders.

    _notifications = []
    _gateway_fail = False
    _stock = {}
    _reserved = {}


def set_gateway_fail(fail):
    """Configure gateway to simulate payment failure."""
    global _gateway_fail
    _gateway_fail = fail


def _process_payment(amount):
    """Simulate payment gateway."""
    if _gateway_fail:
        raise ValueError("payment declined")
    return {"paid": amount}


def place_order(product_id, qty, price):
    """Place an order: reserve inventory, process payment, notify.

    If payment fails, inventory reservation should be rolled back.
    """
    reserve(product_id, qty)
    try:
        result = _process_payment(qty * price)
    except ValueError:
        release(product_id, qty)
        raise  # Fix: release reservation on payment failure
    _notifications.append({"product": product_id, "qty": qty})
    return {"status": "confirmed", "payment": result}


def get_notifications():
    return list(_notifications)
