## Root Cause
The update_record function calls cache_invalidate(key) followed immediately by cache_set(key, value), which is redundant because cache_set overwrites the cache entry without needing prior invalidation.

## Failure Mechanism
When update_record is invoked, it first invalidates the cache for the key, removing the cached value, and then sets the cache again with the new value. This unnecessary invalidation step causes a brief window where the cache is empty, which could lead to cache misses or race conditions if other processes access the cache in between, and it also introduces redundant operations that do not contribute to correctness.

## Broken Invariant
The cache should be updated atomically with a single set operation, ensuring that the cache always contains the latest value after update_record is called, without unnecessary invalidation steps.

## Fix Strategy
Removing the cache_invalidate call from update_record eliminates the redundant invalidation, allowing cache_set to directly update the cache with the new value, thus maintaining cache correctness with fewer operations.
