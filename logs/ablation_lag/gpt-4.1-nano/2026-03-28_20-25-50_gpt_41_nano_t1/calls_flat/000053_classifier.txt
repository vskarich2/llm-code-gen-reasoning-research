## Root Cause
The process_batch function in worker.py uses a default argument 'seen=set()', which is evaluated only once at function definition time, causing the set to persist across multiple calls. This leads to valid tasks being skipped in subsequent batches if their 'name' was seen in previous calls.

## Failure Mechanism
When process_batch is called multiple times with different task batches, the 'seen' set retains its state from previous calls, causing tasks with the same 'name' in later batches to be incorrectly identified as duplicates and skipped, even if they are valid and new in the current batch.

## Broken Invariant
Each call to process_batch with a new batch must process all tasks in that batch, regardless of previous calls, and should not skip valid tasks based on prior batch processing.

## Fix Strategy
Changing the default argument 'seen=set()' to 'seen=None' and initializing 'seen' to an empty set within the function if it is None ensures that each call to process_batch starts with a fresh set, preventing the persistence of seen tasks across calls.
