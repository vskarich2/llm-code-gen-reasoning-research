# Developer's Reasoning

## Root Cause
In the add_entry function, when a position is specified, the label is inserted at the given index using _labels.insert(position, label), but the value is always appended to _values with _values.append(value). This causes the label and value arrays to become misaligned, as the value is not inserted at the corresponding position, breaking the parallel structure.

## Failure Mechanism
When add_entry is called with a specific position, the label is inserted at that position in _labels, but the value is appended to _values, resulting in the label and value arrays being out of sync. This misalignment causes get_entry and get_all to return incorrect label-value pairs, leading to inconsistent report data.

## Broken Invariant
The _labels and _values arrays must always have the same length, and the label and value at each index must correspond to each other.

## Fix Strategy
Changing the add_entry function to insert the value at the same position in _values as the label is inserted in _labels ensures both arrays remain aligned. Specifically, replacing _values.append(value) with _values.insert(position, value) when position is provided fixes the misalignment.

_values = []


def add_entry(label, value, position=None):
    """Add an entry to the report.

    If position is given, insert at that index.
    Otherwise, append to the end.
    """
    if position is not None:
        _labels.insert(position, label)
        # Fix: insert value at the same position to keep arrays aligned
        _values.insert(position, value)
    else:
        _labels.append(label)
        _values.append(value)


def get_entry(index):
    """Return (label, value) at the given index."""

    """Return list of (label, value) tuples."""
