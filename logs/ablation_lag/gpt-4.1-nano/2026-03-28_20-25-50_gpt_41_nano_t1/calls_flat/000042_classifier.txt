# Developer's Reasoning

## Root Cause
The client.py module captures the configuration in the variable _client_config at import time by calling get_config(), which loads the config only once. Therefore, subsequent calls to get_config() or reset_config() do not affect _client_config, causing the client to use stale configuration values.

## Failure Mechanism
When reset_config() is called, it resets the global _config variable in config.py, but the client still uses the previously captured _client_config variable, which was set at import time. As a result, get_timeout() returns the old timeout value, ignoring the reset.

## Broken Invariant
The client should always reflect the current configuration values returned by get_config(), including after reset_config() is called.

## Fix Strategy
By removing the eager capture of get_config() into _client_config at import time, the client will call get_config() each time get_timeout() or get_db_url() is invoked, ensuring it always uses the latest configuration. This guarantees that reset_config() updates the configuration used by the client.
