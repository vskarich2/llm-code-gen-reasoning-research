# Developer's Reasoning

## Root Cause
The client.py module captures the config dictionary reference at import time by assigning _client_cfg = get_config() during module load, which is before any reset_config() call. When reset_config() is called, it sets _config to None in config.py, but _client_cfg in client.py still points to the old config dictionary, causing get_api_key() and get_base_url() to return stale values.

## Failure Mechanism
After calling reset_config() in config.py, the global _config is set to None, but since _client_cfg in client.py was assigned at import time to the original config dictionary, it does not reflect the reset. Consequently, make_request() and health_check() in handler.py use outdated config values, leading to inconsistent or incorrect behavior when configuration is changed at runtime.

## Broken Invariant
The client configuration used by get_api_key() and get_base_url() must always reflect the current state of the configuration after reset_config() is called, ensuring that any changes to the config are propagated to the client functions.

## Fix Strategy
Remove the static assignment of _client_cfg in client.py and instead call get_config() within each function that needs the current configuration. This ensures that each call retrieves the latest config, including after reset_config() is invoked.
