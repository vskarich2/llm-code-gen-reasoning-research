# Developer's Reasoning

## Root Cause
The function make_withdraw_steps creates separate check and act steps that rely on a shared 'result' dictionary. During interleaving, both check steps for two separate withdrawals pass before either act step executes, because the check_balance function only verifies the current balance without considering concurrent modifications. As a result, both checks approve the withdrawal, and both act steps proceed, leading to an overdraft when both withdrawals of 80 are executed from a 100 balance.

## Failure Mechanism
In interleaved execution, check steps for two separate withdrawals both return True because the balance is still 100 at the time of each check. Both withdrawals are then executed, each subtracting 80, resulting in a final balance of -60, which violates the invariant that the balance should never be negative.

## Broken Invariant
The account balance must never become negative after any sequence of withdrawal steps, regardless of interleaving or concurrency, i.e., get_balance(name) >= 0 after any withdrawal operation.

## Fix Strategy
Modify the do_withdraw function to check the current balance before subtracting the amount, ensuring that the withdrawal only proceeds if the balance is sufficient at the moment of execution. This prevents overdrafts caused by race conditions in interleaved scenarios.



# Task Description
Under interleaving, two withdrawals of 80 from balance=100 both succeed, leaving -60. Fix so balance never goes negative.

def reset():

def create_account(name, balance):

def check_balance(name, amount):
    """CHECK: is balance sufficient?"""
    return _accounts.get(name, 0) >= amount

def do_withdraw(name, amount):
    """ACT: decrement balance. Assumes caller verified."""
    # Check current balance before withdrawal to prevent overdraft
    current_balance = _accounts.get(name, 0)
    if current_balance >= amount:
        _accounts[name] = current_balance - amount


def run_steps(steps):
    results = []
    for fn, args in steps:
        results.append(fn(*args))
    return results

def make_withdraw_steps(name, amount):
    """Split withdrawal into separate check and act steps.

    BUG: under interleaving, both checks pass before either debits.
    """
    result = {"approved": False}

    def step_check():
        result["approved"] = check_balance(name, amount)
        return ("check", result["approved"])

    def step_act():
        if result["approved"]:
            do_withdraw(name, amount)
        return ("act", result["approved"])

    return step_check, step_act
