# Developer's Reasoning

## Root Cause
The function update_product in catalog.py updates the product data in the database but only invalidates the shared cache layer using invalidate_shared(product_id). It does not invalidate the local cache layer, which may still hold stale product data.

## Failure Mechanism
When a product is updated via update_product, the shared cache is invalidated but the local cache remains unchanged. Subsequent calls to get_product will first check the local cache, find stale data, and return it without fetching the updated data from the database, leading to stale product data being returned despite updates.

## Broken Invariant
After update_product is called for a product_id, both the local and shared cache layers must be invalidated so that subsequent get_product calls fetch fresh data from the database.

## Fix Strategy
Adding invalidate_local(product_id) in update_product ensures that both cache layers are invalidated after a product update, preventing stale data from being returned from the local cache layer.

def add_product(product_id, name, price):

    _db[product_id] = {"name": name, "price": price}


def db_get(product_id):
    """Raw DB lookup."""
    p = _db.get(product_id)
    return dict(p) if p else None


def update_product(product_id, **fields):
    """Update product in DB and invalidate caches.

    Invariant: after update, all cache layers must be invalidated.
    """
    if product_id not in _db:
        return False
    _db[product_id].update(fields)
    invalidate_shared(product_id)
    invalidate_local(product_id)
    return True
