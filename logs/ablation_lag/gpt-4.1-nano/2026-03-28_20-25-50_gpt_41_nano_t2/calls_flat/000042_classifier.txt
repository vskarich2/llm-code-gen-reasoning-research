# Developer's Reasoning

## Root Cause
The client.py module captures the configuration in the variable _client_config at import time by calling get_config(), which loads the config only once. Resetting the config via reset_config() in config.py does not update _client_config, so subsequent calls to get_db_url() and get_timeout() use the stale, initially loaded configuration.

## Failure Mechanism
After calling reset_config() to clear the cached configuration, the client still returns the old timeout value because _client_config was set during import and is not refreshed. For example, if the timeout is changed to 60 after reset_config(), get_timeout() still returns 30, the old value, leading to inconsistent behavior.

## Broken Invariant
The client should always reflect the current configuration state, so get_timeout() must return the latest timeout value after reset_config() is called, not the initial cached value.

## Fix Strategy
By removing the eager capture of get_config() into _client_config and instead calling get_config() within get_db_url() and get_timeout() functions, the client retrieves the latest configuration each time these functions are called, ensuring it reflects the current config after reset_config().
