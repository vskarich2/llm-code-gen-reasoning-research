## Root Cause
The bug is in the module-level variable _default_host and the get_host function: _default_host is assigned once at import with _settings["host"] (line: _default_host = _settings["host"]). get_host() returns that captured _default_host instead of reading the live _settings, so it never reflects later updates to _settings.

## Failure Mechanism
If code calls configure(host='example.com') to change the host, _settings['host'] becomes 'example.com' but _default_host remains the original 'localhost'. Subsequent calls to get_host() still return 'localhost' because get_host() returns the stale _default_host. Similarly, reset_settings() replaces _settings but does not update _default_host, so get_host() can return a value inconsistent with the current _settings.

## Broken Invariant
The module violates the invariant: after configure(host=X) or reset_settings(), get_host() must return the current value of _settings['host']. This is a specific, testable requirement (e.g., configure(host='x'); assert get_host() == 'x'), and it fails because get_host() reads _default_host captured at import time.

## Fix Strategy

This ensures configure(...) and reset_settings() updates are observed by get_host() immediately. No other behavior was changed; get_settings still returns a copy and configure still mutates the current _settings dict.
