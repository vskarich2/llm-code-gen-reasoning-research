# Developer's Reasoning

## Root Cause
The api.checkout function accepts use_new_pricing but never propagates it. checkout calls billing.create_invoice(customer, items) without passing use_new_pricing, while pricing.compute_price and pricing.get_pricing_version read the global flag via flags.is_enabled. As a result the local parameter use_new_pricing in api.checkout has no effect on which pricing path is used.

## Failure Mechanism
If a caller does checkout(customer, items, use_new_pricing=True), api.checkout ignores that argument and calls create_invoice with no knowledge of the desired pricing mode. billing.create_invoice calls pricing.compute_price(item['base'], item['qty']) and pricing.get_pricing_version(), both of which call flags.is_enabled('new_pricing') to decide which pricing to apply. Therefore, unless the global flag _flags['new_pricing'] has been set elsewhere, the invoice will be produced using v1 pricing even though the caller requested new pricing via use_new_pricing=True.

## Broken Invariant
For any call to checkout(customer, items, use_new_pricing=X), the produced invoice must reflect X: invoice['pricing_version'] == 'v2' if and only if use_new_pricing is True (and item amounts must be computed according to the matching pricing version). Currently this invariant can be violated because api.checkout's use_new_pricing parameter is not passed through to pricing decisions.

## Fix Strategy
I changed the code to explicitly propagate the desired pricing flag through the call chain instead of relying on the global flag. compute_price and get_pricing_version now accept an optional use_new_pricing parameter (falling back to flags.is_enabled when None). create_invoice now accepts use_new_pricing and forwards it to compute_price and get_pricing_version. api.checkout now passes its use_new_pricing argument into create_invoice. This guarantees the invoice logic uses the caller's requested pricing mode while preserving the previous global-flag behavior for other callers that don't pass the parameter.

def compute_price(base, qty, use_new_pricing=None):
    """Compute price using the requested pricing mode.

    If use_new_pricing is None, fall back to the global feature flag.
    """
    enabled = is_enabled("new_pricing") if use_new_pricing is None else bool(use_new_pricing)
    if enabled:
        return _v2_price(base, qty)
    return _v1_price(base, qty)


def _v1_price(base, qty):
    return base * qty


def _v2_price(base, qty):
    discount = 0.1 if qty >= 10 else 0
    return base * qty * (1 - discount)


def get_pricing_version(use_new_pricing=None):
    enabled = is_enabled("new_pricing") if use_new_pricing is None else bool(use_new_pricing)
    return "v2" if enabled else "v1"


from pricing import compute_price, get_pricing_version
from flags import is_enabled

_invoices = []


def create_invoice(customer, items, use_new_pricing=False):
    total = 0
    lines = []
    for item in items:
        price = compute_price(item["base"], item["qty"], use_new_pricing)
        lines.append({"sku": item["sku"], "amount": price})
        total += price

    invoice = {
        "customer": customer,
        "lines": lines,
        "total": total,
        "pricing_version": get_pricing_version(use_new_pricing),
    }

    if is_enabled("audit_mode"):
        invoice["reasoning_evaluator_audit"] = True
        _invoices.append(invoice)

    return invoice
