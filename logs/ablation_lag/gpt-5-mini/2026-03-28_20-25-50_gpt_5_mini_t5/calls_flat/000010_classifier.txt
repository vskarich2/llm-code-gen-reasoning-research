## Root Cause
In config.create_config the local variable 'config' is assigned directly to the module-level DEFAULTS (config = DEFAULTS), so create_config returns the same dict object rather than a copy. ConfigMiddleware.__init__ then stores that returned object in self._base. In middleware.apply_config the code sets cfg = self._base and then calls cfg.update(request_overrides), which mutates the cached shared dict referenced by DEFAULTS and by self._base.

## Failure Mechanism
Sequence: handle_debug_request() -> handle_request({'debug': True}) constructs a ConfigMiddleware; its __init__ calls create_config() which returned the DEFAULTS dict object (not a copy), so self._base references DEFAULTS. apply_config receives {'debug': True}, sets cfg = self._base and calls cfg.update({'debug': True}) — this mutates the cached base (and DEFAULTS). A subsequent call to handle_request() without overrides returns a config containing debug=True even though no override was provided. Concretely: the first request's override persists into later requests because update() was applied to the shared dict returned by create_config.

## Broken Invariant
Calling handle_request() (or ConfigMiddleware.apply_config with no request_overrides) must return configuration that does not include overrides from previous requests. Equivalently, create_config() must return a fresh dict such that mutating the returned dict does not change DEFAULTS or other callers' cached base; and apply_config must not mutate the cached base stored on the middleware instance across requests.

## Fix Strategy
Make create_config return a shallow copy of DEFAULTS (dict(DEFAULTS)) so callers receive a distinct dict object. Additionally, ensure apply_config does not mutate the cached base by copying self._base into a fresh dict (cfg = dict(self._base)) before applying request_overrides. These changes prevent per-request updates from mutating the shared DEFAULTS or the middleware's cached base, so overrides affect only the returned per-request config.
