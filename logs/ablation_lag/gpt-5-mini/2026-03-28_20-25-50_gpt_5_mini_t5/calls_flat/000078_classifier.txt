# Developer's Reasoning

## Root Cause
In code_snippets_v2/use_before_set_b/loader.py the function load() uses the expression `if source and len(source) > 0:` and only assigns to the module state variables `_status` and `_data` inside that branch. As a result, when `source` is empty/None (or when `len(source)` raises because the source is a non-sized iterable like a generator), `_status` is not updated and `_data` is not cleared. The bug is therefore in loader.load: it both relies on `len(source)` (which can raise) and fails to set `_status` for empty inputs, leaving stale values in `_status`/_data.

## Failure Mechanism
Concrete scenario: pipeline.run_pipeline(iter(())) or run_pipeline(some_generator) calls load(source). In load, the test `if source and len(source) > 0:` attempts to evaluate `len(source)` on a generator (no __len__), which raises TypeError and propagates out of load to pipeline.run_pipeline, causing the pipeline to crash. Alternatively, if source is a sized empty list `[]`, the `if` branch is false and load returns without setting `_status` or clearing `_data`, so `_status` retains the previous 'loaded' value and stale `_data` is returned — violating the contract that status must reflect THIS call's outcome.

## Broken Invariant
After run_pipeline(source) completes, get_status() must reflect the outcome of that call: it must be exactly 'loaded' when the provided source yields one or more items, and exactly 'empty' when the provided source yields zero items or is None. This is a specific, testable invariant: for any sequence/iterable source, calling run_pipeline(source) must produce a response where response['status'] == ('loaded' if len(list(source))>0 else 'empty').

## Fix Strategy
I changed loader.load so it no longer calls len(source) directly and always updates both `_data` and `_status` for every call. The function now: (1) converts source safely to a list via `list(source)` when source is not None (this accepts generators/iterators without calling len on them), (2) sets `_data` to that list (or `[]` for None), and (3) sets `_status` to 'loaded' if the resulting list is non-empty, otherwise to 'empty'. This prevents the TypeError from len() on non-sized iterables, clears stale `_data`, and guarantees the status reflects the current call.
