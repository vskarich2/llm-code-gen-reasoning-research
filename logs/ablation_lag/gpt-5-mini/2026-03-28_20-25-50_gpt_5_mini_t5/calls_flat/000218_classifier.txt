# Developer's Reasoning

## Root Cause
The bug is in make_increment_steps(): its nested function step_write uses the stale value captured['current'] (populated earlier by step_read) instead of reading the live counter via get(). Because step_write writes captured['current'] + 1, it writes based on an earlier read rather than the current _value.

## Failure Mechanism
Concrete interleaving that demonstrates the failure: reset() sets _value = 0; read_a() (from make_increment_steps() for increment A) stores capturedA['current'] = 0; read_b() stores capturedB['current'] = 0; write_a() executes _set(capturedA['current'] + 1) -> _set(1); write_b() executes _set(capturedB['current'] + 1) -> _set(1). The second write overwrites the first because it used the stale capturedB value 0, resulting in final get() == 1 instead of 2.

## Broken Invariant
After performing two increments (two read/write step pairs produced by make_increment_steps()) in any interleaving of the four steps, get() must equal 2. Currently, interleaving read_a, read_b, write_a, write_b produces get() == 1, violating that invariant.

## Fix Strategy
Modify step_write to read the current _value at write time (call get()), compute new = current + 1, and call _set(new). This removes reliance on the stale captured['current'] value and ensures each write increments the live counter value; e.g., in the interleaving read_a/read_b/write_a/write_b, write_b will read the updated value written by write_a and increment it to 2. The change is made by replacing the body of step_write to call get() and use that value when calling _set.

_value = 0


def reset():
    global _value
    _value = 0


def get():
    return _value


def _set(v):
    global _value
    _value = v


def run_steps(steps):
    results = []
    for fn, args in steps:
        results.append(fn(*args))
    return results


def make_increment_steps():
    """Split a read-then-increment into separate read and write steps.

    BUG: under interleaving, two increments both read the same value
    and both write value+1, losing one update.
    """
    captured = {}

    def step_read():
        captured["current"] = get()
        return ("read", captured["current"])

    def step_write():
        # Read the live counter at write time to avoid using a stale captured
        # value. This makes the write increment the current _value rather
        # than a previously captured snapshot.
        current = get()
        new = current + 1
        _set(new)
        return ("write", new)

    return step_read, step_write


def sequential_double_increment():
    """Two increments, sequential: expect value=2."""
    reset()
    read_a, write_a = make_increment_steps()
    read_b, write_b = make_increment_steps()
    run_steps([(read_a, ()), (write_a, ()), (read_b, ()), (write_b, ())])
    return get()

    read_b, write_b = make_increment_steps()
    run_steps([(read_a, ()), (read_b, ()), (write_a, ()), (write_b, ())])
