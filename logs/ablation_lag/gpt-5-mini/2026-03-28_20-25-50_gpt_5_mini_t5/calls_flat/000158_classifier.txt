# Developer's Reasoning

## Root Cause
The bug is in the function add_entry: when position is not None the code inserts the label into _labels but appends the value into _values. Specifically, _labels.insert(position, label) is used while _values.append(value) is used instead of _values.insert(position, value), causing label/value ordering to diverge.

## Failure Mechanism
When a caller inserts an entry at a specific position, the label is placed at that index in _labels but the corresponding value is placed at the end of _values. For example, starting with _labels = ['a','b'] and _values = [1,2], calling add_entry('x', 0, position=1) results in _labels = ['a','x','b'] and _values = [1,2,0]. Then get_entry(1) returns ('x', 2) instead of the expected ('x', 0), demonstrating the misalignment between labels and values.

## Broken Invariant
After add_entry(label, value, position), the report guarantees that get_entry(position) == (label, value). That invariant is violated by the buggy implementation because label and value can end up in different positions across _labels and _values.

## Fix Strategy
Replace the parallel arrays with a single list of (label, value) tuples and update all functions to operate on that list. This makes insertion atomic (a single insert puts the label and value together) and prevents the earlier misalignment. Concretely, _labels and _values are replaced by _entries and add_entry now inserts or appends a (label, value) tuple; get_entry, get_all, count, and reset were updated to use _entries.

```python
"""Report builder (refactored for clarity).

This module previously used parallel _labels and _values lists which allowed
insertion bugs where the label and value could become misaligned. The
implementation below stores entries as a single list of (label, value)
pairs to ensure atomic insertion and clearer semantics.
"""

_entries = []


def add_entry(label, value, position=None):
    """Add an entry (label, value) to the report.

    If position is given, insert the pair at that index. Otherwise, append
    to the end.
    """
    pair = (label, value)
    if position is None:
        _entries.append(pair)
    else:
        _entries.insert(position, pair)


def get_entry(index):
    """Return (label, value) at the given index."""
    return _entries[index]


def get_all():
    """Return a list of (label, value) tuples.

    A shallow copy of the entries list is returned to avoid exposing the
    internal list object.
    """
    return list(_entries)


def count():
    """Return the number of entries."""
    return len(_entries)


def reset():
    """Clear all entries."""
    _entries.clear()

```
