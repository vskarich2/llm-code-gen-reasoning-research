## Root Cause
In retry_send, the loop never stops on a successful send because the code uses `if not result: continue` and otherwise falls through to the end of the loop without breaking or returning. Concretely, the function assigns `result = send(msg)` and then only uses `continue` when the result is False; when result is True there is no break/return, so the loop proceeds to the next iteration and calls send again.

## Failure Mechanism
Call retry_send('m', max_retries=2). send appends 'm' to the module-level list `_sent` and returns True. retry_send calls send twice (once per iteration) because it never returns on success, so `_sent` becomes ['m', 'm'] even though the first attempt succeeded. The observed effect is duplicate sends when the first attempt should have prevented further attempts.

## Broken Invariant

## Fix Strategy

Also implement clear_log to reset the internal log. These changes ensure the loop doesn't invoke send more times than necessary and satisfy the invariant that a successful first attempt prevents further calls.
