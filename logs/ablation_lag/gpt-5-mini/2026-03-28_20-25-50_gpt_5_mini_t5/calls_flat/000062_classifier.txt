# Developer's Reasoning

## Root Cause
In process_batch(items) the call to snapshot() is placed after the for-loop instead of inside it. As a result, the module-level list _snapshots is appended only once per batch rather than once per processed item.

## Failure Mechanism
When process_batch([1, 2, 3]) runs, the code increments _counter three times (0 -> 1 -> 3 -> 6) but calls snapshot() only once after the loop. That appends a single value (6) to _snapshots, so len(_snapshots) == 1 even though three items were processed. Any check that expects one snapshot per item (for example, verify_consistency() or tests relying on snapshot counts) will observe the wrong snapshot count.

## Broken Invariant
After calling process_batch(items), the number of newly recorded snapshots must equal len(items). Concretely: if before the call len(_snapshots) == S and items has N elements, then after the call len(_snapshots) == S + N.

## Fix Strategy
Move the snapshot() call into the body of the loop so a snapshot is recorded immediately after each individual item increments _counter. This ensures one append to _snapshots per item. The change is localized to process_batch: the previous form

    for item in items:
        _counter += item
    snapshot()

was changed to

    for item in items:
        _counter += item
        snapshot()

I also clarified docstrings (get_snapshots and process_batch) to make the per-item snapshot behavior explicit. This directly enforces the invariant because each iteration now appends exactly one snapshot.
