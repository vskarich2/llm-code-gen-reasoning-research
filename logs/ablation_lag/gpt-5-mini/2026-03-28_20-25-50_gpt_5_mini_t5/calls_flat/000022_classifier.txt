## Root Cause
In code_snippets_v2/partial_update_c/profile.py, the function update_profile updates user['email'] but does not modify user['verified'] or user['cached_greeting'] when the email actually changes. The variables involved are old_email (the previous user['email']) and user['cached_greeting']; because verified/ cached_greeting are not updated after assigning the new email, the old greeting and a previously True verified flag can persist.

## Failure Mechanism
Example: A user is created and then verified (user['verified'] == True) and user['cached_greeting'] holds "Hello, Alice!". Calling update_profile(user, {'email': 'alice.new@example.com'}) runs the email branch: old_email is read, user['email'] is set to the new address, but the function never sets user['verified'] to False nor clears user['cached_greeting']. As a result, the user remains marked verified and the cached greeting still shows the old name/greeting even though the email changed. Concretely, the code path in update_profile reaches the line user['email'] = value and then falls through without executing any further adjustments because the missing statements were not implemented.

## Broken Invariant
When update_profile is called with changes that include a validated email change (validate_email(value) is True) and should_reverify(old_email, new_email) returns True, then after update_profile returns it must hold that user['verified'] == False and user['cached_greeting'] is None. Currently this is not guaranteed because the function does not clear verified or cached_greeting on email changes.

## Fix Strategy
In update_profile I added logic in the email-handling branch to call should_reverify(old_email, value) and, if it returns True, set user['verified'] = False and user['cached_greeting'] = None. This directly enforces the invariant by making the function clear the cached greeting and mark the user unverified when the email has effectively changed (respecting should_reverify's case-insensitive comparison and old_email None handling). The change is localized to the email branch and preserves the existing name-handling behavior.

```python
"""User profile with email verification and cached greeting."""

from validation import validate_email, validate_name
from notifications import build_greeting, should_reverify


def create_user(name, email):
    """Create a user with verified status and cached greeting."""
    return {
        "name": name,
        "email": email,
        "verified": False,
        "cached_greeting": build_greeting({"name": name}),
    }


def verify_user(user):
    """Mark user as verified."""
    user["verified"] = True
    return user


def update_profile(user, changes):
    """Update profile fields.

    Invariant: changing email must set verified=False and clear cached_greeting.
    Invariant: changing name must update cached_greeting.
    """
    for key, value in changes.items():
        if key == "email" and validate_email(value):
            old_email = user.get("email")
            user["email"] = value
            # If the email effectively changed, require re-verification and clear greeting
            if should_reverify(old_email, value):
                user["verified"] = False
                user["cached_greeting"] = None
        elif key == "name" and validate_name(value):
            user["name"] = value
            user["cached_greeting"] = build_greeting(user)
    return user

```
