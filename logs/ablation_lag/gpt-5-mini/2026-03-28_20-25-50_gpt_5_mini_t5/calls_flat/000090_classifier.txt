# Developer's Reasoning

## Root Cause
In sender.send_with_retry the retry loop (for attempt in range(max_retries)) calls send(msg, ...) but does not stop the loop after a successful call. Because send() unconditionally calls append(msg) and notify(msg) on success, continuing the loop causes subsequent iterations to call send() again and append/notify the same message multiple times. The missing immediate return/break after a successful send is the direct cause.

## Failure Mechanism
Example: call send_with_retry('hello', max_retries=3, fail_first=True). The first call to send('hello') raises ConnectionError (simulated). The loop catches that and continues. On the second iteration send succeeds and calls append('hello') and notify('hello'). Because send_with_retry does not return/break, the loop continues to the third iteration and calls send('hello') again, causing a second append('hello') and second notify. The store therefore contains duplicate messages and duplicate notifications.

## Broken Invariant
For a single high-level call to send_with_retry(msg, ... ) that eventually succeeds, the store should contain exactly one appended message for that call. Concretely: after a successful send_with_retry(msg), store.message_count() must increase by exactly 1 and get_messages() must contain at most one new entry equal to msg for that call. The current implementation can violate this by appending the same msg multiple times.

## Fix Strategy
Stop retrying after the first successful send. I changed send_with_retry so that it immediately returns True when send(msg, ...) succeeds, which prevents further iterations from re-calling append/notify. I also changed the post-loop behavior to raise the last ConnectionError if all attempts failed, so failures are propagated instead of silently returning True. These changes ensure exactly one append/notify per successful high-level call and preserve retry behavior on transient errors.

from store import append, notify, get_messages, get_notifications

_attempt_count = 0


def reset():
    global _attempt_count, _messages, _notifications
    _attempt_count = 0
    _messages = []
    _notifications = []


def send(msg, fail_first=False):
    """Send a message: store it and notify.

    If fail_first is True, raises on first call to simulate transient error.
    """
    global _attempt_count
    _attempt_count += 1
    if fail_first and _attempt_count == 1:
        raise ConnectionError("transient failure")
    append(msg)
    notify(msg)
    return True


def send_with_retry(msg, max_retries=2, fail_first=False):
    """Retry send on transient errors."""
    last_error = None
    for attempt in range(max_retries):
        try:
            send(msg, fail_first=fail_first)
            # success: stop retrying to avoid duplicate append/notify
            return True
        except ConnectionError as e:
            last_error = e
            continue
    # all attempts exhausted — propagate the last error
    if last_error:
        raise last_error
    return False


def get_attempt_count():
    return _attempt_count
