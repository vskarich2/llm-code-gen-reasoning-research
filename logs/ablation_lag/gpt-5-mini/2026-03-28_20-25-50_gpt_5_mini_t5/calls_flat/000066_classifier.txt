## Root Cause
In code_snippets_v2/effect_order_b/processor.py the function process_batch calls increment(item["value"]) inside the loop but calls emit_event(item["id"], item["value"]) only once after the loop. That single post-loop emit_event uses the loop variable item (the last iterated item), so only one event is recorded for the last item. Additionally, processor.reset defines globals _counter and _events in the processor module instead of calling the metrics.reset function, so it never clears the state stored in the metrics module.

## Failure Mechanism
Given items = [{"id": 1, "value": 2}, {"id": 2, "value": 3}, {"id": 3, "value": 5}], process_batch runs the loop and calls increment three times so metrics._counter becomes 10. Because emit_event was placed outside the loop, it is invoked once with item referring to the last loop element ({"id": 3, "value": 5}), so metrics._events gets a single entry for item_id 3 with counter==10. The system therefore reports 3 processed items but metrics.get_events() returns a list of length 1, and prior calls to processor.reset do not clear metrics._events or metrics._counter because reset only sets module-local names in processor.py instead of invoking metrics.reset, allowing stale events/counters to accumulate across runs.

## Broken Invariant
After calling process_batch(items), metrics.get_events() must contain exactly one event per input item (i.e., len(metrics.get_events()) == len(items)) and each event must correspond to the same item id from the input list in the same order; currently that invariant is violated because only one event (for the last item) is emitted.

## Fix Strategy
Move the emit_event call inside the per-item loop so an event is emitted immediately after each increment, and make processor.reset delegate to metrics.reset so the shared metrics state is properly cleared. Concretely, import the metrics module and replace calls to increment/emit_event with metrics.increment/metrics.emit_event; change reset() to call metrics.reset(). This ensures one event per processed item and that resets clear the actual metrics state.
