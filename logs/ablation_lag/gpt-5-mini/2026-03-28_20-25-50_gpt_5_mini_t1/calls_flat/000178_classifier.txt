# Developer's Reasoning

## Root Cause
In code_snippets_v2/silent_default_c/flags.py the _ENV_KEY_MAP entry for 'dark_mode' is misspelled as 'FEATURE_DARKMODE' (missing underscore), so env lookup never finds the actual env var 'FEATURE_DARK_MODE'. Additionally, is_enabled() calls get_env_bool(env_key) and only treats a truthy result as an override (if env_val: return True), which causes explicit env=false to be ignored rather than applied.

## Failure Mechanism
Concrete scenario: env._ENV contains 'FEATURE_DARK_MODE': 'false' (as in env.py). flags._ENV_KEY_MAP maps 'dark_mode' -> 'FEATURE_DARKMODE' (wrong key), so is_enabled('dark_mode') sets env_key to None and skips the env layer entirely, returning config.get_config_bool('dark_mode') which is True. Even if the map were correct, the existing code does env_val = get_env_bool(env_key); if env_val: return True — so if FEATURE_DARK_MODE were present and set to 'false', get_env_bool would return False and the function would ignore that explicit False and continue to the config layer, potentially returning True. Thus either the wrong env key or the truthy-only check causes env overrides (both true and false) to be ignored or mishandled.

## Broken Invariant
For any flag_name where the corresponding environment variable is present (i.e., env.get_env(env_key) is not None), is_enabled(flag_name) must return the boolean value derived from that environment variable (get_env_bool(env_key)), overriding config and hardcoded defaults. This is currently violated for 'dark_mode' because the mapped env key is wrong, and for any flag set to a falsey env value because the code treats only truthy env values as overrides.

## Fix Strategy
I corrected the env var key mapping for 'dark_mode' to 'FEATURE_DARK_MODE' and changed is_enabled() to first check presence of the env var via get_env(env_key) and, if present, return get_env_bool(env_key) (so both True and False env values override other layers). I also check presence in the config layer via get_config(flag_name) before calling get_config_bool to avoid confusing missing config with a boolean False. These changes ensure the env layer properly overrides config/hardcoded and that explicit false values are respected.

}


def is_enabled(flag_name):
    """Check if a feature flag is enabled.

    Checks env first, then config, then hardcoded defaults.
    """
    env_key = _ENV_KEY_MAP.get(flag_name)
    if env_key:
        # Use presence check so an explicit "false" env var still overrides
        if get_env(env_key) is not None:
            return get_env_bool(env_key)

    # Use presence check in config to distinguish missing config vs False
    if get_config(flag_name) is not None:
        return get_config_bool(flag_name)

    return HARDCODED_DEFAULTS.get(flag_name, False)


def get_flag_source(flag_name):
    """Return which layer provides the flag value (for debugging)."""
    env_key = _ENV_KEY_MAP.get(flag_name)
    if env_key:
        if get_env(env_key) is not None:
            return "env"

    if get_config(flag_name) is not None:
        return "config"

    return "hardcoded"
