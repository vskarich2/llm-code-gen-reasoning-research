# Developer's Reasoning

## Root Cause
In make_withdraw_steps, the nested step_act function relies on the previously-set mutable flag result['approved'] (set by step_check) instead of re-checking the current account balance. Concretely, step_check calls check_balance(name, amount) and stores the boolean in result['approved'], and step_act then unconditionally calls do_withdraw(name, amount) whenever result['approved'] is True. This allows step_act to act on a stale approval value rather than the current _accounts state.

## Failure Mechanism
Concrete interleaving: reset(); create_account('alice', 100); create two withdraw step pairs for amount=80; run_steps in order [(check_a), (check_b), (act_a), (act_b)]. Both check_a and check_b call check_balance and set result['approved']=True because balance is 100. act_a sees result['approved']==True and calls do_withdraw, making balance 20. act_b still sees its stored result['approved']==True (stale) and calls do_withdraw again, making balance -60. The stale boolean in result allows a second withdrawal despite the balance already being reduced.

## Broken Invariant
The module must never permit an account balance to become negative as the result of executing withdrawal steps: for any account name, after any run_steps sequence composed from make_withdraw_steps(name, amount) and related steps, get_balance(name) >= 0 must hold. Currently this invariant is violated (e.g., alice goes from 100 to -60).

## Fix Strategy
Make the ACT step verify the current balance at the time of acting instead of trusting the earlier CHECK result. I changed step_act inside make_withdraw_steps to call check_balance(name, amount) again and update result['approved'] based on that fresh check; only when that re-check passes do we call do_withdraw(name, amount). This prevents acting on a stale approval when checks interleave, so at most one of two concurrent withdraws that individually saw the pre-check balance as sufficient will actually perform the debit.

def reset():
    _accounts.clear()


def create_account(name, balance):

def get_balance(name):
    return _accounts.get(name, 0)


def check_balance(name, amount):
    """CHECK: is balance sufficient?"""
    return _accounts.get(name, 0) >= amount


def do_withdraw(name, amount):
    """ACT: decrement balance. Assumes caller verified."""
    _accounts[name] = _accounts.get(name, 0) - amount


def run_steps(steps):
    results = []
    for fn, args in steps:
        results.append(fn(*args))
    return results


def make_withdraw_steps(name, amount):
    """Split withdrawal into separate check and act steps.

    BUG: under interleaving, both checks pass before either debits.
    """
    result = {"approved": False}

    def step_check():
        result["approved"] = check_balance(name, amount)
        return ("check", result["approved"])

    def step_act():
        # Re-check at ACT time to avoid acting on a stale approval.
        # If the balance is still sufficient, update approval and withdraw;
        # otherwise clear approval and do not withdraw.
        if check_balance(name, amount):
            result["approved"] = True
            do_withdraw(name, amount)
        else:
            result["approved"] = False
        return ("act", result["approved"])

    return step_check, step_act
