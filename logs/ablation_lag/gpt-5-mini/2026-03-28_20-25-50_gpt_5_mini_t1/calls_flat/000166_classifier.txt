## Root Cause
In code_snippets_v2/index_misalign_c/report.py the method Report.insert_column updates self.headers and each row but fails to update self.column_widths. The missing update to the self.column_widths list causes the three parallel structures (headers, rows, column_widths) to become unsynchronized.

## Failure Mechanism
When a caller inserts a column (e.g. report.insert_column(1, 'NewCol')), Report.headers grows by one element and every row receives an inserted cell, but self.column_widths remains its previous length. Later, Report.render() calls formatter.format_table which does header_parts = [h.ljust(widths[i]) for i, h in enumerate(headers)]. Because widths (self.column_widths) is shorter than headers, indexing widths[i] raises an IndexError at render time, or, if code continued, alignment would be wrong. The concrete sequence: create Report(['A','B'], default_width=10) -> column_widths = [10,10]; call insert_column(1,'X') -> headers becomes ['A','X','B'] but column_widths remains [10,10]; calling render() tries to access widths[2] and fails with IndexError.

## Broken Invariant
After any call that mutates columns (like insert_column), the Report must satisfy len(headers) == len(column_widths). Currently, insert_column can leave len(column_widths) < len(headers), violating that invariant.

## Fix Strategy
Ensure insert_column updates self.column_widths to the correct new length and size. I store the minimum default width in self.default_width (preserving the original default_width behavior) and insert a computed width for the new column using max(self.default_width, len(header), len(str(default_value))). This guarantees the column_widths list stays aligned with headers and provides a sensible initial width for the new column so format_table will not index out of range and alignment remains correct.
