# Developer's Reasoning

## Root Cause
_default_host is defined at module import as _default_host = _settings["host"], and get_host() returns that captured _default_host instead of reading from the live _settings dict. Because _default_host is bound once at import time, later calls to configure() or reset_settings() that change _settings do not affect the value returned by get_host().

## Failure Mechanism
Example: when the module is imported, _settings is {'host': 'localhost', ...} and _default_host becomes 'localhost'. If some code calls configure(host='example.com') afterwards, configure() updates the _settings dict to {'host': 'example.com', ...}, but get_host() still returns the stale captured value 'localhost' because it returns _default_host rather than the current _settings['host']. The causal chain is: module import -> _default_host assigned from _settings -> configure() mutates or replaces _settings -> get_host() returns the stale _default_host.

## Broken Invariant
After calling configure(host=...) or reset_settings(), a subsequent call to get_host() must return the current value of _settings['host']. This is violated because get_host() returns the import-time value stored in _default_host instead of reading _settings.

## Fix Strategy
Removed the eager, module-level capture _default_host and made get_host() read the host from the live _settings dict on each call. By returning _settings['host'] directly, get_host() now reflects updates made by configure() and reset_settings(). The change consists of deleting the _default_host assignment and changing get_host() to return _settings['host'].
