# Developer's Reasoning

## Root Cause
In retry_send the variable result is set to the return value of send(msg) but the code uses 'if not result: continue' and never breaks when send succeeds. Because send(msg) appends to the module-level list _sent on every call, retry_send can call send multiple times for the same message and append duplicate entries to _sent.

## Failure Mechanism
With the default max_retries=2, calling retry_send('hello') executes the loop twice. Each loop iteration calls send('hello'), which appends 'hello' to _sent. Since the code never breaks on a successful send, _sent becomes ['hello', 'hello'] after the call instead of a single entry. Concretely: for attempt in range(max_retries): result = send(msg) -> send appends; result is True; 'if not result' is False so it doesn't continue, but there is also no break or return, so the next iteration also calls send and appends again.

## Broken Invariant
If the first send attempt succeeds, retry_send must result in exactly one append of the message to _sent. Formally, after reset(); retry_send(m, max_retries=N) where send succeeds on the first attempt, len(get_sent()) == 1.

## Fix Strategy
Change retry_send to stop retrying as soon as send returns True and return True, and return False only if all attempts fail. This prevents multiple calls to send for a successful send and thus avoids duplicate entries in _sent. Also implement clear_log to consistently clear the log (delegates to reset()). The change replaces the incorrect 'if not result: continue' behavior with an immediate return on success and a final False return when no attempt succeeded.
