# Developer's Reasoning

## Root Cause
The api.checkout function ignores its use_new_pricing parameter. Checkout never changes the 'new_pricing' feature flag (variable use_new_pricing in api.checkout is unused), so downstream functions like billing.create_invoice and pricing.compute_price continue to read the global flag state from flags.is_enabled rather than honoring the checkout call-site intent.

## Failure Mechanism
If a caller invokes checkout(customer, items, use_new_pricing=True), the code still calls create_invoice(customer, items) without enabling the 'new_pricing' flag. Since pricing.compute_price calls flags.is_enabled('new_pricing') to decide between _v1_price and _v2_price, the invoice will use the currently-configured global pricing mode (e.g. 'v1') instead of the requested new pricing. Concretely: checkout(..., use_new_pricing=True) -> create_invoice -> compute_price checks is_enabled('new_pricing') -> returns False -> v1 pricing applied and invoice['pricing_version']=='v1', violating caller expectation.

## Broken Invariant
Calling checkout(customer, items, use_new_pricing=True) MUST produce an invoice whose pricing_version == 'v2' and whose line amounts are computed by pricing._v2_price. Currently that invariant can be false because checkout does not set the global 'new_pricing' flag.

## Fix Strategy
Make api.checkout enforce the requested pricing mode by temporarily setting the global 'new_pricing' flag before calling create_invoice and restoring the previous flag state afterwards. This uses flags.enable/disable and flags.is_enabled to capture and restore prior state in a finally block so the change is local to the checkout execution and avoids leaking the override to concurrent operations.



# Task Description
The checkout function takes a use_new_pricing flag but pricing doesn't seem to respect it. Fix the flag propagation. Return the updated code.

# Code Produced
```python
from billing import create_invoice, get_invoices
from flags import enable, disable, is_enabled


def checkout(customer, items, use_new_pricing=False):
    # Preserve previous 'new_pricing' flag state and set according to the function argument
    prev = is_enabled("new_pricing")
    if use_new_pricing:
        enable("new_pricing")
    else:
        disable("new_pricing")
    try:
        invoice = create_invoice(customer, items)
    finally:
        # Restore previous state to avoid leaking the override
        if prev:
            enable("new_pricing")
        else:
            disable("new_pricing")
    return invoice
```
