# Developer's Reasoning

## Root Cause
The bug is in function enqueue: the parameter queue is given a mutable default value (queue = []). That single list object is created when the function is defined and then reused across calls. When enqueue appends to queue, it mutates that shared default object, so later calls operate on the same list.

## Failure Mechanism
Concrete scenario: first call enqueue(make_task('A')) uses the default queue and appends task A to that default list, returning ['A']. A later call enqueue(make_task('B')) without passing an explicit queue uses the same default list and appends task B, returning ['A', 'B'] instead of ['B']. The cause is queue.append(task) operating on the shared default list created by the default parameter queue=[].

## Broken Invariant
The function violates its documented invariant: "each call with a single task (no explicit queue) must return a list containing only that task." Testable statement: calling enqueue(make_task('X')) on two independent call sites (without providing queue) must each return a list of length 1 whose sole element has name 'X'. Under the current code the second call returns a list containing previous tasks as well.

## Fix Strategy
Replace the mutable default with None and allocate a fresh list inside the function when queue is None. Concretely, change the signature to enqueue(task, queue=None) and add if queue is None: queue = [] before appending. This ensures each call that omits queue gets a new list, so queue.append(task) only mutates that call-local list and does not leak tasks to subsequent calls.
