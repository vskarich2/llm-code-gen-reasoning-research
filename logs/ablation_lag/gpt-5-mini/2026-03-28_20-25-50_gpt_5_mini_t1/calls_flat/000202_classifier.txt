# Developer's Reasoning

## Root Cause
The cache_writer module defined two separate helpers, refresh_user_snapshot (which calls cache_put_if_absent) and sync_user_to_cache (which calls cache_put), that provide overlapping behavior for writing a user's display name into the same _store. Because refresh_user_snapshot only writes if the key is absent (cache_put_if_absent) while sync_user_to_cache always overwrites (cache_put), callers using the wrong helper can produce inconsistent cache state. The key functions/variable involved are cache_writer.refresh_user_snapshot, cache_writer.sync_user_to_cache, and the shared cache_writer._store.

## Failure Mechanism
In user_service.rename_user, the code updates the DB via db.update_name(...) and then calls refresh_user_snapshot(updated). refresh_user_snapshot uses cache_put_if_absent, so if the user key (e.g. 'user:42') already exists in cache with the old name, the cache is not updated and remains stale. Concretely: before rename_user, _store['user:42'] == 'Alice'. After db.update_name sets name to 'Alicia', calling refresh_user_snapshot(updated) does not overwrite because the key exists, so _store remains 'Alice' rather than 'Alicia'.

## Broken Invariant
After rename_user(user_id, new_name) completes, the cache must reflect the updated name: _store.get(f'user:{user_id}') == lookup_user(user_id)['name']. Currently this invariant can be violated because rename_user used refresh_user_snapshot which uses cache_put_if_absent and therefore may leave the cache with the old name.

## Fix Strategy
I replaced the two small helpers in cache_writer.py with a single consolidated function sync_user_to_cache(user, overwrite=False) that can either put-if-absent (default) or overwrite when overwrite=True. Then I updated user_service to use the consolidated function for all cache operations; specifically, rename_user now calls sync_user_to_cache(updated, overwrite=True) to ensure the cache is updated after a name change, preserving the intended invariant. This removes duplicated helpers and makes the overwrite behavior explicit and controlled by callers.
