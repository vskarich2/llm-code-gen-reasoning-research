The variable _cache and the function record are causally related: the early return uses _cache to supply a cached result but skips record(), so duplicate calls are not logged.

## Failure Mechanism
Concrete scenario: call process_payment('tx1', 100) -> not in _cache, path creates result, calls record('tx1', 100, 'charged') and stores result in _cache. Call process_payment('tx1', 100) again -> txn_id in _cache triggers the early return branch; the cached result is returned but record(...) is not called. Effect: ledger._entries contains one entry even though process_payment was called twice, so ledger.get_summary()['count'] == 1 while the number of process_payment calls is 2.

Under the current code, calling process_payment twice with the same txn_id yields ledger.verify(2) == False (it returns False because only one record was created).

This guarantees each process_payment invocation appends an entry to _entries so ledger.verify(...) will match the number of calls. No changes were made to ledger.py.

"""Payment processor with duplicate detection."""

from ledger import record, verify, reset_ledger

_cache = {}


def process_payment(txn_id, amount):
    """Process a payment. Detects duplicates via txn_id cache.

    Every call — including duplicates — must be recorded in the ledger
    so that verify() counts match total process_payment calls.
    """
    if txn_id in _cache:
        # For duplicates, record the already-charged amount/status from the cache
        cached = _cache[txn_id]
        record(txn_id, cached["amount"], cached["status"])
        return cached

    result = {"txn_id": txn_id, "amount": amount, "status": "charged"}
    record(txn_id, amount, "charged")
    _cache[txn_id] = result
    return result


def get_cached(txn_id):
    """Retrieve a cached payment result."""
    return _cache.get(txn_id)


def reset():
    """Reset payment state."""
    _cache.clear()
    reset_ledger()
