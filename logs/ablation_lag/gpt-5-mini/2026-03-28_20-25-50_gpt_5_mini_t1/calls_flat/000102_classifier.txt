# Developer's Reasoning

## Root Cause
In order_service.place_order the except ValueError handler re-raises the payment exception without calling inventory.release, so the inventory module's _reserved mapping (accessed via reserve/release/get_reserved) remains incremented for the failed order. The causal relationship: reserve(product_id, qty) increments inventory._reserved, then a payment failure triggers the except branch which re-raises immediately and never calls release(product_id, qty) to decrement inventory._reserved.

## Failure Mechanism
Concrete scenario: inventory._stock['widget']=10. place_order('widget', 2, price) calls reserve('widget', 2) which sets inventory._reserved['widget'] += 2. Then _process_payment raises ValueError (payment declined). The except block in place_order catches and re-raises without releasing. As a result inventory.get_reserved('widget') returns 2 even though the order failed and no confirmed purchase occurred. Subsequent attempts to place orders or compute availability see available('widget') == 8 (because reserved stayed at 2), causing inventory to appear reduced incorrectly and potentially preventing valid purchases.

## Broken Invariant
After a failed payment raised by _process_payment during place_order(product_id, qty, price), inventory.get_reserved(product_id) must be decremented by qty so that inventory.get_reserved(product_id) equals its value before the place_order call. Equivalently, available(product_id) + get_reserved(product_id) must equal the original _stock[product_id] after a failed place_order (i.e., a failed payment must not permanently change reservation counts).

## Fix Strategy
Ensure that any reservation created by reserve(product_id, qty) is rolled back when payment fails. I added a call to release(product_id, qty) in the except ValueError branch inside place_order so the inventory._reserved counter is decremented before re-raising the payment exception. This directly undoes the earlier reserve call and restores the inventory invariants.

"""Order service coordinating inventory and payment."""

from inventory import reserve, release

_notifications = []
_gateway_fail = False


def reset():
    global _notifications, _gateway_fail, _stock, _reserved
    _notifications = []
    _gateway_fail = False
    _stock = {}
    _reserved = {}


def set_gateway_fail(fail):
    """Configure gateway to simulate payment failure."""
    global _gateway_fail
    _gateway_fail = fail


def _process_payment(amount):
    """Simulate payment gateway."""
    if _gateway_fail:
        raise ValueError("payment declined")
    return {"paid": amount}


def place_order(product_id, qty, price):
    """Place an order: reserve inventory, process payment, notify.

    If payment fails, inventory reservation should be rolled back.
    """
    reserve(product_id, qty)
    try:
        result = _process_payment(qty * price)
    except ValueError:
        # Roll back the inventory reservation made above so that a payment
        # failure does not leave stock permanently reserved.
        release(product_id, qty)
        raise  # re-raise after rolling back reservation
    _notifications.append({"product": product_id, "qty": qty})
    return {"status": "confirmed", "payment": result}


def get_notifications():
    return list(_notifications)
