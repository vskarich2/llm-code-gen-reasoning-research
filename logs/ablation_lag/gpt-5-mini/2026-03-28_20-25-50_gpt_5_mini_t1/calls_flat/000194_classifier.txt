# Developer's Reasoning

## Root Cause
In transfer_service.py the function execute_transfer interleaves observability calls (ledger.record_debit and audit.emit_failure_alert) with business state changes (sender.balance -= amount and receiver.balance += amount). Specifically, record_debit is called immediately after decreasing sender.balance but before increasing receiver.balance, and a transient failure (the random RuntimeError) is raised after record_debit and before the credit, which makes the ledger reflect a debit that has no matching credit and leaves balances inconsistent.

## Failure Mechanism
Concrete scenario: execute_transfer(sender, receiver, 100) runs validate_transfer, then record_transfer_attempt(...). The code then does sender.balance -= 100 and immediately calls record_debit(sender.account_id, 100). If random.random() < 0.3 the code then calls emit_failure_alert and raises RuntimeError('transient failure during credit') before doing receiver.balance += 100 or record_credit. The result is that sender.balance is decreased by 100 and the ledger contains a debit entry for 100, but receiver.balance is unchanged and there is no credit entry — producing a partial, observable mismatch between balances and ledger/audit.

## Broken Invariant
Invariant violated: For any completed transfer attempt recorded, a debit entry and a matching credit entry of the same amount must both exist in the ledger and the sender/receiver balances must reflect -amount and +amount respectively. Concretely: after a transfer attempt, it is possible to observe a debit ledger entry without a corresponding credit ledger entry and without the receiver's balance being increased by that amount.

## Fix Strategy
I separated the pure business operation (the atomic balance move) from observability. I introduced _core_transfer(sender, receiver, amount) that only mutates the in-memory balances (sender.balance -= amount; receiver.balance += amount). The outer execute_transfer does validation, records the attempt as pending, calls _core_transfer, and only after the balances have been updated performs all ledger and audit calls (record_debit, record_credit, emit_transfer_event). Any exception during the observability phase is caught in a single place: we emit a failure alert and record the attempt as failed, then re-raise. By moving all ledger/audit side-effects out of the critical path and executing them after the core transfer completes, we remove the previous ordering that allowed a debit to be logged before the credit was applied, thus preventing the specific partial-record/partial-balance state described above.

```python
import random
from models import Account
from ledger import record_debit, record_credit, record_transfer_attempt
from audit import emit_transfer_event, emit_failure_alert


def validate_transfer(sender, amount):
    if amount <= 0:
        raise ValueError("amount must be positive")
    if sender.balance < amount:
        raise ValueError("insufficient funds")


def _core_transfer(sender, receiver, amount):
    """Pure business logic: move balances. No logging/observability here."""
    sender.balance -= amount
    receiver.balance += amount


def execute_transfer(sender, receiver, amount):
    """Wrapper that performs validation, calls the core transfer, and handles all observability (ledger + audit).

    Observability calls are centralized so they cannot interleave with the core balance mutation and cause partial
    recorded state (e.g. a recorded debit without a matching credit).
    """
    validate_transfer(sender, amount)

    # record that we started an attempt
    record_transfer_attempt(sender.account_id, receiver.account_id, amount, status="pending")

    try:
        # perform the atomic business change
        _core_transfer(sender, receiver, amount)

        # simulate an external transient failure possibility — handled centrally below
        if random.random() < 0.3:
            # Treat this as an observability/external failure; raise to be handled by the wrapper.
            raise RuntimeError("transient failure during credit")

        # Observability: record both sides of the ledger and emit the transfer event
        record_debit(sender.account_id, amount)
        record_credit(receiver.account_id, amount)
        emit_transfer_event(sender.account_id, receiver.account_id, amount)

        # mark attempt completed
        record_transfer_attempt(sender.account_id, receiver.account_id, amount, status="completed")

    except Exception as exc:
        # central failure handling: emit audit alert and mark attempt failed, then re-raise
        try:
            emit_failure_alert(sender.account_id, receiver.account_id, amount, str(exc))
        finally:
            record_transfer_attempt(sender.account_id, receiver.account_id, amount, status="failed")
        raise
```
