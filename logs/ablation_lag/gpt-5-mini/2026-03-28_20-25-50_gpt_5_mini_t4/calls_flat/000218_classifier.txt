# Developer's Reasoning

## Root Cause
The bug is in make_increment_steps() — specifically step_write() uses the stale value stored in captured['current'] (set earlier by step_read()) to compute the new value: _set(captured['current'] + 1). Because _set and get operate on the module-level _value, step_write() overwrites the global _value with a value computed from an out-of-date snapshot instead of the current _value.

## Failure Mechanism
Concrete failing interleaving: interleaved_double_increment() calls run_steps([(read_a, ()), (read_b, ()), (write_a, ()), (write_b, ())]). read_a and read_b each call step_read() and both record captured['current']==0. Then write_a runs step_write() and executes _set(captured['current'] + 1) -> _set(1). Then write_b runs step_write() and also executes _set(captured['current'] + 1) -> _set(1) because captured['current'] was 0 in its closure. The second write overwrites the first write, so _value ends up 1 instead of 2.

## Broken Invariant
After reset() and performing two logical increments (two calls to make_increment_steps() each performing read then write in any ordering), get() must return 2. Formally: reset(); create two increment step pairs; run_steps with any ordering of the two read and two write steps; assert get() == 2. That invariant is violated by the current step_write() implementation.

## Fix Strategy
I changed make_increment_steps() so the write step computes the increment from the current runtime value at write time by calling get() instead of using the earlier-captured snapshot. Concretely, I replaced _set(captured['current'] + 1) with reading new_val = get() + 1 and then _set(new_val). This ensures each write increments the then-current global _value, so when writes execute sequentially (as run_steps does) interleaved reads cannot cause a later write to overwrite a prior write with a stale result. The change eliminates reliance on the stale captured value while keeping the separate read and write steps for simulation/debugging.

_value = 0


def reset():

    _value = 0


def get():

def _set(v):
    global _value
    _value = v


def run_steps(steps):
    results = []
    for fn, args in steps:
        results.append(fn(*args))
    return results


def make_increment_steps():
    """Split a read-then-increment into separate read and write steps.

    FIX: compute the increment at write time from the current _value so
    a write does not blindly overwrite a more recent update with a stale
    snapshot captured earlier by a read step.
    """

    def step_read():
        # return the observed value at read time for debugging/inspection
        current = get()
        return ("read", current)

    def step_write():
        # compute from the current runtime value at write time to avoid lost updates
        new_val = get() + 1
        _set(new_val)
        return ("write", new_val)

    return step_read, step_write


def sequential_double_increment():
    """Two increments, sequential: expect value=2."""
    reset()
    read_a, write_a = make_increment_steps()
    read_b, write_b = make_increment_steps()
    run_steps([(read_a, ()), (write_a, ()), (read_b, ()), (write_b, ())])
