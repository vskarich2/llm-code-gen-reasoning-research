# Developer's Reasoning

## Root Cause
In Report.insert_column (report.py), the list self.column_widths is not updated when a new header is inserted. The method updates self.headers and inserts a default value into each row, but it leaves self.column_widths at its previous length, so headers and widths drift out of sync.

## Failure Mechanism
When insert_column is called (e.g. report.insert_column(1, 'NewCol')), self.headers gains an extra entry while self.column_widths remains the old length. Later calls that assume widths and headers align fail: validate() calls validate_table(headers, rows, column_widths) which checks len(headers) == len(widths) and will return False, and render() calls format_table which does header_parts = [h.ljust(widths[i]) for i, h in enumerate(headers)] — if widths is shorter than headers this list comprehension will raise an IndexError because widths[i] is out of range.

## Broken Invariant
For any Report instance, after any sequence of operations, len(report.headers) == len(report.column_widths) must hold. This invariant is violated after insert_column because column_widths is not updated to include the new column.

## Fix Strategy
Update insert_column to insert a corresponding width at the same position in self.column_widths. The change self.column_widths.insert(position, len(header)) ensures column_widths remains the same length as headers and that the new column is initially wide enough to hold its header. This directly prevents the IndexError in format_table and makes validate_table succeed again.
