# Developer's Reasoning

## Root Cause
The bug is in function enqueue: the parameter queue has a mutable default value queue=[]. That default list object is created once at function definition time and shared across all calls that omit the queue argument, so multiple calls append to the same list instance.

## Failure Mechanism
If a caller invokes enqueue('task1') with no explicit queue, enqueue appends 'task1' to the shared default list and returns it (e.g. ['task1']). A later call enqueue('task2') with no explicit queue appends 'task2' to the same shared list, producing ['task1', 'task2']. This demonstrates accumulation across independent calls because the single default list object is reused instead of creating a fresh list per call.

## Broken Invariant
The function enqueue violates the contract in its own docstring: 'each call with a single task (no explicit queue) must return a list containing only that task.' Concretely, for any task name t, enqueue(t) must return ['t'], which is not true after a previous enqueue call has mutated the shared default list.

## Fix Strategy
I replaced the mutable default list with None (enqueue(task, queue=None)) and create a new list inside the function when queue is None (if queue is None: queue = []). This ensures a fresh list instance is used for each call that doesn't supply an explicit queue, preventing cross-call accumulation and restoring the invariant.
