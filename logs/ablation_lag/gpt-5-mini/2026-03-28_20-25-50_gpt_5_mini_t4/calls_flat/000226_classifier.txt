# Developer's Reasoning

## Root Cause
The function process() treats the absence of initialization (the global flag _initialized) as an unrecoverable error: it appends an error entry to _log and returns False. The global list _buffer is declared at module scope but never used, so items submitted to process() before init() are discarded instead of being retained for later processing.

## Failure Mechanism
In broken_order(), run_steps calls process('a') while _initialized is False. process() records _log.append(f"error:not_init:{item}") and returns False, so the item 'a' is not stored. Later init() sets _initialized = True and appends 'init' to the log, but because _buffer was never populated, there is nothing to replay and the eventual shutdown() log is missing 'processed:a'. Concretely, calling run_steps([(process,'a'), (init,()), (process,'b'), (shutdown,())]) produced a log containing 'error:not_init:a' and no 'processed:a'.

## Broken Invariant
For any sequence of calls that includes init() before shutdown(), every process(item) call must result in a 'processed:<item>' entry in the final shutdown log, preserving the order items were received. (Specifically, after run_steps([(process,'a'), (init,()), (process,'b'), (shutdown,())]) the log must include 'processed:a' before 'processed:b'.)

## Fix Strategy
Make process() enqueue items when _initialized is False (using the existing _buffer) instead of logging an error. Then, when init() runs, flush _buffer by appending 'processed:<item>' entries in arrival order and clear the buffer. This change ensures items submitted before init() are not lost: process() accepts and stores them, and init() replays them into _log once initialization completes.
