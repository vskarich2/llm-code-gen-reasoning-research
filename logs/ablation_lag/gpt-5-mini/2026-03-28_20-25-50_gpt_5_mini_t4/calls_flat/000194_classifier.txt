# Developer's Reasoning

## Root Cause
transfer_service.execute_transfer mixes observability (ledger.record_*/audit.emit_*) with business state changes: it decrements sender.balance and calls record_debit before the transient failure check. Specifically, execute_transfer does 'sender.balance -= amount' then 'record_debit(...)' and only afterwards the random failure check can raise RuntimeError, leaving the system with sender debited but receiver not credited.

## Failure Mechanism
Concrete scenario: sender.balance is 100, receiver.balance is 0, amount=50. execute_transfer validates and calls record_transfer_attempt, then executes 'sender.balance -= 50' (sender.balance becomes 50) and immediately calls record_debit(sender.account_id, 50). The random branch triggers (random.random() < 0.3), so emit_failure_alert is called and RuntimeError('transient failure during credit') is raised before 'receiver.balance += amount' and record_credit(...). Result: ledger has a debit entry, audit has a failure alert, sender lost 50 but receiver never gained 50 — the total balances decreased by 50 and the system is left in a partially-applied state.

## Broken Invariant
After any call to execute_transfer(sender, receiver, amount) where sender.balance >= amount at call time, the total sum of sender.balance + receiver.balance must remain equal to the sum before the call (i.e., transfers must not change the system-wide total balance even if the transfer raises). This invariant is violated when the function raises during the credit phase: the sender is debited but the receiver is not credited.

## Fix Strategy
I separated pure state mutation (the 'core' transfer) from observability. I introduced a core helper that applies the debit and credit operations and returns a status describing which steps completed, without calling ledger or audit. The execute_transfer wrapper now performs validation and all ledger/audit calls based on the core's returned status: it records the attempt, records a debit if the core applied the debit, records a credit if the core applied the credit, emits a failure alert if credit didn't complete, and only then raises. By returning status rather than raising from the core on transient failure, the wrapper can always emit observability events in a way that correctly reflects the state changes and preserves ordering. This makes instrumentation consistent with actual balance changes and avoids mixed responsibilities that caused the partial-invariant bug.

import random
from models import Account
from ledger import record_debit, record_credit, record_transfer_attempt
from audit import emit_transfer_event, emit_failure_alert


def validate_transfer(sender, amount):
    if amount <= 0:
        raise ValueError("amount must be positive")
    if sender.balance < amount:
        raise ValueError("insufficient funds")


def _core_transfer(sender, receiver, amount):
    """Core business logic: apply debit and credit steps and return what completed.

    This helper performs no observability (ledger/audit) calls and does not raise
    on the simulated transient failure; instead it returns a status dict so the
    wrapper can emit accurate observability signals that reflect the state.
    """
    # apply debit
    sender.balance -= amount
    # simulate a transient failure that can occur between debit and credit
    if random.random() < 0.3:
        return {"debit_applied": True, "credit_applied": False, "error": "connection reset during credit phase"}

    # apply credit
    receiver.balance += amount
    return {"debit_applied": True, "credit_applied": True}


def execute_transfer(sender, receiver, amount):
    """Wrapper that handles validation and all observability (ledger/audit).

    The wrapper calls the pure core transfer and then emits ledger and audit
    events based on the core's result. If the core reports the credit failed,
    the wrapper emits a failure alert and raises a RuntimeError after logging.
    """
    validate_transfer(sender, amount)

    # record that we attempted a transfer (observability)
    record_transfer_attempt(sender.account_id, receiver.account_id, amount)

    # perform the core transfer (no logging here)
    result = _core_transfer(sender, receiver, amount)

    # record debit if it was applied
    if result.get("debit_applied"):
        record_debit(sender.account_id, amount)

    # if credit didn't complete, emit failure alert and raise
    if not result.get("credit_applied"):
        emit_failure_alert(
            sender.account_id, receiver.account_id, amount,
            result.get("error", "transient failure during credit"),
        )
        raise RuntimeError("transient failure during credit")

    # credit completed successfully: record it and emit transfer event
    record_credit(receiver.account_id, amount)
    emit_transfer_event(sender.account_id, receiver.account_id, amount)
