# Developer's Reasoning

## Root Cause
The bug is in pipeline.ingest: the for-loop over max_pipeline_retries calls send_with_retry(msg, ...) but does not break after a successful call. Because send_with_retry itself performs the send (and appends the message) and does not raise on success, ingest will continue the loop and call send_with_retry again. Additionally, pipeline.reset tried to clear variables _messages, _notifications, and _attempt_count that are not defined in pipeline.py (it attempted to manipulate other modules' internals) which would raise NameError and prevent proper test isolation.

## Failure Mechanism
Concrete scenario: ingest(msg, max_pipeline_retries=2, fail_first=False) runs a loop with two iterations. On the first iteration send_with_retry succeeds and appends the message to store._messages. Because ingest lacks a break after success, the second iteration also calls send_with_retry and appends the same message again, producing duplicates. If fail_first=True, sender.send may raise once and succeed later, but ingest still invokes send_with_retry for each pipeline iteration, so each pipeline iteration that ultimately succeeds will append the message once — resulting in 2 copies with the default pipeline retries, and more copies if the pipeline retry count is higher. The broken pipeline.reset compounds test interference because it tries to assign to _messages/_notifications/_attempt_count in pipeline.py instead of invoking the other modules' reset functions, causing tests to not get a clean store between runs.

## Broken Invariant
For any single call to ingest(msg), the store must contain exactly one appended message for that msg (i.e., store.message_count() increases by 1 and store.get_messages() contains one new entry equal to msg).

## Fix Strategy
Add an explicit break in pipeline.ingest after send_with_retry returns successfully so the pipeline stops retrying once the send completed. Also fix pipeline.reset to call the store and sender reset functions (reset_store and reset_sender) and only clear pipeline-local _ingest_log, avoiding assignments to names not present in this module. These changes ensure exactly one successful send invocation per ingest call and proper test isolation by clearing other modules via their public reset APIs.
