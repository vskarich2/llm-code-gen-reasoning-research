## Root Cause
In code_snippets_v2/commit_gate/pipeline.py the function process_batch removed the calls to reducers.commit(st) and reducers.freeze_view(st). As a result, st["meta"]["frozen"] is never set to True and st["stable"] is never populated with the canonical committed data; the pipeline only ran stage(st, merged) which leaves data in pending/view but does not perform the commit/freeze steps.

## Failure Mechanism

Then get_committed_total(st) in api.ingest sees st["meta"]["frozen"] == False and returns None. Similarly, ingest_and_verify() computes view_digest from st["view"] (the staged view) but get_committed_digest(st) returns None because the state was never frozen; this causes inconsistent or missing committed totals and committed digests even though entries were processed through stage().

## Broken Invariant

## Fix Strategy

This restores the intended contract so selectors like get_committed_total and get_committed_digest will return the expected committed values instead of None.
