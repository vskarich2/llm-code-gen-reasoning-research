# Developer's Reasoning

## Root Cause
In process_batch(items) the code increments the module counter (_counter) for each item but calls snapshot() only once after the loop. This causes _snapshots to receive a single entry instead of one per item. Additionally, there is no tracked expected snapshot count (no _items_processed variable), and verify_consistency() currently returns len(_snapshots) (an integer) rather than checking the intended invariant.

## Failure Mechanism
For example, calling process_batch([1, 2, 3]) will add 1+2+3 to _counter, then call snapshot() once, appending the final counter value to _snapshots a single time. After that call, _snapshots has length 1 but three items were processed. Because verify_consistency() just returns the raw length (1) rather than comparing it to the number of processed items, callers cannot detect the missing per-item snapshots and the invariant 'one snapshot per item' is violated silently.

## Broken Invariant
After processing N items via process_batch, the module must have exactly N new snapshots recorded; i.e. len(_snapshots) == _items_processed (where _items_processed is the total number of items processed since the last reset).

## Fix Strategy
Call snapshot() immediately after incrementing _counter for each item inside the loop so a snapshot is recorded per item. Add a module-level _items_processed counter updated by process_batch so we can test the invariant. Change verify_consistency() to return a boolean comparing len(_snapshots) to _items_processed. reset() clears _counter, _snapshots, and _items_processed. These changes ensure each processed item produces one snapshot and make that invariant testable.

```python
 """Batch processor with per-item snapshots.

This module maintains a running numeric counter and records snapshots of
that counter. Each processed item should cause the counter to advance
and a snapshot to be recorded immediately after that item is applied.

Public functions:
- reset(): reset internal state
- snapshot(): record the current counter value
- get_snapshots(): return a copy of recorded snapshots
- process_batch(items): process each item, snapshotting after each
- verify_consistency(): return True iff exactly one snapshot exists per processed item
"""

_counter = 0
_snapshots = []
_items_processed = 0


def reset():
    """Reset the module state: counter, snapshots, and processed count."""
    global _counter, _snapshots, _items_processed
    _counter = 0
    _snapshots = []
    _items_processed = 0


def snapshot():
    """Record the current counter value into the snapshot list."""
    _snapshots.append(_counter)


def get_snapshots():
    """Return a shallow copy of the recorded snapshots."""
    return list(_snapshots)


def process_batch(items):
    """Process each item: increment counter and record a snapshot after each item.

    items: iterable of numeric values added to the running counter.

    Returns the updated counter value.
    """
    global _counter, _items_processed
    for item in items:
        _counter += item
        # record a snapshot immediately after handling each item
        snapshot()
        _items_processed += 1
    return _counter


def verify_consistency():
    """Verify the invariant: one snapshot per processed item.

    Returns True when len(_snapshots) equals the total items processed
    since the last reset; otherwise False.
    """
    return len(_snapshots) == _items_processed

```
