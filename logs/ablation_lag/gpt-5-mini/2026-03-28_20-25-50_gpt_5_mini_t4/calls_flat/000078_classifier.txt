# Developer's Reasoning

## Root Cause
In loader.load(), the module-level variables _status and _data are not updated when the incoming source is empty or None. The function only sets _status = 'loaded' and _data when the truthy condition (source and len(source) > 0) holds; otherwise it returns leaving _status and _data at their previous values.

## Failure Mechanism
Example sequence: call load(['a']) -> loader._data becomes ['a'] and loader._status becomes 'loaded'. Later call load([]) (an empty list). Because the condition if source and len(source) > 0 is false for [], the function returns without changing _status or _data. As a result get_status() still returns 'loaded' and get_data() still returns ['a'], so run_pipeline([]) reports status 'loaded' and count 1 even though the most recent load had an empty source.

## Broken Invariant
After any call to loader.load(source), get_status() must reflect the outcome of that specific call. Concretely: for an empty or None source, get_status() == 'empty' and get_data() returns an empty list.

## Fix Strategy
Ensure loader.load explicitly sets both _status and _data for empty or None sources (set _status = 'empty' and _data = []). Also handle non-sized iterables by converting to list and deciding status from the resulting length. Additionally, make pipeline.reset delegate to loader.reset to avoid module-local shadowing of loader state. These changes guarantee status and data are always consistent with the most recent load call.
