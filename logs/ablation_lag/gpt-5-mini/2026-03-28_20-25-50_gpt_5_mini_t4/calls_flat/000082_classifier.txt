## Root Cause
In pipeline.find_best the variable _last_best (module global) is reused when no current record exceeds the threshold: the function's for/else sets best = _last_best in the else branch. This makes find_best return a stale record stored in _last_best instead of returning None. The causal relationship is: _last_best is only updated when a qualifying record is found, but when none are found the code assigns best = _last_best, so the function returns previously-stored data.

## Failure Mechanism
Concrete scenario: first call to find_best processes records and finds recA with value > 50, so it sets _last_best = recA and returns recA. Later, new input has no records with value > 50. The for loop in find_best does not set a new 'best', so the else branch executes and assigns best = _last_best (which still holds recA). The function then sets _pipeline_result = 'found' because best is not None and returns recA. Downstream code therefore operates on an incorrect record (recA) even though none of the current records qualified, leading to incorrect processing or crashes elsewhere that expect the pipeline to return None when there is no current match.

## Broken Invariant
Contract of find_best: 'must return the matching record or None if none qualifies.' This is violated because when no current record qualifies, find_best returns the previously stored record in _last_best instead of None, and also sets _pipeline_result = 'found' incorrectly.

## Fix Strategy
Change the else branch in find_best to set best = None and clear _last_best = None. This ensures that when no current record exceeds the threshold the function returns None and sets _pipeline_result to 'not_found', restoring the declared contract. The change removes the use of stale state (_last_best) as the function's return value.
