## Root Cause
In update_profile (code_snippets_v2/partial_update_a/profile.py), the branch that handles the 'name' key sets user['name'] but never updates user['display_name']. The code comment even notes the bug, but the causal variable is user['display_name'] being left unchanged when the canonical user['name'] is modified.

## Failure Mechanism
Create a user with create_user('John', 'j@example.com') which sets both 'name' and 'display_name' to 'John'. Calling update_profile(user, {'name': 'John Doe'}) runs the update_profile loop: the 'name' branch executes user['name'] = 'John Doe' but does not touch user['display_name'.] As a result user becomes {'name': 'John Doe', 'display_name': 'John', 'email': 'j@example.com', 'age': None}. Any code that reads display_name (for example a UI or formatter) will still show 'John' even though the canonical name is 'John Doe'.

## Broken Invariant
For every user dict produced by create_user or modified via update_profile, user['display_name'] must equal user['name'] (i.e., user['display_name'] == user['name']).

## Fix Strategy
Introduce a single helper _set_name(user, name) that sets both user['name'] and user['display_name'], and make update_profile call this helper for both 'name' and 'display_name' keys. This ensures any update to the name (or an attempted update to display_name) synchronously updates both fields, restoring the invariant. The change is local to update_profile and adds a small helper to keep the intent explicit.

def _set_name(user, name):
    """Set both the canonical name and the display_name so the invariant holds."""
    user["name"] = name

def update_profile(user, changes):
    """Update user profile fields from changes dict.

    Invariant: display_name must always equal name.
    """

        if key in ("name", "display_name"):
            # Keep name and display_name in sync regardless of which field is provided
