# Developer's Reasoning

## Root Cause
Two problems in flags.py: (1) the mapping _ENV_KEY_MAP for the 'dark_mode' flag uses the wrong environment variable name 'FEATURE_DARKMODE' instead of the actual env var 'FEATURE_DARK_MODE' (variable: _ENV_KEY_MAP['dark_mode']). (2) is_enabled(flag_name) uses get_env_bool(env_key) and then tests the returned boolean for truthiness (env_val) before deciding to return; that logic only returns when the env var is truthy and ignores an explicit env-provided False. Together these cause environment overrides to be missed.

## Failure Mechanism
Concrete scenario: the environment defines FEATURE_DARK_MODE='false' (in env._ENV), and the config file has dark_mode=True (in config._FILE_CONFIG). Because flags._ENV_KEY_MAP incorrectly maps 'dark_mode' to 'FEATURE_DARKMODE', get_env('FEATURE_DARKMODE') returns None so get_env_bool('FEATURE_DARKMODE') yields the default False. is_enabled() then tests env_val and since it's False it falls through to read the config via get_config_bool('dark_mode') which returns True, so is_enabled('dark_mode') returns True even though an environment variable (FEATURE_DARK_MODE) existed and explicitly set the flag to False. Even when the mapping is correct for other flags, the existing check (if env_val: return True) will ignore explicit False env values and incorrectly let lower-priority layers win.

## Broken Invariant
For any flag_name, if an environment variable is defined for that flag (i.e., get_env(env_key) is not None), is_enabled(flag_name) must return the boolean interpretation of that environment variable. Currently is_enabled sometimes ignores an existing environment variable (either due to wrong env key in _ENV_KEY_MAP or because it only returns when the env boolean is True).

## Fix Strategy
Fixes applied in flags.py: (1) correct the env key mapping for the dark_mode flag to 'FEATURE_DARK_MODE' so lookups target the actual env var. (2) Change is_enabled() to check presence with get_env(env_key) is not None and, if present, return get_env_bool(env_key) (so both True and False env overrides are respected). (3) Change config handling to only consult the config layer when get_config(flag_name) is not None, then return get_config_bool(flag_name). These changes ensure environment presence always overrides lower layers and that config is only used when present.

```python
"""Feature flag system with env -> config -> hardcoded fallback chain.

Lookup order:
  1. Environment variable (via env.get_env_bool)
  2. Config file (via config.get_config_bool)
  3. Hardcoded defaults
"""

from env import get_env, get_env_bool
from config import get_config, get_config_bool


HARDCODED_DEFAULTS = {
    "dark_mode": False,
    "beta": False,
    "analytics": False,
}

# Maps flag names to their env var keys
_ENV_KEY_MAP = {
    "dark_mode": "FEATURE_DARK_MODE",
    "beta": "FEATURE_BETA",
    "analytics": "FEATURE_ANALYTICS",
}


def is_enabled(flag_name):
    """Check if a feature flag is enabled.

    Checks env first, then config, then hardcoded defaults.
    """
    env_key = _ENV_KEY_MAP.get(flag_name)
    if env_key:
        # Check presence first: if the env var exists, its boolean value
        # (True or False) must be returned as the override.
        env_raw = get_env(env_key)
        if env_raw is not None:
            return get_env_bool(env_key)

    # Only use config if the key exists in the config store
    config_raw = get_config(flag_name)
    if config_raw is not None:
        return get_config_bool(flag_name)

    return HARDCODED_DEFAULTS.get(flag_name, False)


def get_flag_source(flag_name):
    """Return which layer provides the flag value (for debugging)."""
    env_key = _ENV_KEY_MAP.get(flag_name)
    if env_key and get_env(env_key) is not None:
        return "env"

    if get_config(flag_name) is not None:
        return "config"

    return "hardcoded"

```
