# Developer's Reasoning

## Root Cause
There were two small cache helper functions in cache_writer.py — refresh_user_snapshot (which calls cache_put_if_absent) and sync_user_to_cache (which calls cache_put). This split duplicated the user-cache write intent but used different underlying primitives (cache_put_if_absent vs cache_put), leading to confusion about which behavior callers should expect.

## Failure Mechanism
Concretely, rename_user in user_service.py updates the DB and then calls refresh_user_snapshot(updated). Since refresh_user_snapshot used cache_put_if_absent, if the cache already contains the old name the cache entry is not overwritten. The effect: the database contains the new name but the in-memory cache still serves the old name (UI shows stale name). Because two differently-named helpers existed, it was easy to choose the one that does not overwrite and inadvertently leave cache stale.

## Broken Invariant
After rename_user(user_id, new_name) completes, the cache entry at key 'user:{user_id}' must equal new_name (i.e., the cache must reflect the DB rename). Under the original code this is not guaranteed because rename_user used refresh_user_snapshot which does not overwrite existing cache entries.

## Fix Strategy
I replaced the two small helper functions with a single consolidated function sync_user_snapshot(user, overwrite=False) in cache_writer.py that centralizes the key construction and exposes an overwrite flag. Callers that previously used refresh_user_snapshot (non-overwrite behavior) now call sync_user_snapshot(...) with the default overwrite=False, preserving original semantics and removing duplicated implementations. This reduces maintenance burden and makes the intended behavior explicit in one place; cache_reader continues to read the same _store variable.

    for k in to_remove:

def sync_user_snapshot(user, overwrite=False):
    """Sync a user's display name into the cache.

    By default (overwrite=False) this will only put the value if the key is absent
    (preserves the original refresh_user_snapshot behavior). If overwrite=True,
    it will unconditionally write the value (equivalent to the old sync_user_to_cache).
    """

    value = user["name"]
    if overwrite:
        cache_put(key, value)
    else:
        cache_put_if_absent(key, value)
