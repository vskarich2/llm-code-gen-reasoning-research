## Failure Mechanism
Concrete scenario: a user dict has verified=True and cached_greeting='Hello, Alice!'. Calling update_profile(user, {'email': 'alice.new@example.com'}) runs the email branch, which sets user['email'] to the new address but does not change user['verified'] or user['cached_greeting']. As a result the user remains verified=True and cached_greeting still contains the old greeting 'Hello, Alice!', so the system continues to show the old greeting and an (incorrect) verified state after an email change.

This is a specific, testable post-condition on update_profile when an email change occurs.

## Fix Strategy

This directly fixes the failure mechanism: once the email field is changed the verified flag is reset and the cached greeting is cleared, so callers will no longer observe the old greeting or an incorrectly still-verified state.     }


def verify_user(user):
    """Mark user as verified."""
    user["verified"] = True

def update_profile(user, changes):
    """Update profile fields.

    Invariant: changing email must set verified=False and clear cached_greeting.
    Invariant: changing name must update cached_greeting.
    """
    for key, value in changes.items():
        if key == "email" and validate_email(value):
            old_email = user.get("email")
            user["email"] = value
            # Ensure changing the email clears verification and the cached greeting
            user["verified"] = False
            user["cached_greeting"] = ""
        elif key == "name" and validate_name(value):
            user["name"] = value
            user["cached_greeting"] = build_greeting(user)
