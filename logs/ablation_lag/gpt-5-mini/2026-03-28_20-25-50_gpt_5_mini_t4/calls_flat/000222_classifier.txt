# Developer's Reasoning

## Root Cause
The bug is in make_withdraw_steps: the step_check callback sets result['approved'] based on check_balance(name, amount) but does not change _accounts. Because result['approved'] is a separate flag, step_check can return True for multiple withdrawals without any mutation to the shared state. Later, step_act uses that flag to call do_withdraw(name, amount). Concretely, result['approved'] (the variable in make_withdraw_steps) records the outcome of the check without performing the debit, so two independent check steps can both set approved=True before either step_act mutates _accounts.

## Failure Mechanism
Under the interleaved sequence run_steps([(check_a, ()), (check_b, ()), (act_a, ()), (act_b, ())]) both check_a and check_b call step_check. Each step_check executes check_balance('alice', 80) against the initial _accounts['alice'] == 100 and sets result['approved'] = True. Because step_check does not reduce the balance, both checks succeed. Then act_a calls do_withdraw('alice', 80) (because result['approved'] is True), reducing the balance to 20. act_b then also calls do_withdraw('alice', 80), reducing the balance from 20 to -60. The missing atomicity between check_balance and do_withdraw (the separation implemented by result['approved']) allows two approvals to become two withdrawals and produce a negative balance.

## Broken Invariant
For any account and any interleaving of the check and act steps returned by make_withdraw_steps, the account balance must never become negative. Equivalently: after executing any sequence of the check and act functions produced by make_withdraw_steps(name, amount) for withdrawals whose individual amounts are <= the initial balance, get_balance(name) >= 0 must hold.

## Fix Strategy
Make the approval step perform a reservation (debit) immediately when the check succeeds so the shared state (_accounts) reflects the approval and prevents subsequent checks from also succeeding. Concretely, step_check now calls do_withdraw(name, amount) when check_balance returns True and marks the approval as reserved; step_act no longer performs the debit. This removes the separate check-then-act window that allowed two checks to both observe the original balance and thus prevents the interleaving that produced an overdraft.

_accounts = {}


def reset():
    _accounts.clear()


def create_account(name, balance):
    _accounts[name] = balance


def get_balance(name):
    return _accounts.get(name, 0)


def check_balance(name, amount):
    """CHECK: is balance sufficient?"""
    return _accounts.get(name, 0) >= amount


def do_withdraw(name, amount):
    """ACT: decrement balance. Assumes caller verified."""
    _accounts[name] = _accounts.get(name, 0) - amount


def run_steps(steps):
    results = []
    for fn, args in steps:
        results.append(fn(*args))
    return results


def make_withdraw_steps(name, amount):
    """Split withdrawal into separate check and act steps.

    FIX: perform reservation during the check step when a check succeeds.
    The check step now debits (reserves) immediately so another check
    cannot observe the original balance and also approve. The act step
    no longer performs a second debit.
    """
    result = {"approved": False, "reserved": False}

    def step_check():
        # If there's enough balance, reserve (debit) immediately to avoid
        # a race where multiple checks both observe the same balance.
        if check_balance(name, amount):
            # Debit now to make the approval visible in shared state.
            do_withdraw(name, amount)
            result["approved"] = True
            result["reserved"] = True
        else:
            result["approved"] = False
        return ("check", result["approved"])

    def step_act():
        # The act step should not double-withdraw. If the check already
        # reserved the funds, do nothing here. If some alternative flow
        # sets approved without reserving, act will perform the debit.
        if result["approved"] and not result.get("reserved"):
            do_withdraw(name, amount)
            result["reserved"] = True
        return ("act", result["approved"])

    return step_check, step_act


def sequential_withdrawals():
