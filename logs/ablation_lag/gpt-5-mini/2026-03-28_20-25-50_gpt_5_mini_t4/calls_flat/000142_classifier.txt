# Developer's Reasoning

## Root Cause
In limiter.should_allow the boolean expression uses variables expired, under_limit, and exempt but is written as `return not expired and under_limit or exempt`. Because of Python operator precedence this is parsed as `((not expired) and under_limit) or exempt`, so the value of `exempt` can make the whole expression True even when `expired` is True. The specific causal relationship is: the variable `expired` is intended to gate all allowances, but the misplaced `or exempt` allows exemption to short-circuit the result after the expired check has been effectively bypassed.

## Failure Mechanism
When a request's timestamp is outside the window (is_expired(timestamp, now, window_seconds) returns True) but the client_id is in the exempt_list (is_exempt returns True), the expression `not expired and under_limit or exempt` evaluates to True because Python computes it as `((not expired) and under_limit) or exempt`. Concretely, for expired=True, under_limit=False, exempt=True: `not expired` => False, `(False and under_limit)` => False, `False or True` => True; should_allow incorrectly returns True and the middleware increments the client's count and returns allowed. This violates the intended policy that expired tokens must always be rejected.

## Broken Invariant
For any inputs where is_expired(timestamp, now, window_seconds) is True, should_allow(...) must return False regardless of is_exempt(client_id, exempt_list). This invariant is violated because the previous return expression allowed exemption to produce True even when expired is True.

## Fix Strategy
Change the boolean expression to explicitly require that the token is not expired and that either the client is under the limit or is exempt: `return (not expired) and (under_limit or exempt)`. This enforces the intended gating by `expired` (if expired is True, the whole result is False) while still allowing exempt clients to bypass the limit when the token is not expired. Only limiter.py needed modification; middleware.py and policy.py are unchanged.
