# Developer's Reasoning

## Root Cause
In auth.py the dispatch table _ROLE_DISPATCH is missing the mapping for the "guest" role. As a result, _ROLE_DISPATCH.get(role, _default_access) in get_access() returns _default_access when role == "guest" instead of calling guest_access.

## Failure Mechanism
When code calls can_read("guest") (or get_access("guest")) the lookup handler = _ROLE_DISPATCH.get(role, _default_access) yields the fallback _default_access because "guest" is not a key in _ROLE_DISPATCH. _default_access() returns {"read": False, "write": False, "delete": False}, so can_read("guest") returns False despite roles.guest_access() defining read-only access.

## Broken Invariant
For the guest role the system must return read-only permissions: get_access("guest") must equal {"read": True, "write": False, "delete": False} (equivalently can_read("guest") must be True). Currently this invariant is violated because the dispatch table lacks the "guest" handler.

## Fix Strategy
Add the missing "guest": guest_access entry to the _ROLE_DISPATCH mapping so that get_access("guest") resolves to guest_access instead of _default_access. This ensures handler() calls guest_access() and returns the intended read-only permissions.

# Code Produced
```python
"""Authentication and authorization dispatch."""

from roles import admin_access, user_access, moderator_access, guest_access


# Dispatch table mapping roles to access handlers
_ROLE_DISPATCH = {
    "admin": admin_access,
    "user": user_access,
    "moderator": moderator_access,
    "guest": guest_access,
}


def _default_access():
    """Default: no access for unknown roles."""
    return {"read": False, "write": False, "delete": False}


def get_access(role):
    """Return the access dict for a given role."""
    handler = _ROLE_DISPATCH.get(role, _default_access)
    return handler()


def can_read(role):
    """Check if role has read access."""
    return get_access(role).get("read", False)

```
