# Developer's Reasoning

## Root Cause
In function enqueue the parameter 'queue' is defined with a mutable default value ([]). Because default argument objects are created once at function definition time, the same list object is reused across calls and is stored in the function object's default, causing tasks appended in one call to persist into later calls.

## Failure Mechanism
If a caller invokes enqueue(make_task('a')) without passing an explicit queue, the call appends the new task dict to the default list and returns that list. A subsequent call enqueue(make_task('b')) will append to the same default list, so the second call returns a list containing both 'a' and 'b'. For example: first call returns [{'name':'a', 'priority':1}] but second call returns [{'name':'a','priority':1}, {'name':'b','priority':1}] instead of returning a single-element list for the new task.

## Broken Invariant
The function enqueue violates the module-level invariant: "each call with a single task (no explicit queue) must return a list containing only that task." Concretely, for tasks t1 and t2, the property enqueue(t1) returns a list L1 with len(L1)==1 and L1[0] is t1 fails because enqueue(t2) can return a list L2 where len(L2)>1 and contains t1 as well as t2.

## Fix Strategy
Change the default value of the 'queue' parameter from a shared mutable list to None and create a fresh list inside enqueue when queue is None. This ensures each call without an explicit queue receives a new list object. Concretely, the implementation now checks 'if queue is None: queue = []' before appending, so the append no longer mutates a shared default list.

    """Add a task to the queue and return the queue.

    # Create a fresh list for callers that do not provide one

    """Create a task dict."""
    return {"name": name, "priority": priority}

    """Process all tasks in the queue and return results."""
    results = []
    for task in queue:
        results.append(f"done:{task['name']}")
