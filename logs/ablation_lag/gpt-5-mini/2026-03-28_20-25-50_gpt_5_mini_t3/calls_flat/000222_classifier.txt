# Developer's Reasoning

## Root Cause
In make_withdraw_steps the variable result['approved'] is set only by step_check (via check_balance) and then trusted by step_act. Concretely, step_check() calls check_balance(name, amount) and stores that boolean in result['approved'], and step_act() uses that stored value to decide whether to call do_withdraw(name, amount). Because step_act does not re-check the current _accounts state, it can act on stale approval stored in result['approved'].

## Failure Mechanism
Given the sequence run_steps([(check_a,()), (check_b,()), (act_a,()), (act_b,())]) both check_a and check_b run while balance is 100 so both set their result['approved'] to True. Later act_a() sees result['approved'] True and calls do_withdraw('alice', 80) leaving 20. act_b() then also sees its stored result['approved'] True (stale) and calls do_withdraw('alice', 80) again, leaving -60. The causal chain: step_check reads balance -> writes result['approved'] -> time passes and another check reads same original balance -> both checks True -> step_act trusts stored approval -> both subtract -> negative balance.

## Broken Invariant
The code violates the invariant that an account's balance must never go negative. Formally: for any account name, after any sequence of calls built from make_withdraw_steps (check then act steps), get_balance(name) >= 0 must hold. The current implementation allows get_balance('alice') == -60 after interleaved_withdrawals().

## Fix Strategy
I changed step_act inside make_withdraw_steps to re-validate the current balance by calling check_balance(name, amount) at act time instead of trusting the earlier stored result['approved']. The act now only calls do_withdraw(name, amount) when the fresh check passes and updates result['approved'] accordingly. This prevents acting on stale approvals: in the interleaved scenario act_b will re-check and see insufficient funds and will not withdraw, ensuring balances never go negative.

def reset():

def create_account(name, balance):

def get_balance(name):

def check_balance(name, amount):
    """CHECK: is balance sufficient?"""
    return _accounts.get(name, 0) >= amount


def do_withdraw(name, amount):
    """ACT: decrement balance. Assumes caller verified."""
    _accounts[name] = _accounts.get(name, 0) - amount


def run_steps(steps):
    results = []
    for fn, args in steps:
        results.append(fn(*args))
    return results


def make_withdraw_steps(name, amount):
    """Split withdrawal into separate check and act steps.

    Fix: ACT re-checks current balance before debiting to avoid acting on stale approval.
    """
    result = {"approved": False}

    def step_check():
        result["approved"] = check_balance(name, amount)
        return ("check", result["approved"])

    def step_act():
        # Re-validate balance at act time to avoid acting on a stale approval.
        if check_balance(name, amount):
            do_withdraw(name, amount)
            result["approved"] = True
        else:
            result["approved"] = False
        return ("act", result["approved"])

    return step_check, step_act
