## Root Cause
In code_snippets_v2/temporal_drift_b/pipeline.py the pipeline() function calls compute_raw_stats(cleaned) where 'cleaned' is the result of normalize(data). The bug is the wrong argument passed to compute_raw_stats: compute_raw_stats expects the original (untransformed) data but is being given the normalized data stored in variable 'cleaned'.

## Failure Mechanism
Because pipeline() computes raw_stats from 'cleaned', a call like pipeline([10, 20, 30]) will normalize first (cleaned becomes [0.0, 0.5, 1.0]) and then compute_raw_stats on that normalized list. The returned raw_stats will be {'raw_max': 1.0, 'raw_min': 0.0, 'raw_sum': 1.5} instead of the intended {'raw_max': 30, 'raw_min': 10, 'raw_sum': 60}. In short, raw_stats reflect the normalized values rather than the original values.

## Broken Invariant
The contract in compute_raw_stats requires that pipeline() provide the original untransformed data so that raw_stats['raw_max'] == max(original_data), raw_stats['raw_min'] == min(original_data), and raw_stats['raw_sum'] == sum(original_data). This invariant is violated because pipeline() passes the normalized 'cleaned' list into compute_raw_stats instead of the original 'data'.

## Fix Strategy
Call compute_raw_stats on the original 'data' variable rather than on 'cleaned'. I moved the compute_raw_stats call to use compute_raw_stats(data) (and placed it before normalization for clarity), ensuring raw_stats are computed from the untransformed input. This directly fixes the failure mechanism because compute_raw_stats now receives the original numbers and will return correct raw_max/raw_min/raw_sum.
