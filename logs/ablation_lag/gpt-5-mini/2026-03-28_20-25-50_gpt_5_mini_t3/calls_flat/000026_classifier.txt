## Root Cause
The bug is in update_product: after updating the persistent store _db, the function does not update or invalidate the in-memory _cache. Because _cache is used by get_product to serve subsequent lookups, leaving _cache unchanged causes get_product to keep returning the stale cached dict instead of the updated data in _db.

## Failure Mechanism
Concrete scenario: add_product('p1', 'Widget', 10) stores {'name':'Widget','price':10} in _db. Calling get_product('p1') populates _cache['p1'] with a copy of that dict. Then update_product('p1', price=12) updates _db['p1']['price'] to 12 but does not touch _cache. A later get_product('p1') sees the entry in _cache and returns the old price 10 from the cached dict — the cache is stale and hides the update in _db.

## Broken Invariant
After a successful update_product(product_id, **fields) (i.e., update_product returns True), get_product(product_id) must return a mapping whose key/values reflect the updated fields in _db. Example test that fails in the original code: add_product('p', 'X', 1); get_product('p'); update_product('p', price=2) -> get_product('p')['price'] should equal 2.

## Fix Strategy
update_product now synchronizes the cache after modifying _db: once _db[product_id] is updated, if a cached entry exists we replace _cache[product_id] with a fresh copy dict(_db[product_id]). This prevents stale reads. Additionally, get_product returns a defensive copy of the cached dict (dict(...)) so callers cannot mutate the cache in place. These changes ensure get_product always sees the updated data after update_product and that callers cannot accidentally mutate the cached object.

"""Product catalog with caching.

This module keeps a simple in-memory database (_db) and a read cache (_cache).
get_product uses _cache to speed repeated reads. update_product now ensures the
cache is synchronized with the database so callers never observe stale data.
"""

_db = {}
_cache = {}


def add_product(product_id, name, price):
    """Add a product to the database.

    The product is stored in the persistent _db. The cache is not modified here;
    the first get_product call will populate _cache lazily.
    """
    _db[product_id] = {"name": name, "price": price}


def get_product(product_id):
    """Get product by ID, using cache for repeated lookups.

    Returns a fresh dict copy of the cached or stored product, or None if not found.
    Returning a copy prevents external callers from mutating the internal cache.
    """
    if product_id in _cache:
        # Return a defensive copy so callers cannot mutate the cached object.
        return dict(_cache[product_id])
    product = _db.get(product_id)
    if product is not None:
        # Store a copy in the cache and return a copy to the caller.
        _cache[product_id] = dict(product)
        return dict(_cache[product_id])
    return None


def update_product(product_id, **fields):
    """Update product fields in the database.

    Invariant: get_product() must return current data after update.

    Returns True on success, False if the product_id does not exist.
    """
    if product_id not in _db:
        return False
    _db[product_id].update(fields)
    # Keep the cache consistent: if the product is cached, replace the cached
    # entry with a fresh copy of the updated database record.
    if product_id in _cache:
        _cache[product_id] = dict(_db[product_id])
    return True


def reset():
    """Clear all data."""
    _db.clear()
    _cache.clear()
