# Developer's Reasoning

## Root Cause
In order_service.place_order the except ValueError block re-raises the exception without undoing the earlier side-effects: reserve(product_id, qty) (which increments inventory._reserved in inventory) and add_audit_entry(...) (which appends to payment._audit_log). Because place_order does not call release(product_id, qty) or remove_audit_entry(order_id) before re-raising, the partial state from the failed payment is left in inventory._reserved and payment._audit_log.

## Failure Mechanism
Concrete scenario: set payment._gateway_fail = True and call place_order('P1', 2, 10). place_order calls reserve('P1', 2) which increases inventory._reserved['P1'] by 2, then add_audit_entry({'order_id': 'ORD-P1-2', ...}) appends an entry to payment._audit_log. process(...) sees _gateway_fail True and raises ValueError. The except block in place_order re-raises the ValueError immediately. As a result, inventory._reserved still contains the 2-unit reservation and payment._audit_log still contains the order entry, even though the payment failed. Subsequent calls see reduced available('P1') and a stale audit entry tied to a failed order.

## Broken Invariant
If process(amount, order_id) raises ValueError for a call of place_order(product_id, qty, price), then after place_order returns by raising: (1) inventory.get_reserved(product_id) must not include the qty reserved by that failed order (i.e., inventory.available(product_id) should equal its pre-order available quantity), and (2) payment.get_audit_log() must not contain any entry with order_id == f'ORD-{product_id}-{qty}'. Currently both conditions can be violated.

## Fix Strategy
I modified order_service.place_order to perform compensating actions when process(...) raises: it now calls release(product_id, qty) to undo the reservation created by reserve(...) and calls remove_audit_entry(order_id) to remove the audit entry added by add_audit_entry(...) before re-raising the ValueError. I also fixed reset() in order_service to delegate reset to the inventory and payment modules (inventory.reset() and payment.reset()) so module-level state is cleared properly. These changes ensure partial side-effects are cleaned up on payment failure and the broken invariant above holds.
