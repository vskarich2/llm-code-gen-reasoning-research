# Developer's Reasoning

## Root Cause
The bug is in process(): it checks the module-level flag _initialized and, when False, logs an error and returns without preserving the item. The module already defines a _buffer list but process() never uses it, so early-arriving items are discarded instead of being queued.

## Failure Mechanism
In broken_order(), run_steps calls process('a') before init(). process() sees _initialized == False, appends "error:not_init:a" to _log and returns False, losing 'a'. Later init() sets _initialized True and appends "init", but there is no record of 'a' to process, so the final log lacks "processed:a". Concretely: process('a') -> error:not_init:a; init() -> init; process('b') -> processed:b; shutdown -> shutdown. 'a' is never processed because process() discarded it instead of buffering.

## Broken Invariant
If init() is eventually called before shutdown(), then every call process(item) that occurs before or after init() must result in exactly one "processed:<item>" entry in _log by the time shutdown() is called. Currently this is violated when process() is called before init(): "processed:<item>" is missing.

## Fix Strategy
Change process() so that when _initialized is False it buffers the item in _buffer instead of logging an error and discarding it. Modify init() to set _initialized True, append "init" to _log, then drain the _buffer (in FIFO order) and process each buffered item so that each gets a "processed:<item>" entry. Clearing _buffer before draining avoids re-entrancy/duplication. This ensures items arriving before init are retained and processed after initialization.
