# Developer's Reasoning

## Root Cause
In make_increment_steps(), the inner function step_write() uses captured['current'] (set earlier by step_read()) when calling _set. The captured dict is per-increment closure, so if two increments call their step_read() before either step_write(), both captured values are the same (e.g., 0). step_write() then writes captured['current'] + 1, overwriting the global _value with the stale value+1.

## Failure Mechanism
In interleaved_double_increment() the steps are run as: read_a, read_b, write_a, write_b. Execution: read_a sets captured_a['current']=0; read_b sets captured_b['current']=0; write_a does _set(captured_a['current']+1) -> _set(1); write_b does _set(captured_b['current']+1) -> _set(1), so the second write overwrites the first and the final get() returns 1 instead of 2.

## Broken Invariant
The counter must satisfy: after performing two increment operations (each produced by make_increment_steps() and executed as read then write in any interleaving), get() == 2. Currently this invariant is violated for the interleaving read_a, read_b, write_a, write_b.

## Fix Strategy
Make the write step compute the increment from the current global state at write time instead of using the earlier-captured snapshot. Concretely, change step_write() to call get() and then _set(get() + 1). This ensures each write observes the most recent _value and increments it, so two increments produce 2 under any ordering of read/write steps. The read step still records the observed value for diagnostics, but the write no longer relies on the stale captured value.



# Task Description

_value = 0


def reset():
    global _value
    _value = 0


def get():
    return _value


def _set(v):
    global _value
    _value = v


def run_steps(steps):
    results = []
    for fn, args in steps:
        results.append(fn(*args))
    return results


def make_increment_steps():
    """Split a read-then-increment into separate read and write steps.

    Fixed: the write step reads the current global value at write-time
    instead of trusting the earlier captured snapshot, so interleavings
    where multiple reads happen before writes do not lose updates.
    """
    captured = {}

    def step_read():
        captured["current"] = get()
        return ("read", captured["current"])

    def step_write():
        # Read the up-to-date global value at write time and increment it.
        # This avoids using the stale captured['current'] when other
        # increments have already updated _value between the read and write.
        current = get()
        _set(current + 1)
        return ("write", current + 1)

    return step_read, step_write


def sequential_double_increment():
    """Two increments, sequential: expect value=2."""
    reset()
    read_a, write_a = make_increment_steps()
    read_b, write_b = make_increment_steps()
    run_steps([(read_a, ()), (write_a, ()), (read_b, ()), (write_b, ())])
