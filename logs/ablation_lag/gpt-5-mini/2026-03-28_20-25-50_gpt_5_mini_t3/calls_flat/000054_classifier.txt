## Root Cause
In code_snippets_v2/mutable_default_b/worker.py, the function process_batch defines the parameter seen with a mutable default value seen=set(). Because default argument expressions are evaluated once at function definition time, the single set object bound to the default 'seen' persists across multiple calls to process_batch. The persistent set is mutated (seen.add(task_id)), so subsequent calls observe previously-seen task IDs even when the caller intended a fresh, independent run.

## Failure Mechanism
When process_batch is first called, it iterates over tasks and adds each task['name'] into the default 'seen' set. On a later call to process_batch with a new batch (and no explicit seen argument), the same default set is reused, so the membership test if task_id in seen returns True for any name seen previously, causing the function to continue and skip processing that task. Concretely: call process_batch([{'name':'A'},{'name':'B'}]) returns results for A and B and mutates the default seen to {'A','B'}; a subsequent call process_batch([{'name':'A'},{'name':'C'}]) will skip 'A' because 'A' is in the preserved seen set and only process 'C', even though the invariant requires processing all tasks in the new batch.

## Broken Invariant
The function process_batch must process every task in the tasks argument on each independent call when no explicit seen set is provided. Formally testable invariant: for two independent calls process_batch(tasks1) and process_batch(tasks2) made with no shared seen argument, every element t in tasks1 should be processed in the first call, and every element u in tasks2 should be processed in the second call regardless of whether names overlap between tasks1 and tasks2. This is violated because the default seen set persists between calls, causing some elements of tasks2 to be skipped.

## Fix Strategy
Change the default value of the seen parameter from a mutable set created at function-definition time to None, and allocate a fresh set() inside the function when seen is None. This ensures each call without an explicit seen argument uses a new independent set, so membership checks only reflect the current call's state. Specifically, replace def process_batch(tasks, seen=set()): with def process_batch(tasks, seen=None): and add if seen is None: seen = set() before using seen. The rest of the logic (seen.add and skipping) is unchanged, preserving the ability for callers to pass a shared seen set if they deliberately want that behavior.
