This duplicated small helpers exposed inconsistent conventions for updating the same cache key (user:{id}) and made it unclear which behavior callers should expect.

## Failure Mechanism
For example, user_service.rename_user updates the DB then calls refresh_user_snapshot(updated). Because refresh_user_snapshot uses cache_put_if_absent, if a stale name key already exists in _store the cache is not updated. As a result cache_reader.get_display_name(user_id) can return the old name even though the DB has been updated, which is a concrete cause-effect: rename_user -> DB updated -> refresh_user_snapshot (put_if_absent) -> cache not changed -> readers see stale value.

After a successful rename_user(user_id, new_name) completes, the cache must reflect the updated name: get_display_name(user_id) == new_name. This invariant is currently violated because rename_user calls refresh_user_snapshot which will not overwrite an existing cache entry.

## Fix Strategy

This removes duplication while preserving existing default behavior (put-if-absent) and still allows callers to request overwrite when necessary. Then update all callers in user_service to call the single function so there are no dangling references to the removed helper.
