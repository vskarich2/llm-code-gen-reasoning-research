# Developer's Reasoning

## Root Cause
In sender.py, the function send_with_retry calls send(msg, ...) inside a for loop (for attempt in range(max_retries)) but does not break or return after a successful send. The missing break/return causes subsequent iterations of the loop to call send again. The key variable involved is the loop control (attempt) combined with the call to send(msg,...), which results in multiple append() and notify() calls for the same message when the first attempt succeeds.

## Failure Mechanism
Concrete scenario: call send_with_retry(msg, max_retries=2, fail_first=False). On attempt 0 the call to send(msg, fail_first=False) succeeds and calls append(msg) and notify(msg). Because send_with_retry does not break or return after success, the loop proceeds to attempt 1 and calls send(msg, ...) again, appending and notifying the same message a second time. The store._messages and store._notifications therefore contain two entries for the same logical send, causing duplicated messages and notifications.

## Broken Invariant
After a successful call to send_with_retry(msg, max_retries=N) that does not raise, the store must contain exactly one appended message and exactly one notification for that msg. Formally: if send_with_retry returns successfully, then store.message_count() increases by 1 and len(get_notifications()) increases by 1 for that msg. The current implementation violates this when the first attempt succeeds because send is invoked multiple times.

## Fix Strategy
Make send_with_retry stop retrying as soon as send succeeds by returning immediately on success. If all attempts raise ConnectionError, re-raise the last ConnectionError so callers can observe the failure. This prevents any additional calls to send after a successful call and thus prevents duplicate append/notify. The change is implemented by replacing the 'no break' behavior with an immediate return True on success, and raising last_error if retries are exhausted.

"""Message sender with retry and store integration."""

from store import append, notify, get_messages, get_notifications

_attempt_count = 0


def reset():
    global _attempt_count, _messages, _notifications
    _attempt_count = 0
    _messages = []
    _notifications = []


def send(msg, fail_first=False):
    """Send a message: store it and notify.

    If fail_first is True, raises on first call to simulate transient error.
    """
    global _attempt_count
    _attempt_count += 1
    if fail_first and _attempt_count == 1:
        raise ConnectionError("transient failure")
    append(msg)
    notify(msg)
    return True


def send_with_retry(msg, max_retries=2, fail_first=False):
    """Retry send on transient errors."""
    last_error = None
    for attempt in range(max_retries):
        try:
            send(msg, fail_first=fail_first)
            # SUCCESS: stop retrying and return immediately to avoid duplicate sends
            return True
        except ConnectionError as e:
            last_error = e
            continue
    # If we exhausted retries, raise the last encountered ConnectionError
    if last_error:
        raise last_error
    return False


def get_attempt_count():
    return _attempt_count
