# Developer's Reasoning

## Root Cause
config.create_config sets config = DEFAULTS (a reference to the module-level dict) so callers receive the shared DEFAULTS object. middleware.ConfigMiddleware.__init__ stores that shared object in self._base, and middleware.apply_config then does cfg.update(request_overrides) which mutates the shared DEFAULTS via the cached reference.

## Failure Mechanism
Sequence: create_config() returns DEFAULTS by reference. ConfigMiddleware.__init__ does self._base = create_config(), so self._base and DEFAULTS are the same dict. A request that calls apply_config({'debug': True}) runs cfg = self._base; cfg.update({'debug': True}) — this mutates the shared dict DEFAULTS. Subsequent requests call apply_config() and observe debug == True even when no override is provided. Concretely, handle_debug_request() sets debug in the shared dict and later handle_request() returns debug True unexpectedly.

## Broken Invariant
Each call to create_config(...) must return an independent config dict so that applying per-request overrides cannot mutate the global DEFAULTS or affect other requests. Equivalently: after handle_request({'debug': True}) returns, a later handle_request() without overrides must return debug == False. This property is violated by the current code.

## Fix Strategy
Return a fresh dict from create_config and stop mutating any cached shared dict in middleware. create_config now produces a shallow copy of DEFAULTS (dict(DEFAULTS)) and applies overrides onto that new dict. The middleware no longer caches a mutable base; apply_config delegates to create_config(request_overrides) so each request gets a fresh config dict. get_timeout() also reads from a fresh config copy. These changes prevent request overrides from mutating DEFAULTS or leaking into other requests.
