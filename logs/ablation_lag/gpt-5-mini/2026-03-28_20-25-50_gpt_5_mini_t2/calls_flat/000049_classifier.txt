# Developer's Reasoning

## Root Cause
In the function enqueue, the parameter 'queue' is given a mutable default value of [] at function definition time. That single list object (named by the local parameter 'queue') is reused across calls, so appending a task mutates a list that will be returned on subsequent calls.

## Failure Mechanism
Because the default list is shared, two concrete calls demonstrate the failure: call1 = enqueue(make_task('t1')) returns ['t1']; call2 = enqueue(make_task('t2')) (no queue argument) then returns ['t1', 't2'] instead of ['t2']. The shared default list (the same object bound to 'queue' each time) accumulates appended tasks across independent invocations.

## Broken Invariant
For any call to enqueue(task) invoked without an explicit queue argument, the function must return a newly created list equal to [task]. Currently this invariant is violated because successive calls without an explicit queue can return lists containing tasks from previous calls.

## Fix Strategy
Changed the enqueue signature to use queue=None and create a fresh list inside the function when queue is None (if queue is None: queue = []). This removes the shared mutable default so each call without an explicit queue gets a new list, preventing cross-call accumulation. The only code change is replacing the mutable default [] with None and initializing a new list when needed.
