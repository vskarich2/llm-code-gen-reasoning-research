# Developer's Reasoning

## Root Cause
The bug is in api.checkout: the parameter use_new_pricing is never used. The checkout function does not change the feature flag state (the 'new_pricing' flag) or pass the choice down, so pricing.compute_price continues to consult the global flags._flags value instead of honoring the checkout call site intent.

## Failure Mechanism
When a caller invokes checkout(..., use_new_pricing=True), checkout simply calls create_invoice(customer, items) without enabling the 'new_pricing' flag. compute_price (in pricing.py) calls is_enabled('new_pricing') to choose between _v1_price and _v2_price, so the invoice will be computed using the existing flags._flags['new_pricing'] value (usually False), producing v1 prices and a pricing_version of 'v1' even though use_new_pricing=True was requested. Similarly, use_new_pricing=False will not disable an already-enabled flag, causing a mismatch.

## Broken Invariant
For any call checkout(customer, items, use_new_pricing=X), the resulting invoice must have invoice['pricing_version'] == 'v2' and all line amounts computed by pricing._v2_price when X is True, and invoice['pricing_version'] == 'v1' with v1 amounts when X is False. Currently this invariant can be violated because checkout does not set or restore the 'new_pricing' feature flag based on use_new_pricing.

## Fix Strategy
checkout now temporarily sets the global 'new_pricing' flag to the requested use_new_pricing value before calling create_invoice, saving the prior flag state and restoring it after invoice creation (using try/finally). This ensures compute_price and get_pricing_version observe the intended flag value for that checkout call without permanently mutating global flag state for other callers. The code change adds is_enabled import, records the previous state, sets the flag to match use_new_pricing, calls create_invoice, and then restores the previous state.

# Code Produced
```python
from billing import create_invoice, get_invoices
from flags import enable, disable, is_enabled


def checkout(customer, items, use_new_pricing=False):
    # Preserve current flag state so we don't permanently mutate global flags for other callers
    prev = is_enabled("new_pricing")
    try:
        if use_new_pricing:
            enable("new_pricing")
        else:
            disable("new_pricing")
        invoice = create_invoice(customer, items)
    finally:
        # Restore original flag state
        if prev:
            enable("new_pricing")
        else:
            disable("new_pricing")

    return invoice

    return get_invoices()
```
