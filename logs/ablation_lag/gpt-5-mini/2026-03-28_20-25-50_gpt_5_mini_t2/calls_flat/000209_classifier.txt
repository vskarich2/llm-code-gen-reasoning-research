As a result the state meta flag st['meta']['frozen'] is never set to True and st['stable'] is never populated from st['pending'], because only stage(st, merged) is executed. This directly leaves the state in a staged-but-uncommitted condition.

## Failure Mechanism
Concrete scenario: process_batch() calls make_state(entries) then normalize/collapse and stage(st, merged). stage populates st['pending'] and st['view'] and increments st['meta']['version'], but without commit(st) st['stable'] remains [] and st['meta']['frozen'] remains False. Later, ingest() calls get_committed_total(st) which checks st['meta']['frozen'] and therefore returns None. ingest_and_verify() computes view_digest from st['view'] (the staged view) and committed_digest via get_committed_digest(st) which returns None because st['meta']['frozen'] is False, so consistency checks fail (e.g., view_digest is a string like "a|b" while committed_digest is None).

## Broken Invariant
After process_batch(entries) returns, the pipeline must produce a committed, frozen state: st['meta']['frozen'] == True, st['stable'] must contain the committed (sorted by id) entries derived from the input (i.e., equal to sorted(st['pending'], key=lambda e: e['id'])), and st['view'] must reflect the committed stable data. This invariant is violated because commit() and freeze_view() were omitted.

## Fix Strategy

This ensures materialize(st) returns the committed view and selectors like get_committed_total/get_committed_digest observe st['meta']['frozen'] == True and report the committed values.
