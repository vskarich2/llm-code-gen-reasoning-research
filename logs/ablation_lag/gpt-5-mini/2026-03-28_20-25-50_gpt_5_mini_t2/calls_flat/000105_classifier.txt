# Developer's Reasoning

## Root Cause
In order_service.place_order the exception handler 'except ValueError: raise' (the re-raise) fails to call inventory.release(product_id, qty) and payment.remove_audit_entry(order_id). As a result, the functions reserve(...) and add_audit_entry(...) leave state in inventory._reserved and payment._audit_log even when process(...) raises.

## Failure Mechanism
Concrete scenario: inventory.add_product('P', 5); order_service.place_order('P', 2, 10) is called while payment._gateway_fail is True. place_order calls reserve('P', 2) which increments inventory._reserved['P'] to 2, then add_audit_entry(...) appends an entry into payment._audit_log. process(...) then raises ValueError("payment declined"). The existing except block simply re-raises the ValueError without calling release('P', 2) or remove_audit_entry(order_id). The effect is that inventory._reserved remains +2 and payment._audit_log still contains the order entry even though payment failed, corrupting both inventory and audit state.

## Broken Invariant
After a payment failure (process(...) raises), the system must have released the reserved inventory and removed the audit entry for that order. Formally: if place_order(product_id, qty, price) raises, then inventory.get_reserved(product_id) == 0 (or equals prior reservations excluding this order) and payment.get_audit_log() contains no entry with order_id == f"ORD-{product_id}-{qty}". The current code violates this: reserved count and audit entries remain after the exception.

## Fix Strategy
I changed place_order to perform explicit rollback on failure: when process(...) raises, the code now calls release(product_id, qty) and remove_audit_entry(order_id) before re-raising the exception. This ensures the reserved inventory and the audit log are cleaned up if payment fails. I also fixed reset() to call the module reset functions (inventory.reset() and payment.reset()) and only reset the local _notifications list, avoiding attempts to reassign inventory internals from within order_service. These concrete changes ensure the two mutated resources (inventory._reserved and payment._audit_log) are rolled back in the same error path where they were created.

from inventory import reserve, release
from payment import process, add_audit_entry, remove_audit_entry
import inventory
import payment

_notifications = []


def reset():
    global _notifications
    _notifications = []
    # delegate resetting inventory and payment modules to their own reset functions
    inventory.reset()
    payment.reset()


def place_order(product_id, qty, price):
    """Place order: reserve inventory, log reasoning_evaluator_audit, process payment, notify.

    If payment fails, must release inventory AND remove reasoning_evaluator_audit entry.
    """
    order_id = f"ORD-{product_id}-{qty}"
    reserve(product_id, qty)
    add_audit_entry({"order_id": order_id, "product": product_id, "qty": qty})
    try:
        result = process(qty * price, order_id)
    except Exception:
        # rollback the reservation and the audit entry on any payment failure
        try:
            release(product_id, qty)
        finally:
            # ensure audit entry is removed even if release somehow fails
            remove_audit_entry(order_id)
        raise
    _notifications.append({"order_id": order_id, "status": "confirmed"})
    return {"status": "confirmed", "payment": result}


def retry_payment(product_id, qty, price):

        try:
            return process(qty * price, order_id)
        except ValueError:
            continue
    return None


def get_notifications():
    return list(_notifications)
