# Developer's Reasoning

## Root Cause
The redundancy stems from reducers.stage() and reducers.commit() both copying processed data into the state (stage -> st['pending'] = processed; commit -> st['stable'] = st['pending']). Additionally reducers.freeze_view() rebuilds st['view'] from st['stable'] even though stage() already sets st['view'] from the processed input. This duplicates state updates and allows workflows to require calling multiple functions to reach a consistent committed view.

## Failure Mechanism
When the pipeline previously needed a committed snapshot, callers had to call stage() then commit() (and sometimes freeze_view()). For example, process_batch would stage(merged) and then call commit() and freeze_view() (or depend on callers to do so). That meant the same list got copied twice (to pending, then to stable) and view got rebuilt twice. If commit() was omitted, st['stable'] could remain stale while st['pending'] and st['view'] reflected the new data, causing get_committed_total() to return None or an old value because it checks meta['frozen']. In short, the duplicated copy operations and separate freezing step led to inconsistent observable state unless all steps were executed in the right order.

## Broken Invariant
After processing input via the pipeline, the state must present a single consistent committed snapshot and view. Specifically: after calling stage(st, processed) in the new pipeline, it must hold that st['pending'] == processed, st['stable'] == processed, st['view'] == project(processed), and st['meta']['frozen'] is True. Previously this invariant could be violated when callers only invoked stage() but not commit()/freeze_view().

## Fix Strategy
I removed the separate commit() and freeze_view() functions and folded their responsibilities into stage(): stage() now writes 'pending' and 'stable', builds 'view', increments the version, and marks meta['frozen'] True. This ensures a single call produces a consistent committed snapshot and avoids copying the same data twice and rebuilding the view redundantly. I also removed the now-unused imports for commit and freeze_view from the pipeline module.

def normalize(entries):
    seen = set()
    out = []
    for e in entries:
        k = e["id"]
        if k not in seen:
            seen.add(k)
            out.append(e)
    return out


def project(entries):
    return [{"id": e["id"], "label": e.get("label", ""), "val": e.get("val", 0)} for e in entries]


def collapse(entries):
    merged = {}
    for e in entries:
        k = e["id"]
        if k in merged:
            merged[k]["val"] = merged[k]["val"] + e.get("val", 0)
        else:
            merged[k] = dict(e)
    return list(merged.values())


def stage(st, processed):
    # Stage now also commits: set pending and stable to the processed list,
    # build the view from processed, bump version and mark frozen.
    st["pending"] = list(processed)
    st["stable"] = list(processed)
    st["view"] = project(processed)
    st["meta"]["version"] += 1
    st["meta"]["frozen"] = True


def materialize(st):
    return {
        "items": list(st["stable"]),
        "display": list(st["view"]),
        "v": st["meta"]["version"],
    }
