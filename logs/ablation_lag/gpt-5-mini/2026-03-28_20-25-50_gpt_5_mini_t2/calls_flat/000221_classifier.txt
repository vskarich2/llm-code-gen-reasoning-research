# Developer's Reasoning

## Root Cause
In make_withdraw_steps the inner function step_act uses the closure variable result['approved'] (set earlier by step_check) to decide whether to call do_withdraw(name, amount) without re-checking the current account balance. Because make_withdraw_steps is called twice (creating two distinct result dictionaries) both step_check functions can set their own result['approved'] = True, and each corresponding step_act will blindly call do_withdraw based only on its own result['approved']. This causal chain (step_check -> result['approved'] True -> step_act unconditionally calling do_withdraw) allows multiple withdrawals to proceed even if intervening operations have reduced the balance.

## Failure Mechanism
Concrete interleaving: reset(); create_account('alice', 100); make_withdraw_steps is called twice, producing (check_a, act_a) with result_a and (check_b, act_b) with result_b. run_steps executes (check_a) which sets result_a['approved'] = True (balance >= 80 at that moment). Then (check_b) runs and sets result_b['approved'] = True (balance still 100). Now (act_a) runs: it sees result_a['approved'] True and calls do_withdraw('alice', 80), reducing the balance to 20. Then (act_b) runs: it sees result_b['approved'] True (from its earlier check) and calls do_withdraw('alice', 80) again, reducing the balance to -60. Because step_act did not re-check the current balance via check_balance before performing the decrement, the second withdrawal proceeds even though the account no longer has sufficient funds.

## Broken Invariant
After any sequence of steps executed via run_steps, for every account name the balance must be non-negative: get_balance(name) >= 0. The current implementation allows get_balance('alice') to become -60 after the interleaved sequence described above, violating this invariant.

## Fix Strategy
Enforce the check-and-act atomicity at the act step by re-checking the current balance inside step_act before calling do_withdraw. The change makes step_act call check_balance(name, amount) and only performs do_withdraw if that check returns True; otherwise it sets result['approved'] = False and does not withdraw. This prevents an act from relying solely on a stale approval flag and stops overdrawing even when checks were interleaved. Because the guard uses the same check_balance and the actual subtraction do_withdraw, this preserves intended behavior for sequential operations while preventing the described interleaving failure.

_accounts = {}


def reset():
    _accounts.clear()


def create_account(name, balance):
    _accounts[name] = balance


def get_balance(name):
    return _accounts.get(name, 0)


def check_balance(name, amount):
    """CHECK: is balance sufficient?"""
    return _accounts.get(name, 0) >= amount


def do_withdraw(name, amount):
    """ACT: decrement balance. Assumes caller verified."""
    _accounts[name] = _accounts.get(name, 0) - amount


def run_steps(steps):
    results = []
    for fn, args in steps:
        results.append(fn(*args))
    return results


def make_withdraw_steps(name, amount):
    """Split withdrawal into separate check and act steps.

    The act step now re-checks the balance before debiting to avoid
    acting on a stale approval produced by an earlier check.
    """
    result = {"approved": False}

    def step_check():
        result["approved"] = check_balance(name, amount)
        return ("check", result["approved"])

    def step_act():
        # Re-check current balance before performing the withdrawal.
        # If the balance is no longer sufficient, do not withdraw and
        # mark approved False to reflect the actual outcome.
        if result["approved"] and check_balance(name, amount):
            do_withdraw(name, amount)
            result["approved"] = True
        else:
            result["approved"] = False
        return ("act", result["approved"])

    return step_check, step_act


def sequential_withdrawals():
    """Two withdrawals of 80 from balance=100. Sequential: second denied."""
    reset()
    create_account("alice", 100)
    check_a, act_a = make_withdraw_steps("alice", 80)
    check_b, act_b = make_withdraw_steps("alice", 80)
    run_steps([(check_a, ()), (act_a, ()), (check_b, ()), (act_b, ())])
    return get_balance("alice")

    return get_balance("alice")
