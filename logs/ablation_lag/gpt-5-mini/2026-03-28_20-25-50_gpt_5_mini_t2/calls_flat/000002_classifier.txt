# Developer's Reasoning

## Root Cause
In create_config, the code sets config = DEFAULTS which makes config reference the module-level DEFAULTS dictionary. Because config is not a copy, subsequent config.update(...) mutates DEFAULTS itself. The problematic interaction is between the create_config function and the DEFAULTS variable: create_config updates the shared DEFAULTS object instead of producing a fresh config dict.

## Failure Mechanism
Concrete scenario: call create_config({'debug': True}). Inside the original function, config = DEFAULTS binds config to the same dict object as DEFAULTS, then config.update({'debug': True}) sets DEFAULTS['debug'] to True. A later call to create_config() (with no overrides) returns the mutated DEFAULTS that now has debug True, so callers observe mutated defaults. Similarly, a caller that does cfg = create_config(); cfg['timeout'] = 10 also changes DEFAULTS because cfg and DEFAULTS are the same object.

## Broken Invariant
After any call to create_config (with or without overrides), the module-level DEFAULTS must remain equal to {'timeout': 30, 'retries': 3, 'debug': False}. This invariant is violated because create_config previously returned and mutated the shared DEFAULTS object.

## Fix Strategy
create_config now returns a shallow copy of DEFAULTS (DEFAULTS.copy()) and applies overrides to that copy, so updating the returned dict cannot mutate the module-level DEFAULTS. I introduced DEFAULTS_TEMPLATE as the canonical template and use DEFAULTS_TEMPLATE.copy() to initialize and to reset DEFAULTS, ensuring reset_defaults restores the canonical values. I also added a small type check to ensure overrides is a dict when provided. These changes prevent accidental mutation of DEFAULTS and restore the intended behavior.

```python
DEFAULTS_TEMPLATE = {"timeout": 30, "retries": 3, "debug": False}

# The module-level DEFAULTS holds the current defaults; callers should never
# receive this object directly. create_config returns a copy instead.
DEFAULTS = DEFAULTS_TEMPLATE.copy()


def create_config(overrides=None):
    """Return a new config dict based on defaults, with optional overrides.

    The returned dict is always a fresh shallow copy so callers can modify it
    without mutating module-level DEFAULTS.

    Args:
        overrides (dict|None): Optional mapping of keys to override in the
            returned config.

    Returns:
        dict: A new configuration dictionary merging DEFAULTS and overrides.
    """
    # Work from a copy of DEFAULTS so we never mutate the module-level dict.
    config = DEFAULTS.copy()

    if overrides:
        if not isinstance(overrides, dict):
            raise TypeError("overrides must be a dict or None")
        config.update(overrides)

    return config


def reset_defaults():
    """Restore DEFAULTS to the canonical template values.

    This reassigns DEFAULTS to a fresh copy of DEFAULTS_TEMPLATE so that any
    previous mutations (if they occurred) are undone.
    """
    global DEFAULTS
    DEFAULTS = DEFAULTS_TEMPLATE.copy()

```
