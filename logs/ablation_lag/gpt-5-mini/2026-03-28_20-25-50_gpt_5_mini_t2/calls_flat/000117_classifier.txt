# Developer's Reasoning

## Root Cause
In code_snippets_v2/temporal_drift_c/pipeline.py inside function pipeline(), the variable raw_stats is computed by calling compute_raw_stats(normalized) (i.e. passing the already-normalized list). The compute_raw_stats function is meant to receive the original untransformed data (see metrics.compute_raw_stats docstring). By using the normalized variable instead of the original data parameter, raw_stats is derived from transformed values rather than the original input.

## Failure Mechanism
Because pipeline() passes normalized data into compute_raw_stats, raw metrics reflect transformed ranges. For example, given original data [10, 20, 30]: normalize([10,20,30]) -> [0.0, 0.5, 1.0]. The buggy call compute_raw_stats(normalized) yields raw_max = 1.0, raw_min = 0.0, raw_sum = 1.5, raw_count = 3 and raw_mean = 0.5. These are incorrect for raw metrics which should be raw_max = 30, raw_min = 10, raw_sum = 60, raw_count = 3 and raw_mean = 20. Downstream consumers that expect raw_* keys to describe the original data will get wrong values and any comparisons or drift detections based on raw stats will be invalid.

## Broken Invariant
Pipeline semantic contract: 'raw_stats MUST reflect the original (untransformed) data.' Concretely, for any input list data, pipeline(data)['raw_stats']['raw_max'] must equal max(data) (or 0 when data is empty). This invariant is violated because pipeline computed raw_max from normalized values instead of from data.

## Fix Strategy
Compute raw_stats from the original data argument rather than from normalized. I moved Stage 1 to execute on the original data (raw_stats = compute_raw_stats(data)) and kept the subsequent normalization/clipping for cleaned/display outputs. This change restores the intended contract: compute_raw_stats receives untransformed data, so raw_max/raw_min/raw_sum/raw_count (and derived raw_mean) correctly describe the original input.

"""Multi-stage metrics pipeline.

Stage 1: compute raw stats on original data
Stage 2: normalize
Stage 3: clip to range
Stage 4: summarize for display
"""

from transforms import normalize, clip, summarize_for_display
from metrics import compute_raw_stats, compute_derived


def pipeline(data):
    """4-stage pipeline.

    raw_stats MUST reflect the original data before any transforms.
    """
    # Stage 1: raw stats (must use original data)
    raw_stats = compute_raw_stats(data)
    derived = compute_derived(raw_stats)
    # Stage 2: normalize
    normalized = normalize(data)
    # Stage 3: clip
    clipped = clip(normalized, 0.05, 0.95)
    # Stage 4: display summary
    display = summarize_for_display(clipped)

    return {
        "raw_stats": raw_stats,
        "derived": derived,
        "cleaned": clipped,
        "display": display,
    }
