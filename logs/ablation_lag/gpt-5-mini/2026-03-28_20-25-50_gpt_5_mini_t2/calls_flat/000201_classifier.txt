# Developer's Reasoning

## Root Cause
Two separate helpers in cache_writer.py implement user snapshot writes with different semantics: refresh_user_snapshot uses cache_put_if_absent while sync_user_to_cache uses cache_put. These functions (refresh_user_snapshot and sync_user_to_cache) and the shared in-memory store _store are the causal elements: having two similarly named helpers with different write behavior leads to inconsistent cache updates.

## Failure Mechanism
In user_service.rename_user the code calls refresh_user_snapshot(updated) after updating the database (db.update_name). Because refresh_user_snapshot maps to cache_put_if_absent(f"user:{user['id']}", user['name']), if the user key already exists in _store the cache is not updated. Concretely: db.update_name('u1', 'Alice2') changes the DB; refresh_user_snapshot(updated) is a no-op if 'user:u1' already existed, so cache_reader.get_display_name('u1') can still return the old name, leaving DB and cache inconsistent.

## Broken Invariant
After updating a user's name via user_service.rename_user(user_id, new_name), the cache must reflect the DB change such that get_display_name(user_id) == new_name. This is testable by calling rename_user and then cache_reader.get_display_name and observing equality. The original code can violate this because refresh_user_snapshot used cache_put_if_absent.

## Fix Strategy
I removed the duplicated helpers and consolidated their behavior into a single function sync_user_to_cache(user, overwrite=False) in cache_writer.py. The function performs cache_put_if_absent by default (preserving the previous refresh_user_snapshot default) and will overwrite the entry when overwrite=True. I updated all user_service callers to use this single function. Centralizing the behavior removes the divergent implementations in two functions and makes it explicit when callers intend to overwrite versus only initialize the cache.
