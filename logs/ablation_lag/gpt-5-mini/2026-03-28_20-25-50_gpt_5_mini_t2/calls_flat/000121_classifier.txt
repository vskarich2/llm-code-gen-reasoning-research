## Root Cause
The bug is in the ROLE_PERMISSIONS mapping used by get_permissions. The ROLE_PERMISSIONS dictionary defined in permissions.py does not include an entry for the 'moderator' role, so get_permissions(role) uses ROLE_PERMISSIONS.get(role, set()) and returns the default empty set for 'moderator'.

## Failure Mechanism
When code calls has_permission('moderator', 'delete'), has_permission calls get_permissions('moderator'), which looks up ROLE_PERMISSIONS.get('moderator', set()). Because ROLE_PERMISSIONS lacks the 'moderator' key, get_permissions returns the empty default set and has_permission then returns False. Concretely: ROLE_PERMISSIONS.get('moderator', set()) -> set() -> 'delete' in set() evaluates to False, causing the system to believe a moderator does not have the 'delete' permission.

## Broken Invariant
For any supported role name (including 'moderator'), get_permissions(role) must return the defined permission set for that role as listed in ROLE_PERMISSIONS. Specifically, after the fix, get_permissions('moderator') should return the non-empty set frozenset({'read', 'delete', 'manage_reports'}) rather than the empty set.

## Fix Strategy
I added an explicit ROLE_PERMISSIONS entry for 'moderator' and made permission sets immutable frozensets for clarity and to avoid accidental mutation. I also introduced DEFAULT_PERMISSIONS as the explicit default returned for unknown roles and exposed SUPPORTED_ROLES for clarity. By adding the 'moderator' key to ROLE_PERMISSIONS and returning DEFAULT_PERMISSIONS consistently from get_permissions, requests for moderator permissions now return the intended permission set and no longer fall through to an empty set.

```python
"""Access control: map roles to permission sets.

This module keeps a small, explicit mapping from role name to the
set of permissions granted to that role. Permission sets are
stored as frozenset to make them immutable and easy to compare in tests.
"""

# Explicit default used when an unknown role is requested
DEFAULT_PERMISSIONS = frozenset()

# Map of roles to their permission sets. Add new roles here.
ROLE_PERMISSIONS = {
    "admin": frozenset({"read", "write", "delete", "manage_users"}),
    "user": frozenset({"read", "write"}),
    # Add missing 'moderator' role with its intended permissions
    "moderator": frozenset({"read", "delete", "manage_reports"}),
}

# Convenience view of supported roles
SUPPORTED_ROLES = frozenset(ROLE_PERMISSIONS.keys())


def get_permissions(role):
    """Return the frozenset of permissions for the given role.

    If the role is not defined in ROLE_PERMISSIONS, DEFAULT_PERMISSIONS is
    returned (an empty frozenset).
    """
    return ROLE_PERMISSIONS.get(role, DEFAULT_PERMISSIONS)


def has_permission(role, action):
    """Check whether a role has a specific permission.

    Example: has_permission('moderator', 'delete') -> True
    """
    return action in get_permissions(role)

```
