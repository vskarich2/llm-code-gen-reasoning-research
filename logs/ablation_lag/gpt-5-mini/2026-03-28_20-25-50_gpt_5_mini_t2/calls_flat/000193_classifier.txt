# Developer's Reasoning

## Root Cause
In transfer_service.execute_transfer the business logic that mutates balances (sender.balance -= amount and receiver.balance += amount) is intermixed with observability calls (record_debit, record_credit, record_transfer_attempt, emit_transfer_event, emit_failure_alert). Specifically, execute_transfer decrements sender.balance and immediately calls record_debit, then performs a random failure check before crediting the receiver. Because the random failure check and the credit happen after record_debit, the ledger can record a debit when the credit never occurs.

## Failure Mechanism
Example concrete scenario: sender.balance == 100 and amount == 40. execute_transfer validates, then calls record_transfer_attempt(...). It then does sender.balance -= 40 and record_debit(sender.account_id, 40). If random.random() < 0.3, the code emits a failure alert and raises RuntimeError before receiver.balance is incremented or record_credit is called. The result is sender.balance == 60, receiver.balance unchanged, the ledger contains a debit entry for the sender but no credit entry for the receiver, and an alert was emitted. The observable logs and account balances are therefore inconsistent.

## Broken Invariant
For any transfer attempt, if there is a recorded debit ledger entry for (from_id, amount) then there must be a corresponding credit ledger entry for (to_id, amount) and receiver.balance must have increased by amount. (Concretely: after a transfer attempt, ledger must not contain a debit without the corresponding credit and matching balance change on the receiver.)

## Fix Strategy
I separated the pure balance mutations into minimal helpers (_core_debit and _core_credit) and moved every observability call into the execute_transfer wrapper. execute_transfer now: validates first (same as before), records the transfer_attempt with status='pending', calls _core_debit then record_debit, runs the transient-failure check and on failure emits an alert and marks the attempt 'failed' before raising, otherwise calls _core_credit then record_credit and marks the attempt 'completed' and emits the success event. This makes the code's responsibilities explicit: core helpers only change balances, while the wrapper is responsible for when and how ledger/audit calls happen. As a result, every ledger entry (debit/credit) is produced immediately after the corresponding balance mutation and the attempt status is updated to reflect success or failure, preventing inconsistent interleaving that previously allowed a recorded debit without a recorded credit.

from models import Account
from ledger import record_debit, record_credit, record_transfer_attempt
from audit import emit_transfer_event, emit_failure_alert


def validate_transfer(sender, amount):
    if amount <= 0:
        raise ValueError("amount must be positive")
    if sender.balance < amount:
        raise ValueError("insufficient funds")


def _core_debit(sender, amount):
    # core business logic: mutate balances, no observability
    sender.balance -= amount


def _core_credit(receiver, amount):
    # core business logic: mutate balances, no observability
    receiver.balance += amount


def execute_transfer(sender, receiver, amount):
    # keep validation outside observability to avoid logging invalid attempts
    validate_transfer(sender, amount)

    # record the attempt as pending
    record_transfer_attempt(sender.account_id, receiver.account_id, amount, status="pending")

    try:
        # perform debit and record it
        _core_debit(sender, amount)
        record_debit(sender.account_id, amount)

        # simulate a transient failure before crediting
        if random.random() < 0.3:
            emit_failure_alert(
                sender.account_id, receiver.account_id, amount,
                "connection reset during credit phase",
            )
            record_transfer_attempt(sender.account_id, receiver.account_id, amount, status="failed")
            raise RuntimeError("transient failure during credit")

        # perform credit and record it
        _core_credit(receiver, amount)
        record_credit(receiver.account_id, amount)

        # mark attempt completed and emit success event
        record_transfer_attempt(sender.account_id, receiver.account_id, amount, status="completed")
        emit_transfer_event(sender.account_id, receiver.account_id, amount)

    except Exception as exc:
        # ensure failures are observable (if not already emitted above)
        if not isinstance(exc, RuntimeError) or "transient failure during credit" not in str(exc):
            emit_failure_alert(sender.account_id, receiver.account_id, amount, exc)
            record_transfer_attempt(sender.account_id, receiver.account_id, amount, status="failed")
        raise
