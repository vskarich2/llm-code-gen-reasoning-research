# Developer's Reasoning

## Root Cause
In sender.send_with_retry the function continues the for-loop after a successful call to send instead of stopping. The code comment even notes the bug: '# BUG: no break after success — continues loop, duplicating'. Because send_with_retry does not return or break on success, append(msg) and notify(msg) (called by send) can be invoked multiple times for a single high-level send_with_retry call.

## Failure Mechanism
Concrete scenario: call send_with_retry('hello', max_retries=2, fail_first=False). On attempt 0 send('hello') succeeds and calls append('hello') and notify('hello'), but send_with_retry does not exit the loop and continues to attempt 1, calling send('hello') again. This results in _attempt_count incrementing twice and the message 'hello' being appended twice to store._messages and two notifications recorded in store._notifications.

## Broken Invariant
A single call to send_with_retry(msg, max_retries=N) must result in at most one stored message and at most one notification for that msg if the send succeeds on the first try. Currently, when max_retries > 1 and the first attempt succeeds, the code can store and notify the same message multiple times.

## Fix Strategy
Stop the retry loop immediately when send succeeds by returning True right after send(msg) completes. Also make failure behavior explicit by re-raising the last ConnectionError if all attempts fail. Additionally, fix reset() in sender to call the store's reset() so the underlying _messages and _notifications are actually cleared. These changes prevent duplicate append/notify calls after a successful send and ensure the store is properly reset.

from store import append, notify, get_messages, get_notifications, reset as store_reset

_attempt_count = 0


def reset():
    global _attempt_count
    _attempt_count = 0
    # Reset the underlying store so messages/notifications are cleared.
    store_reset()


def send(msg, fail_first=False):
    """Send a message: store it and notify.

    If fail_first is True, raises on first call to simulate transient error.
    """
    global _attempt_count
    _attempt_count += 1
    if fail_first and _attempt_count == 1:
        raise ConnectionError("transient failure")
    append(msg)
    notify(msg)
    return True


def send_with_retry(msg, max_retries=2, fail_first=False):
    """Retry send on transient errors."""
    last_error = None
    for attempt in range(max_retries):
        try:
            send(msg, fail_first=fail_first)
            # Success: stop retrying to avoid duplicating work in the store.
            return True
        except ConnectionError as e:
            last_error = e
            continue
    # All attempts failed: re-raise the last connection error to surface the failure.
    if last_error:
        raise last_error
    return False


def get_attempt_count():
    return _attempt_count
