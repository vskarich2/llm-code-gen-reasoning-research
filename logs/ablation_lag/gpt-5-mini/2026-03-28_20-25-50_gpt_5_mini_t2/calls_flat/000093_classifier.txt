# Developer's Reasoning

## Root Cause
pipeline.ingest() omits a break after a successful send_with_retry() call and sender.send_with_retry() silently swallows ConnectionError by always returning True. Concretely, pipeline.ingest() always loops max_pipeline_retries times (no break), and send_with_retry() in sender.py catches ConnectionError in all attempts and returns True even when all retries fail; together these cause multiple successful calls to sender.send() (which increments the module-level _attempt_count and appends messages) per single ingest invocation.

## Failure Mechanism
Example with the existing defaults: pipeline.ingest(msg, max_pipeline_retries=2) calls send_with_retry(msg, max_retries=2). On the first pipeline iteration send_with_retry() may perform two attempts (the first attempt can raise in sender.send() due to fail_first and the second attempt succeeds), which results in one append(msg). Because pipeline.ingest() lacks a break, it calls send_with_retry() again for the second pipeline iteration, causing another append(msg). Thus the same message gets appended twice. In other parameter combinations (e.g. different retry counts) a pipeline-level retry multiplied by sender-level retries can produce 3–4 appends. The root variables involved are _attempt_count (incremented in send), send_with_retry's loop that hides failures, and the missing break in pipeline.ingest.

## Broken Invariant
After a successful ingest(msg) call, the store should contain exactly one additional message for that msg (i.e., store.message_count() increases by 1). The current code can increase the message count by more than 1 for a single ingest(msg) invocation.

## Fix Strategy
1) Make send_with_retry return immediately on the first successful send and raise the last ConnectionError if all attempts fail, so callers can detect persistent failures instead of seeing a swallowed 'success'. 2) Make pipeline.ingest stop retrying after a successful send_with_retry by breaking out of its retry loop; only retry on ConnectionError. 3) Fix pipeline.reset to call the store and sender reset functions rather than trying to reset other modules' internal globals directly. These changes ensure a successful send is not duplicated by additional pipeline-level iterations and that real failures are propagated so retries behave correctly.
