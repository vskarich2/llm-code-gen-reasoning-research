## Root Cause
In code_snippets_v2/effect_order_c/processor.py the function process_batch() performs increment() and emit_event() inside a for loop over items but calls audit_log() only once after the loop using the loop variable item. Because audit_log is invoked at batch level with the final value of item, audit entries are not created per input item. The problematic variable is item (used outside its loop) and the problematic function is audit_log called outside the loop.

## Failure Mechanism
Given items = [{"id": "a", "value": 1}, {"id": "b", "value": 2}], process_batch iterates and calls increment and emit_event for both items, but then executes audit_log(item["id"], "processed", f"value={item['value']}") once after the loop. The variable item refers to the last iterated element ({"id": "b", "value": 2}), so a single audit entry is appended for id 'b' and no audit entry is created for id 'a'. If items is empty the post-loop reference to item raises an error (UnboundLocalError/NameError).

## Broken Invariant
After calling process_batch(items), audit.get_audit_log() must contain exactly len(items) entries and include one entry per item such that for every item in items there exists an audit entry with entry['item_id'] == item['id'] and entry['detail'] == f"value={item['value']}".

## Fix Strategy
Call audit_log for each item inside the loop so an audit entry is recorded per item. Additionally, delegate reset() to the metrics and audit modules to properly clear their state. Moving the audit_log call inside the per-item loop ensures the audit entries match the per-item effects (increment and emit_event) and prevents the single-batch audit that produced fewer entries than items.
