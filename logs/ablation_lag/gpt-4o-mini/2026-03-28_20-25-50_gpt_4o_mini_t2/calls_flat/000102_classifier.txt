## Root Cause
The bug occurs in the 'place_order' function where, upon a payment failure, the inventory reservation is not released. Specifically, the variable '_reserved' remains unchanged because the 'release' function is not called in the exception handling block.

## Failure Mechanism
When a user attempts to place an order and the payment fails (e.g., by setting '_gateway_fail' to True), the 'place_order' function raises a ValueError. However, since the 'release' function is not invoked, the reserved inventory for that product remains allocated, leading to an incorrect inventory state where stock appears reserved even though the order was not completed.

## Broken Invariant
The invariant that is violated is that the reserved inventory must be released if the payment fails. Specifically, after a failed payment, the available stock should reflect the original state before the reservation was made.

## Fix Strategy
The fix involves adding a call to the 'release' function within the exception handling block of the 'place_order' function. This ensures that if a payment fails, the reserved quantity is correctly released, restoring the inventory state to what it was before the reservation.

        raise ValueError("payment declined")

    """Place an order: reserve inventory, process payment, notify.

    If payment fails, inventory reservation should be rolled back.
    """
    reserve(product_id, qty)
    try:

        release(product_id, qty)  # Fix: release inventory on payment failure
        raise
    _notifications.append({"product": product_id, "qty": qty})
    return {"status": "confirmed", "payment": result}
