## Root Cause
The bug is in the `make_withdraw_steps` function, specifically in the `step_check` and `step_act` functions. The `result['approved']` variable is set to True if the balance is sufficient, but this check occurs before any withdrawal is made, allowing multiple checks to pass before any action is taken.

## Failure Mechanism
In the `interleaved_withdrawals` function, both `check_a` and `check_b` are executed before either `act_a` or `act_b`. This means both checks can approve the withdrawal of 80, even though the balance is only 100. When both withdrawals are processed, the balance goes to -60, which is incorrect.

## Broken Invariant
The invariant that the balance should never go negative is violated. Specifically, after two approved withdrawals of 80 from an initial balance of 100, the balance should not be less than zero.

## Fix Strategy
To fix the issue, I will modify the `step_act` function to re-check the balance right before the withdrawal is executed. This ensures that the balance is still sufficient at the time of the withdrawal, preventing overdrafts.

def do_withdraw(name, amount):

def run_steps(steps):

def make_withdraw_steps(name, amount):
    """Split withdrawal into separate check and act steps.

        result["approved"] = check_balance(name, amount)
        return ("check", result["approved"])

        if check_balance(name, amount):  # Re-check balance before withdrawal
            do_withdraw(name, amount)
        return ("act", result["approved"])
