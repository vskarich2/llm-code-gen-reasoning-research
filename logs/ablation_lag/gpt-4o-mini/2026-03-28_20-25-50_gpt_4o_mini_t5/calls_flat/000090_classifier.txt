## Failure Mechanism

However, if the message is sent successfully on the second attempt, the loop continues to the next iteration, causing the same message to be sent again, resulting in duplicate entries in the store.

## Broken Invariant
The invariant that is violated is that each message should only be sent and stored once per call to 'send_with_retry'. This can be tested by checking that the message count in the store matches the number of unique messages sent.

## Fix Strategy
Adding a 'break' statement after a successful call to 'send' in 'send_with_retry' ensures that the loop exits immediately upon success, preventing any further attempts to send the same message and thus eliminating duplicates.
