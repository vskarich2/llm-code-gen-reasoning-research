## Root Cause
The bug is in the 'with_history' function where the default value for the 'history' parameter is set to the module-level '_shared_log' list. This causes all decorated functions to share the same history list.

## Failure Mechanism
When multiple tasks are scheduled using 'schedule_one' and 'schedule_batch', they both append their call history to the same '_shared_log' list. For example, if 'schedule_one' is called twice and 'schedule_batch' is called once, the history for both will be mixed, leading to incorrect tracking of calls.

## Broken Invariant
Each decorated function must have its OWN independent history list, meaning that the history of 'schedule_one' should not affect the history of 'schedule_batch'.

## Fix Strategy
By changing the default value of the 'history' parameter in 'with_history' to 'None' and initializing a new list within the function if 'None' is passed, each decorated function will maintain its own independent history list.

"""Scheduler with decorator that tracks call history."""

from worker import process, batch_process


def with_history(func, history=None):
    """Decorator that records call history for a function.

    Invariant: each decorated function must have its OWN
    independent history list.
    """
    if history is None:
        history = []

    def wrapper(*args, **kwargs):
        result = func(*args, **kwargs)
        history.append({"func": func.__name__, "args_count": len(args)})
        return result

    wrapper.get_history = lambda: list(history)
    wrapper.clear_history = lambda: history.clear()
    return wrapper


@with_history
def schedule_one(task):
    """Schedule and process a single task."""
    return process(task)


@with_history
def schedule_batch(tasks):
    """Schedule and process a batch of tasks."""
    return batch_process(tasks)


def get_all_stats():
    """Get combined stats (distractor)."""
    return {
        "one_calls": len(schedule_one.get_history()),
        "batch_calls": len(schedule_batch.get_history()),
    }
