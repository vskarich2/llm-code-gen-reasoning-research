## Root Cause
The bug is in the 'process_batch' function where the 'emit_event' call is outside the loop. This means only the last item's event is emitted, while the counter is incremented for all items processed.

## Failure Mechanism
When processing a batch of items, if there are multiple items, only the last item's event is recorded. For example, if the batch contains three items with IDs 1, 2, and 3, only the event for item 3 is emitted, leading to a mismatch between the number of items processed and the number of events emitted.

## Broken Invariant
The number of emitted events must equal the number of items processed in a batch. This is violated because only one event is emitted regardless of the number of items.

## Fix Strategy
By moving the 'emit_event' call inside the loop, each item's event will be emitted immediately after its value is incremented. This ensures that the number of emitted events matches the number of items processed.
