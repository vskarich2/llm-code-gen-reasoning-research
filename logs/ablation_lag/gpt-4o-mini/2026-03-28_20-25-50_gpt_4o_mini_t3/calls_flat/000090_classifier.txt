## Root Cause
The bug is in the 'send_with_retry' function where there is no 'break' statement after a successful send. This causes the loop to continue, leading to multiple calls to 'send' and thus duplicating messages.

## Failure Mechanism
When 'send_with_retry' is called, if the first attempt fails and subsequent attempts succeed, the lack of a 'break' statement allows the loop to continue, resulting in the message being sent and stored multiple times. For example, if 'max_retries' is set to 2 and the first attempt fails, the message will be sent twice if the second attempt succeeds.

## Broken Invariant
The invariant that each message should only be sent and stored once is violated, as the same message can be appended to '_messages' and notified multiple times due to the retry logic.

## Fix Strategy
Adding a 'break' statement after a successful call to 'send' in 'send_with_retry' ensures that the loop exits immediately upon success, preventing duplicate messages from being sent and stored.

from store import append, notify, get_messages, get_notifications

_attempt_count = 0


def reset():
    global _attempt_count, _messages, _notifications
    _attempt_count = 0
    _messages = []
    _notifications = []


def send(msg, fail_first=False):
    """Send a message: store it and notify.

    If fail_first is True, raises on first call to simulate transient error.
    """
    global _attempt_count
    _attempt_count += 1
    if fail_first and _attempt_count == 1:
        raise ConnectionError("transient failure")
    append(msg)
    notify(msg)
    return True


def send_with_retry(msg, max_retries=2, fail_first=False):
    """Retry send on transient errors."""
    last_error = None
    for attempt in range(max_retries):
        try:
            send(msg, fail_first=fail_first)
            break  # Added break to prevent duplicates
        except ConnectionError as e:
            last_error = e
            continue
    return True


def get_attempt_count():
    return _attempt_count
