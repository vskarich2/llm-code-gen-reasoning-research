The bug is in the 'process_batch' function in 'processor.py', specifically in the way 'emit_event' is called. The function currently emits an event only for the last item processed because 'emit_event' is outside the loop that processes each item.

## Failure Mechanism
When processing a batch of items, if the batch contains multiple items, only the last item's event is emitted. For example, if the batch contains three items with IDs 1, 2, and 3, only the event for item 3 will be emitted, leading to a mismatch between the number of items processed and the number of events emitted.

## Broken Invariant
The number of emitted events must equal the number of items processed in a batch. This invariant is violated because only one event is emitted regardless of the number of items in the batch.

## Fix Strategy
The fix involves moving the 'emit_event' call inside the loop in 'process_batch', ensuring that an event is emitted for each item processed. This change guarantees that the number of emitted events matches the number of items processed.
