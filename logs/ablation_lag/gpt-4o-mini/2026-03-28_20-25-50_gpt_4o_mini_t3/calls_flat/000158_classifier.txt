## Root Cause
The bug is in the 'add_entry' function where the '_values' list is always appended to instead of inserting the value at the specified 'position'. This occurs when 'position' is provided, leading to a misalignment between '_labels' and '_values'.

## Failure Mechanism
When calling 'add_entry' with a specific position, for example, 'add_entry('Label1', 'Value1', 0)' followed by 'add_entry('Label2', 'Value2', 0)', the expected behavior is that 'Label2' and 'Value2' should be at index 0, pushing 'Label1' and 'Value1' to index 1. However, due to the bug, 'Value1' remains at index 1, causing a mismatch.

## Broken Invariant
The semantic contract that each label in '_labels' corresponds to the same index in '_values' is violated. Specifically, for any index 'i', '_labels[i]' should always have a corresponding '_values[i]'.

## Fix Strategy
The fix involves changing the line that appends to '_values' to insert the value at the specified 'position' when it is provided. This ensures that the alignment between '_labels' and '_values' is maintained.
