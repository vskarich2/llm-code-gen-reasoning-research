## Root Cause
The bug is in the create_config function in config.py, where the variable config is assigned DEFAULTS directly. This means that any changes to config will also affect DEFAULTS, leading to stale data being returned by get_settings.

## Failure Mechanism
When get_settings is called after applying overrides, it returns the cached settings which are based on the original DEFAULTS. If DEFAULTS is modified later, the cached settings will reflect those changes, causing unexpected behavior.

## Broken Invariant
get_settings should always return a fresh copy of the configuration based on the current defaults and any applied overrides, ensuring that changes to defaults do not affect previously cached settings.

## Fix Strategy
By modifying create_config to return a copy of DEFAULTS instead of a reference, the cached settings will remain unchanged when DEFAULTS is modified, thus ensuring that get_settings returns the correct data.

    settings.update(overrides)

    config = dict(DEFAULTS)  # Changed to return a copy

        config.update(overrides)
    return config


def merge_overrides(base, overrides):

    """Restore defaults to factory values."""
