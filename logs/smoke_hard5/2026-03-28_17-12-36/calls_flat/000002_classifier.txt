## Root Cause
The bug is in the `apply_config` method of the `ConfigMiddleware` class, specifically with the variable `cfg`. It mutates the cached reference of `_base` instead of creating a new copy, leading to shared state across requests.

## Failure Mechanism
When multiple requests are processed, if one request modifies the config by providing overrides, subsequent requests will see the modified config instead of the original defaults. For example, if the first request sets `debug` to `True`, the next request will also see `debug` as `True`, even if it did not intend to enable debug mode.

## Broken Invariant
The config for each request should be independent and reflect only the provided overrides, not shared state from previous requests.

## Fix Strategy
The code change creates a new copy of the base config in the `apply_config` method by using `cfg = dict(self._base)` before applying any overrides. This ensures that each request gets its own independent config.

# Code Produced
```python
from config import create_config


class ConfigMiddleware:
    """Middleware that loads config once and applies per-request overrides."""

    def __init__(self):
        self._base = create_config()  # cached at init time

    def apply_config(self, request_overrides=None):
        """Return config for this request, applying any overrides."""
        cfg = dict(self._base)  # Create a new copy to avoid mutation
        if request_overrides:
            cfg.update(request_overrides)  # mutates the new copy
        return cfg

    def get_timeout(self):
        return self._base.get("timeout", 30)
```
