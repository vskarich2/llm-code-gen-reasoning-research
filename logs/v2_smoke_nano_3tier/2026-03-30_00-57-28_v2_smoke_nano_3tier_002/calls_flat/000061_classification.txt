Root Cause:
The client.py module captures the result of get_config() at import time into the variable _client_config, which is then used for all subsequent calls. Resetting the config via reset_config() does not affect _client_config, causing the client to use stale configuration values, including the old timeout.

Fix Strategy:
Remove the eager capture of get_config() in client.py by replacing the line '_client_config = get_config()' with a function get_client_config() that calls get_config() each time. This ensures that the latest configuration, including any resets, is used whenever get_db_url() or get_timeout() are called.
