## Developer Reasoning (may be partial or missing fields)

Root Cause:
The client.py module captures the config dictionary reference at import time by assigning _client_cfg = get_config(). When reset_config() is called, _config in config.py is set to None, and get_config() will load a new dictionary, but _client_cfg in client.py still points to the old, stale dictionary, causing configuration changes not to propagate to the client functions.

Fix Strategy:
Remove the assignment _client_cfg = get_config() from client.py so that get_api_key() and get_base_url() call get_config() each time, ensuring they always access the current config. This change makes the client functions fetch the latest config on each call, reflecting resets.
